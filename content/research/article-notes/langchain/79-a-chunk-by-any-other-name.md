# 结构化文本切分与元数据增强的 RAG

> 一句话总结：与其把文档胡乱切成等长碎片，不如按照 HTML 标题层级来切分，同时把标题信息保留为元数据，这样检索时既能按语义搜索、又能按结构过滤，大幅提升 RAG 的检索精度。

---

## 核心要点

### 1. 传统切分的结构性讽刺

构建 RAG 应用的第一步，是把完整文档切成小块（Chunk）送给向量嵌入模型。这个过程本身是一种"去语境化"——你先把文章的上下文拆散，然后又指望嵌入模型能理解上下文，这就是作者所说的"结构性讽刺"。传统的 `RecursiveCharacterTextSplitter` 按固定字符数切分，完全不管文档的章节边界，结果一个 chunk 可能横跨两个毫不相关的段落。

### 2. 结构感知的 HTML 标题切分器（HTMLHeaderTextSplitter）

LangChain 新增的 `HTMLHeaderTextSplitter` 不再按字符数盲切，而是按照 HTML 的 h1/h2/h3/h4 标签来分割文本。每个 chunk 会自动携带其所在的标题层级作为元数据（Metadata）。比如一个关于"哥德尔不完备定理"的段落，它的元数据会记录 `h1=Kurt Godel`、`h2=Mathematical Work`、`h3=Incompleteness Theorem`，形成完整的层级路径。

### 3. 自查询检索器（Self-Query Retriever）

有了结构化的元数据之后，你可以用 LangChain 的自查询检索器让 LLM 把用户问题分解为两部分：语义查询部分（用向量搜索）和结构过滤部分（用元数据过滤）。比如用户问"哥德尔的连续统假说是什么？"，系统会自动构造过滤条件 `h1 contains 'Kurt Godel' AND (h2/h3/h4 contains 'Continuum Hypothesis')`，然后在这个子集里做向量搜索。

### 4. 容错能力

自查询检索器还能处理用户的拼写错误和不精确表达。你可以通过 few-shot 示例教会 LLM：即使用户输入了"goodel"，过滤条件中仍然使用正确的元数据值"Kurt Godel"。这种查询构造层的纠错能力是纯向量搜索做不到的。

## 对比表格

| 维度 | 传统切分（RecursiveCharacterTextSplitter） | 结构化切分（HTMLHeaderTextSplitter） |
|------|------------------------------------------|--------------------------------------|
| 切分依据 | 固定字符数（如 1000 字符） | HTML 标题标签（h1-h4） |
| 上下文保留 | 无，chunk 可能横跨章节 | 有，每个 chunk 携带完整标题层级 |
| 元数据 | 仅有来源 URL | 来源 URL + 多级标题路径 |
| 检索方式 | 纯向量相似度 | 向量搜索 + 元数据过滤 |
| 拼写容错 | 无 | 通过 few-shot 示例支持 |
| 适用场景 | 纯文本、无结构文档 | HTML 页面、结构化文档 |

## 类比理解

想象你去一个巨大的图书馆找一本关于"量子力学中的测量问题"的书。

**传统方式**：图书管理员把所有书的每一页都撕下来，堆成一堆，然后凭"感觉"给你挑出最相关的几页。问题是，你可能拿到一页的上半段讲的是量子力学，下半段讲的是相对论——因为原书在那里换了章节。

**结构化切分**：图书管理员先按章节把书整理好，每一章都贴上标签（"物理学 > 量子力学 > 测量问题"）。当你提问时，管理员先按标签找到正确的章节，再在这些章节里找最相关的段落。这样返回的内容既准确又完整。

---

## 为什么重要

1. **检索精度直接决定 RAG 质量**：如果检索到的 chunk 跨越了不相关的章节，即使 LLM 的生成能力再强，也会被噪声干扰，产生看似合理但实际偏离的答案。
2. **元数据过滤是"精确搜索"与"模糊搜索"的桥梁**：用户的问题往往同时包含精确条件（谁的、哪个定理）和模糊意图（解释一下），两者结合才能高效检索。
3. **HTML 是 Web 数据的主流格式**：大量 RAG 应用建立在网页爬取的数据之上，利用 HTML 本身的结构信息而不是丢弃它，是一种零成本的质量提升。

## 延伸思考

1. **Markdown 也能这样做吗？** LangChain 同样提供了 `MarkdownHeaderTextSplitter`，原理完全一致。你的技术文档如果是 Markdown 格式，可以直接复用这个思路。
2. **如果文档没有好的标题结构怎么办？** 可以先用 LLM 给文档自动添加章节标题，再用结构化切分器处理——这相当于"先给书加目录，再按目录切"。
3. **元数据过滤和全文搜索的关系是什么？** 元数据过滤是一种"预过滤"（Pre-filtering），先缩小候选集再做向量搜索；而全文搜索（如 BM25）是另一种检索手段。两者可以组合使用，形成混合检索（Hybrid Retrieval）。
