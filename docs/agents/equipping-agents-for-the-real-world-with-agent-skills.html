🧩 Agent Skills 是什么

随着模型能力提升，我们可以构建与完整计算环境交互的通用 Agent。但如何让它们获得领域专业知识？

核心定义

Agent Skills 是有组织的文件夹，包含指令、脚本和资源，Agent 可以动态发现和加载以在特定任务上表现更好。

  • 将你的专业知识打包成可组合的资源
  • 将通用 Agent 转变为满足你需求的专用 Agent
  • 类似于为新员工编写入职指南
  • 避免为每个用例构建碎片化的定制 Agent

📌 开放标准

📁 技能的解剖

最简单的 Skill 是一个包含 SKILL.md 文件的目录。

📋 SKILL.md 文件结构

--- name: "PDF Skill" description: "Helps Claude manipulate PDFs, including filling out forms and extracting content." --- # PDF Skill Instructions for working with PDFs... See `forms.md` for form filling guidance. See `reference.md` for API reference.

必须以 YAML frontmatter 开头，包含必需的 name 和 description。

🗂️ PDF Skill 目录示例

pdf/ ├── SKILL.md ← 核心指令（必需） ├── forms.md ← 表单填写专用指南 ├── reference.md ← API 参考文档 └── scripts/ └── extract_fields.py ← 可执行脚本

🔓 渐进式披露（Progressive Disclosure）

渐进式披露是 Agent Skills 的核心设计原则——让 Claude 只在需要时加载信息。

Level 1: 元数据（启动时加载）
name 和 description 在启动时预加载到 system prompt 中。这给了 Claude 足够的信息来判断何时应该使用每个 Skill，而无需加载全部内容。这是第一层渐进披露。
Level 2: SKILL.md 正文（触发时加载）
如果 Claude 认为当前任务相关，会读取完整的 SKILL.md 到上下文。这是第二层详细信息。
Level 3+: 捆绑文件（按需加载）
随着 Skill 复杂度增加，可以捆绑额外文件（如 forms.md、reference.md），Claude 只在特定场景下导航和发现这些文件。第三层及更深。

渐进式披露类比

目录/TOC
Level 1
→
具体章节
Level 2
→
详细附录
Level 3+

像一本组织良好的手册——从目录开始，到具体章节，最后到详细附录

💡 关键优势

Agent 不需要在处理特定任务时将整个 Skill 读入上下文窗口。Skill 中可捆绑的上下文量实际上是无限的。

✅ 优势

• 按需加载，节省上下文
• 互斥上下文分开存储
• 减少 token 消耗

❌ 如果不这样做

• 所有内容都加载到上下文
• 上下文污染导致注意力分散
• 性能降级（Context Rot）

🪟 技能与上下文窗口

Skill 触发时上下文窗口的变化过程。

Step 1: 初始状态
上下文窗口包含核心 system prompt + 每个已安装 Skill 的元数据 + 用户初始消息。
Step 2: 触发 Skill
Claude 通过 Bash 工具读取 pdf/SKILL.md 内容，触发 PDF Skill。
Step 3: 读取捆绑文件
Claude 选择读取 Skill 捆绑的 forms.md 文件。
Step 4: 执行任务
Claude 现在加载了 PDF Skill 的相关指令，继续处理用户任务。

⚡ 技能与代码执行

Skill 还可以包含 Claude 自行决定执行作为工具的代码。

为什么用代码？

❌ LLM Token 生成

• 排序列表等任务通过 token 生成非常昂贵
• 非确定性
• 可能出错

✅ 传统代码执行

• 高效、确定性
• 一致可重复
• 不需要加载脚本或数据到上下文

PDF Skill 中的代码示例

PDF Skill 包含预写的 Python 脚本，读取 PDF 并提取所有表单字段。Claude 可以运行此脚本而不需要将脚本或 PDF 加载到上下文中。

  • 代码是确定性的
  • 工作流一致且可重复
  • 代码既是可执行工具，也是文档

"Large language models excel at many tasks, but certain operations are better suited for traditional code execution."

🛠️ 开发与评估指南

开始编写和测试 Skill 的实用指南。

🎯 1. 从评估开始

在代表性任务上运行 Agent，观察它在哪里挣扎或需要额外上下文。然后逐步构建 Skill 来解决这些不足。

📐 2. 为扩展而设计

当 SKILL.md 变得笨重时，拆分内容到单独文件。如果某些上下文互斥或很少一起使用，保持路径分离以减少 token 消耗。

🧠 3. 从 Claude 角度思考

监控 Claude 在真实场景中如何使用 Skill。特别关注 name 和 description——Claude 用这些来决定是否触发 Skill。

🔄 4. 与 Claude 迭代

让 Claude 捕获成功方法和常见错误到 Skill 中。如果偏离轨道，让它自我反思。这帮你发现 Claude 实际需要什么上下文。

📋 结构决策指南

决策建议
SKILL.md 太长？拆分到单独文件，在 SKILL.md 中引用
某些上下文互斥？保持路径分离，减少 token 消耗
代码应该运行还是读取？明确说明——是直接运行脚本还是读入上下文作为参考
Skill name/description 怎么写？这是 Claude 决定是否触发的唯一信息，必须清晰

🔒 安全考量

Skill 通过指令和代码赋予 Agent 新能力——这也意味着恶意 Skill 可能引入漏洞。

⚠️ 潜在风险

• 在环境中引入漏洞
• 引导 Claude 泄露数据
• 执行意外操作

✅ 建议

• 只从可信来源安装 Skill
• 审计不太可信来源的内容
• 检查代码依赖和捆绑资源
• 注意连接外部网络的指令

🔮 未来展望

Agent Skills 今天已在 Claude.ai、Claude Code、Claude Agent SDK 和 Claude Developer Platform 上支持。

📅 近期计划

  • 支持创建、编辑、发现、共享和使用 Skill 的完整生命周期
  • 帮助组织和个人与 Claude 分享上下文和工作流
  • 探索 Skills 如何补充 Model Context Protocol (MCP) 服务器——教导 Agent 更复杂的涉及外部工具的工作流

🚀 更远期的愿景

让 Agent 自主创建、编辑和评估 Skills，让它们将自己的行为模式编码为可复用的能力。
