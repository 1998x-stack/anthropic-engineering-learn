🎯 背景与动机

Anthropic Engineering Blog 的一个主题是如何构建有效 Agent 和设计 Harness。贯穿这些工作的共同线索是：harness 编码了关于 Claude 不能独立完成的假设。

⚠️ 假设会过时

随着模型改进，这些假设需要经常被质疑。例如：Claude Sonnet 4.5 会在接近上下文限制时过早结束任务（"上下文焦虑"）。通过添加上下文重置来解决。但当在 Claude Opus 4.5 上使用相同 harness 时，这种行为消失了——重置变成了死重。

🏛️ Managed Agents 的设计哲学

构建 Managed Agents 意味着解决一个古老的计算问题：如何为"尚未想到的程序"设计系统。几十年前，操作系统通过将硬件虚拟化为抽象——进程、文件——来解决这个问题，这些抽象足够通用，可以容纳还不存在的程序。

read() 命令不关心它访问的是 1970 年代的磁盘组还是现代 SSD。抽象保持稳定，实现自由变化。

🧩 三个虚拟组件

📜 Session（会话）

发生了什么的追加日志。持久的、可查询的事件记录。

🧠 Harness（Harness）

调用 Claude 并将工具调用路由到相关基础设施的循环。

🖥️ Sandbox（沙盒）

Claude 可以运行代码和编辑文件的执行环境。

每个组件都可以独立替换，互不干扰。对接口形状有意见，对背后运行的实现没有意见。

🐄 Don't Adopt a Pet

最初所有组件放在单个容器中——Session、Harness 和 Sandbox 共享环境。

❌ Pet 模式（耦合设计）

• 有名称、需要手动照料的个体
• 容器失败 = 会话丢失
• 需要"护理"恢复健康
• 无法调试（没有服务边界）
• 所有资源假设在同一容器中

✅ Cattle 模式（解耦设计）

• 可互换的、无状态的
• 组件失败 = 重启即可
• 自动恢复，无需人工干预
• 清晰的调试边界
• 资源可按需连接

🔍 Pet 模式的问题

问题 1: 无法调试
唯一窗口是 WebSocket 事件流，但无法区分 harness bug、事件流丢包、还是容器离线。工程师必须进入容器 shell，但容器包含用户数据，这意味着实际上无法调试。
问题 2: 基础设施耦合
Harness 假设 Claude 工作的内容都在容器内。当客户要求连接到他们的 VPC 时，必须对等网络或在客户环境中运行 harness。

🔗 解耦大脑与双手

解决方案：将大脑（Claude 及其 harness）与双手（执行操作的沙盒和工具）和会话（事件日志）解耦。

解耦架构

🧠 Brain（大脑）

Harness + Claude。无状态，可随时替换。

// 接口 wake(sessionId) getSession(id) emitEvent(id, event)

🖐️ Hands（双手）

Sandboxes + 工具。可插拔执行环境。

// 接口 execute(name, input) → string provision({resources})

📜 Session（会话）

追加事件日志。持久、可查询。

// 接口 getEvents() emitEvent(id, event)

🧠 Harness 离开容器

解耦后 harness 不再住在容器内。它像调用任何其他工具一样调用容器：execute(name, input) → string。

  • 容器变成了 cattle——如果死了，harness 将其作为工具调用错误捕获并传回 Claude
  • Claude 决定重试时，新容器可以用标准配方重新初始化：provision({resources})
  • 不再需要护理失败的容器

🔄 从 Harness 失败中恢复

Harness 也变成了 cattle。因为会话日志坐在 harness 外部，harness 中没有任何东西需要在崩溃后存活。

Harness 崩溃
新 harness 用 wake(sessionId) 重启。
恢复状态
使用 getSession(id) 取回事件日志，从最后一个事件恢复。
继续工作
在 Agent 循环中，harness 用 emitEvent(id, event) 写入会话以保持持久记录。

🔒 安全边界

在耦合设计中，Claude 生成的不受信任代码与凭证在同一容器中运行——提示注入只需说服 Claude 读取自己的环境。

⚠️ 耦合设计的风险

攻击者获得 token 后，可以生成新的、不受限制的会话并委托工作。窄范围是一个明显的缓解措施，但这编码了关于 Claude 无法用有限 token 做什么的假设——而 Claude 越来越聪明。

🛡️ 两种安全模式

🔑 模式 1: 认证与资源捆绑

例如 Git：用每个仓库的 access token 在沙盒初始化期间克隆仓库，接入本地 git remote。Git push/pull 在沙盒内工作，Agent 从不处理 token 本身。

🏦 模式 2: 外部 Vault

自定义工具支持 MCP，OAuth token 存储在安全 vault。Claude 通过专用代理调用 MCP 工具；代理用会话关联 token 从 vault 获取凭证。Harness 从不知道任何凭证。

"The structural fix was to make sure the tokens are never reachable from the sandbox where Claude's generated code runs."

🪟 Session 不是 Claude 的上下文窗口

长程任务经常超过 Claude 上下文窗口的长度，标准方法都涉及关于保留什么的不可逆决定。

📦 会话作为外部上下文对象

在 Managed Agents 中，Session 提供了一个存在于 Claude 上下文窗口之外的上下文对象。

  • getEvents() 允许大脑通过选择事件流的位置切片来查询上下文
  • 可以灵活使用：从上次停止的地方继续、在特定时刻前倒回几个事件查看前因、在特定行动前重读上下文
  • 任何获取的事件都可以在传入 Claude 上下文窗口前在 harness 中转换
  • 转换可以是任何 harness 编码的内容，包括实现高 prompt 缓存命中率的上下文组织

🎯 关注点分离

将可恢复的上下文存储（Session）与任意上下文管理（Harness）分开，因为我们无法预测未来模型需要什么具体的上下文工程。

接口将上下文管理推入 harness，只保证 Session 是持久的、可查询的。

🔄 与压缩和 Memory Tool 的关系

之前的上下文工程工作探索了压缩（compaction）和 Memory Tool。但这些涉及不可逆的保留或丢弃决定。如果消息被压缩步骤转换，harness 从上下文窗口中移除压缩消息，只有存储了才能恢复。

Session 的 getEvents() 避免了这个问题——所有事件都持久存储，可按需查询和转换。

🧠🖐️ 多大脑，多双手

解耦架构带来了两个关键优势：可扩展的推理能力和可组合的执行环境。

🧠 多大脑（Many Brains）

最初大脑在容器内意味着多大脑需要多容器。每个大脑在容器配置完成前无法推理；每个会话都预先支付完整的容器设置成本。

TTFT（Time to First Token）改进

p50 TTFT
下降 ~60%
p95 TTFT
下降 >90%

解耦后，容器只在需要时通过工具调用配置。不立即需要容器的会话不需要等待。推理可以在编排层从会话日志拉取待处理事件后立即开始。

🖐️ 多双手（Many Hands）

每个大脑可以连接多双手。这意味着 Claude 必须推理多个执行环境并决定在哪里发送工作——比在单个 shell 中操作更难认知任务。

  • 每双手都是一个工具：execute(name, input) → string
  • 支持任何自定义工具、任何 MCP 服务器、和 Anthropic 自己的工具
  • Harness 不知道沙盒是容器、手机还是 Pokémon 模拟器
  • 因为没有手与任何大脑耦合，大脑可以互相传递手

🏗️ Meta-Harness 设计

Managed Agents 是一个 meta-harness，对 Claude 未来需要的具体 harness 没有意见。相反，它是一个具有通用接口的系统，允许多种不同的 harness。

📐 接口设计原则

📜 状态操作

Claude 需要操纵状态的能力（Session）

⚡ 计算能力

Claude 需要执行计算的能力（Sandbox）

🔢 可扩展性

Claude 需要扩展到大脑和双手的能力

🎯 不做什么假设

  • 不对 Claude 需要的大脑数量做假设
  • 不对 Claude 需要的大脑位置做假设
  • 不对 Claude 需要的双手数量做假设
  • 不对 Claude 需要的双手位置做假设
  • 不对未来需要什么具体的 harness 做假设

🔄 适配现有 Harness

Managed Agents 可以容纳任何 harness：

  • Claude Code：我们在各种任务中广泛使用的优秀 harness
  • 特定任务 Harness：在特定领域表现出色的专用 harness
  • 未来 Harness：随着 Claude 智能增长，新 harness 可以无缝接入

"Meta-harness design means being opinionated about the interfaces around Claude: we expect that Claude will need the ability to manipulate state (the session) and perform computation (the sandbox). But we make no assumptions about the number or location of brains or hands that Claude will need."
