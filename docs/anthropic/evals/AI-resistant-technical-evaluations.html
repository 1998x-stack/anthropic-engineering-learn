📜 Take-home 的起源

2023 年 11 月，Anthropic 准备训练和发布 Claude Opus 3。他们需要更多性能工程师，但标准面试流程太慢。

背景故事

Tristan Hume 在 Twitter 上发帖招人，收到了比标准面试流程能处理的多得多的候选人。他花了 两周时间设计了一个 take-home 测试，目标是：

  • 高效评估大量候选人
  • 捕捉职位真实需求
  • 识别最有能力的申请者

🎯 设计目标与原则

Tristan 对 take-home 有很高的期望——不是无聊的通用问题，而是真正让候选人兴奋的挑战。

⏱️ 长时间窗口

工程师很少面临少于 1 小时的编码 deadline。4 小时窗口（后缩短为 2 小时）更好地反映工作本质。比正常 50 分钟面试更能评估理解现有系统和构建调试工具的能力。

🏠 真实环境

没有人 watching 或期望 narration。候选人在自己的编辑器中工作，没有干扰。更贴近实际的编码体验。

🤖 兼容 AI 辅助

Anthropic 明确允许候选人在这个 take-home 中使用 AI 工具（正如他们在工作中会做的那样）。长时间问题更难被 AI 完全解决，所以候选人可以使用 AI 工具同时仍需展示自己的技能。

🎮 有趣

快速开发循环、有深度且有趣的问、有创意空间。许多候选人超过 4 小时限制因为他们乐在其中。

🖥️ 模拟器架构

Tristan 构建了一个 Python 模拟器，模拟一个类似 TPU 的假加速器。候选人需要在这个机器上优化代码。

模拟器特性

特性说明类比
手动管理暂存内存与 CPU 不同，加速器通常需要显式内存管理TPU
VLIW每个周期多个执行单元并行运行，需要高效的指令打包超长指令字
SIMD对多个元素每条指令进行向量运算向量处理器
多核在多个核之间分配工作多核 CPU

工具：hot-reloading Perfetto trace，显示每条指令，类似于 Trainium 上的工具。

任务：并行树遍历

故意不是深度学习风格，因为大多数性能工程师还没接触过深度学习，可以在工作中学习领域知识。灵感来自无分支 SIMD 决策树推理——经典 ML 优化挑战。

渐进难度：从完全串行的实现开始 → 多核并行（热身）→ SIMD 向量化 或 VLIW 指令打包（二选一）。原始版本还包含一个需要调试的 bug。

✅ 预测性验证

Twitter 批次中有一人的分数远超其他人。他在二月初入职，立即开始优化 kernel，并找到了一个 launch-blocking 编译器 bug 的变通方案（涉及张量索引数学溢出 32 位）。

最强的无限时间提交包括完整的优化微型编译器和几个 Tristan 没有预料到的巧妙优化。

💥 Claude Opus 4 击败了 V1

到 2025 年 5 月，Claude 3.7 Sonnet 已经进步到超过 50% 的候选人如果把任务交给 Claude Code 会得到更好的结果。

🔍 发生了什么？

Tristan 测试了 Claude Opus 4 的预发布版本。它在 4 小时限制内得出了比几乎所有人类都更优化的解决方案。

这不是 Tristan 设计的第一个被 Claude 击败的面试问题。2023 年他设计了一个实时面试问题，Claude 3 Opus 击败了第一部分，Claude 3.5 Sonnet 击败了第二部分。

📝 Version 2 的修复策略

问题比任何人 4 小时能探索的深度都大得多。Tristan 用 Claude Opus 4 找到它开始挣扎的地方，那成为了 V2 的新起点。

关键变更：

  • 编写了更干净的起始代码
  • 添加了新的机器特性以增加深度
  • 移除了多核（Claude 已经解决，且不提供额外信号反而拖慢开发循环）
  • 时间限制从 4 小时缩短到 2 小时
  • V2 强调巧妙的优化洞察，而非调试和代码量

💥 Claude Opus 4.5 击败了 V2

当 Tristan 测试 Claude Opus 4.5 预发布版本时，他 watched Claude Code 工作了 2 小时，逐渐改进解决方案。

0-60 分钟：解决瓶颈
Claude 解决了初始瓶颈，实现了所有常见的微优化，在 不到 1 小时内就达到了通过阈值。
~60 分钟：停滞
Claude 停下来了，确信自己遇到了不可逾越的内存带宽瓶颈。大多数人类也得出了同样的结论。
提示后：找到巧妙方法
当 Tristan 告诉 Claude 可以达到的周期数时，它思考了一会儿并找到了巧妙的方法——利用问题结构绕过瓶颈。
2 小时：匹配最佳人类表现
Claude 继续调试、调优和实现进一步优化。到 2 小时标记时，它的分数与 2 小时内最佳人类表现相匹配——而那个人类也大量使用了 Claude 4 进行引导。
测试时计算 Harness：持续攀升
Anthropic 在内部测试时计算 harness 中更严格地测试，确认 Claude 不仅能 2 小时内击败人类，还能随着时间持续攀升。

🚨 危机时刻

他们即将发布一个模型，在这个 take-home 上的最佳策略是把任务交给 Claude Code。这意味着 take-home 失去了区分人类和 AI 的能力。

🤔 应对选项分析

团队内部讨论了多种应对策略，但每种都有明显的问题。

❌ 选项 1：禁止 AI 辅助

被拒绝。除了执行困难，Tristan 认为只要人类在工作中仍然扮演重要角色，就应该能找到方法让他们在有 AI 的环境中脱颖而出。不想屈服于"人类只有在超过几小时的任务上才有优势"的想法。

⚠️ 选项 2：要求"大幅超越 Claude Code"

有问题。Claude 工作很快。人类通常花 2 小时中的一半来阅读和理解问题，然后才开始优化。试图引导 Claude 的人类可能总是落后——只能在事后理解 Claude 做了什么。

💡 现代性能工程师的实际工作

如今 Anthropic 的性能工程师仍然有很多工作要做，但看起来更像：

  • 艰难的调试
  • 系统设计
  • 性能分析
  • 想办法验证系统的正确性
  • 想办法让 Claude 的代码更简单、更优雅

但这些事情很难在没有大量时间或共同上下文的情况下客观测试。设计代表工作的面试一直很困难，现在比以往任何时候都更难。

🔄 两次重新设计尝试

Tristan 意识到 Claude 可以帮助他快速实现任何设计，这激励他尝试构建更难的 take-home。

尝试 1: 不同的优化问题

选择了一个基于他在 Anthropic 做过的更难的 kernel 优化的问题：2D TPU 寄存器上的高效数据转置，同时避免 bank conflicts。

第一轮
Claude Opus 4.5 找到了一个 Tristan 甚至没想到的巧妙优化——通过仔细分析，它意识到可以转置整个计算而非转置数据，并重写了整个程序。
修补后
Tristan 修补了问题以移除这种方法。Claude 取得了进展但找不到最高效的解决方案。
"Ultrathink" 模式
Tristan 用 Claude Code 的 "ultrathink" 功能和更长的思考预算双重检查……Claude 解决了它。它甚至知道修复 bank conflicts 的技巧。

事后反思：这不是正确的问题。跨许多平台的工程师都在数据转置和 bank conflicts 上挣扎过，所以 Claude 有大量的训练数据可以借鉴。

🎮 Version 3: Zachtronics 风格

Tristan 需要一个人类推理能胜过 Claude 更大经验基础的问题——足够 out of distribution 的东西。

灵感来源：Zachtronics 游戏

Tristan 想到了他享受过的最不寻常的优化问题，最后选择了 Zachtronics 游戏——这些编程解谜游戏使用不寻常的、高度受限的指令集，迫使你以非常规方式编程。

例如在 Shenzhen I/O 中，程序分布在多个通信芯片上，每个芯片只持有约 10 条指令和一到两个状态寄存器。巧妙的优化通常涉及将状态编码到指令指针或分支标志中。

🎯 V3 设计

新的 take-home 由使用极小、严重受限的指令集的谜题组成，以最小指令数为目标优化解决方案。

  • 实现了一个中等难度的谜题并测试 Claude Opus 4.5 → 它失败了
  • 填充了更多谜题，并让同事验证了不太深入问题的人仍然能胜过 Claude
  • 故意不提供可视化或调试工具——起始代码只检查解决方案是否有效
  • 构建调试工具是测试的一部分：你可以插入精心制作的 print 语句，或要求编码模型在几分钟内生成交互式调试器
  • 关于如何投资工具的判断力是信号的一部分

✅ V3 的优势

• 早期结果有希望：分数与候选人过去工作的质量很好地相关
• 一位最有能力的同事得分高于目前所有候选人
• 比原始版本方差更低（更多独立的子问题）

😔 放弃的东西

• 放弃了原始版本的真实性和 varied depth
• 不再像真实工作
• Tristan 很 sad："Realism may be a luxury we no longer have."

"The original worked because it resembled real work. The replacement works because it simulates novel work."

💡 核心启示

从三轮迭代中提炼出的关于 AI 抗性评测设计的关键洞察。

1
AI 正在重新定义"什么是好问题"

曾经能区分人类水平的 take-home，现在可能被模型轻易解决。评测设计必须持续进化。

2
训练数据覆盖是关键弱点

如果问题有大量在线讨论（如 bank conflicts），Claude 可以借鉴更大的经验工具箱。需要 out-of-distribution 的问题。

3
AI 辅助面试 ≠ 禁止 AI

与其禁止 AI，不如设计人类在使用 AI 的场景下仍能展现独特优势的问题。这是更符合未来工作模式的方向。

🔄 评测设计的范式转变

V1: 代表真实工作
→
V2: 更深的优化问题
→
V3: 模拟新颖工作

🎯 对人类优势的思考

Tristan 拒绝接受"人类只有在超过几小时的任务上才有优势"的观点。他相信只要人类在工作中仍然扮演重要角色，就应该能找到方法让他们在有 AI 的环境中脱颖而出。

V3 的方向是：用人类推理的优势对抗 Claude 的经验优势——新奇、受限、需要创造性思维的问题。
