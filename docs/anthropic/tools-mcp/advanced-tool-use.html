🔥 三大新特性总览

Agent 的未来是无缝横跨数百或数千工具的协作。需要发现、学习和动态执行工具，而非预先将所有定义塞入上下文。

🔍 Tool Search Tool

让 Claude 通过搜索工具访问数千个工具而不消耗上下文窗口。85% token 减少（77K → 8.7K），Opus 4 准确率从 49%→74%。

💻 Programmatic Tool Calling

允许 Claude 在代码执行环境中编排工具调用。中间结果不进入模型上下文，token 平均减少 37%。

📋 Tool Use Examples

提供示例工具调用以演示如何有效使用给定工具。复杂参数处理准确率从72% 提升到 90%。

🔍 Tool Search Tool

不再一次性加载所有工具定义，而是按需发现工具。Claude 只看它实际需要的工具。

🔧 实现方式

将所有工具定义提供给 API，但标记 defer_loading: true 使其可按需发现：

{ "tools": [ // Tool Search Tool {"type": "tool_search_tool_regex_20251119", "name": "tool_search_tool_regex"}, // 标记为按需发现的工具 { "name": "github.createPullRequest", "description": "Create a pull request", "input_schema": {...}, "defer_loading": true } // ... 数百个 defer_loading: true 的工具 ]}

✅ 何时使用

  • 工具定义消耗 >10K tokens
  • 正在经历工具选择准确性问题
  • 正在构建带有多个服务器的 MCP 系统
  • >10 个可用工具

💻 Programmatic Tool Calling

让 Claude 通过代码（而非单独 API 往返）编排工具。中间结果不流经模型上下文。

❌ 传统方法: 预算合规检查

  • 获取团队成员 → 20 人
  • 为每个人获取 Q3 费用 → 20 次工具调用 × 50-100 行/项 = 2,000+ 行费用条目 (50KB+)
  • 按员工级别获取预算限制
  • 所有这些都进入 Claude 上下文...
  • Claude 手动汇总每个人的费用...

✅ 代码执行方式

Claude 写一个 Python 脚本编排整个工作流。脚本在沙箱代码执行环境中运行，暂停时需要你的工具结果。只将最终输出返回给 Claude。2,000+ 行条目 → 仅 1KB 结果（超过预算的 2-3 人）。减少了 99.5% 的数据流过上下文。

📊 Programmatic Tool Calling 优势

Token 节省

平均从 43,588 降至 27,297 tokens——复杂研究任务中 减少 37%

降低延迟

消除 19+ 推理传递次数。API 处理工具执行而无需每次返回到模型。

提高准确性

内部知识检索从 25.6%→28.5%；GIA 基准从 46.5%→51.2%

📋 Tool Use Examples

JSON Schema 擅长定义结构——类型、必需字段、允许的枚举——但无法表达使用模式：何时包含可选参数、哪些组合有意义、API 期望什么约定。

📝 示例: create_ticket

// JSON Schema 定义了什么有效，但不回答：// - due_date 格式？"2024-11-06" or "Nov 6, 2024"? // reporter.id 约定？UUID or USR-12345? // escalation.level 和 sla_hours 如何关联 priority? // ✅ 现在可以通过 input_examples 展示用法 { "name": "create_ticket", "input_schema": { /* same schema */ }, "input_examples": [ { "title": "Login page returns 500 error", "priority": "critical", // critical bugs have contact + escalation "labels": ["bug", "authentication"], "reporter": { "id": "USR-12345", "contact": {"email": "jane@acme.com"} }, "escalation": { "level": 2, "sla_hours": 4 } }, { "title": "Add dark mode support", // feature requests: no contact/escalation "labels": ["feature-request"] }, { "title": "Update API documentation" // minimal example } ]}

📈 效果

72% → 90% (+18pp) 准确率提升 🚀

🏆 最佳实践：分层策略

三种特性针对工具工作流中的不同瓶颈：

痛点 1 上下文膨胀

从工具定义中 → 用 Tool Search Tool

痛点 2 大型中间结果

污染上下文 → 用 Programmatic Tool Calling

痛点 3 参数错误

格式化工具调用 → 用 Tool Use Examples

🔧 Tool Search Tool 设置

  • 工具名称和描述清晰可描述可提高搜索准确性
  • 添加系统提示指导 Claude 了解可用功能
  • 保持三到五个最常用的工具始终加载，其他延迟

💻 Programmatic Tool Calling 设置

  • 记录返回格式以帮助 Claude 编写正确的解析逻辑
  • 优先使用可以并行运行的工具（独立操作）
  • 优先使用安全重试的操作（幂等）

"These features move tool use from simple function calling toward intelligent orchestration. As agents tackle more complex workflows spanning dozens of tools and large datasets, dynamic discovery, efficient execution, and reliable invocation become foundational."
