🧠 什么是 Think Tool

Think tool 是一个简单而强大的技术：给 Claude 一个专门的工具，让它在生成回复过程中停下来、思考是否拥有足够信息，然后再继续行动。这在复杂的多步骤工具调用链中尤为有效。

💡 核心概念

Think tool 不会获取新信息或改变数据库，它只是在日志中追加一条"思考"。但这个简单的动作创建了一个结构化的推理空间，让 Claude 可以：

  • 列出适用于当前请求的具体规则
  • 检查是否已收集所有必需信息
  • 验证计划的操作是否符合所有策略
  • 对工具结果进行正确性迭代检查

⚖️ Think Tool vs Extended Thinking

虽然名字相似，但 think tool 和 extended thinking 是完全不同的概念，适用于不同的场景。理解两者的区别是正确使用的关键。

🧠 Think Tool

回复生成过程中插入的思考步骤

  • 在工具调用链中随时触发
  • 处理新发现的外部信息
  • 聚焦于验证和合规检查
  • 推理深度较浅，但针对性强
  • 适合长链工具调用场景

💫 Extended Thinking

回复生成之前的深度思考

  • 在开始生成回复前进行
  • 对计划进行深度迭代
  • 更全面、更综合的推理
  • 适合编程、数学、物理等
  • 适合简单/非顺序工具调用

🎯 最佳使用场景

Think tool 不是万能工具。基于评估结果，以下是它最能发挥价值的场景，以及不推荐使用的场景。

🔎

工具输出分析

当 Claude 需要仔细处理之前工具调用的输出，并可能需要回溯调整方案时。Think tool 提供了分析和决策的空间。

📜

策略密集环境

当 Claude 需要遵循详细的操作指南并验证合规性时。如航空客服中的退改签规则、金融产品的合规检查。

🔗

顺序决策链

当每个行动都建立在前一步之上，错误代价高昂时。常见于多步骤交互域，如订单处理、账户管理。

✅ 推荐使用

  • 复杂工具链中的中间分析
  • 策略合规性验证
  • 多步骤顺序决策
  • 发现 bug 后头脑风暴修复方案
  • 处理边缘情况和异常场景

❌ 不推荐使用

  • 非顺序工具调用（单次或并行）
  • 简单的指令跟随（约束条件少）
  • 不涉及工具使用的纯推理任务（用 Extended Thinking）
  • Claude 默认行为已足够好的场景

🛠️ 实现最佳实践

基于 τ-bench 实验结果，以下实践可以最大化 think tool 的效果。

1. 战略性提示 + 领域特定示例

最有效的方式是提供清晰的使用指导和领域定制的思考示例。示例应覆盖：

  • 推理过程的预期详细程度
  • 如何将复杂指令拆解为可执行步骤
  • 常见场景的决策树
  • 如何检查是否收集了所有必需信息

💡 优化提示示例（Airline 域）

## Using the think tool Before taking any action or responding to the user after receiving tool results, use the think tool as a scratchpad to: - List the specific rules that apply - Check if all required information is collected - Verify the planned action complies with all policies - Iterate over tool results for correctness <think_tool_example_1> User wants to cancel flight ABC123 - Need to verify: user ID, reservation ID, reason - Check cancellation rules: * Is it within 24h of booking? * If not, check ticket class and insurance - Verify no segments flown or are in the past - Plan: collect missing info, verify rules, confirm </think_tool_example_1> <think_tool_example_2> User wants to book 3 tickets to NYC with 2 checked bags - Need user ID to check membership tier - Baggage calculation: * Economy class x 3 passengers * If regular: 1 free bag each -> 3 extra = $150 * If silver: 2 free bags each -> 0 extra = $0 * If gold: 3 free bags each -> 0 extra = $0 - Payment rules to verify: max 1 travel cert, 1 credit card, 3 gift cards </think_tool_example_2>

2. 将复杂指导放入 System Prompt

当指导内容较长或复杂时，将其放在 system prompt 中比放在 tool description 中更有效。这提供了更广泛的上下文，帮助模型更好地将思考过程整合到整体行为中。

🚀 快速上手指南

添加 think tool 的最大优势在于极低的实现门槛和最小的副作用风险。它不会改变外部行为，除非 Claude 主动决定使用它。

三步上手

🧪
Step 1: 测试场景
从最具挑战性的 agentic 用例开始 — Claude 当前在策略合规或长链推理上表现不佳的场景
🔧
Step 2: 添加工具
实现领域定制的 think tool 定义。考虑在 system prompt 中加入使用指导和示例
📈
Step 3: 监控迭代
观察 Claude 如何使用 think tool，根据实际表现调整提示以引导更有效的思考模式

"添加 think tool 几乎没有负面影响。它不改变外部行为，除非 Claude 决定使用它，也不会干扰你现有的工具或工作流。我们的研究证明，它能显著增强 Claude 在需要策略遵循和长链工具调用推理的复杂任务上的表现。"

⚠️ 注意：Token 成本

Think tool 会增加 prompt 长度和输出 token 数量。在不需要的场景中添加它虽然不会降低性能结果，但会增加不必要的延迟和成本。请根据实际场景选择是否启用。

📚 适用模型

虽然文中的 τ-Bench 结果聚焦于 Claude 3.7 Sonnet，但实验显示 Claude 3.5 Sonnet (New) 也能在相同配置下获得性能提升，表明此改进可推广到其他 Claude 模型。
