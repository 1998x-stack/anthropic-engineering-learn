🧠 Training Beats Prompting

在数万次 agent session 中得到的最重要结论：当 prompt 与模型的 training 冲突时，training 永远赢。

Prompting 是一种建议，Training 是引力。模型在训练期间看到的模式远比你的 prompt 指令更深入。

🐍

Python 状态持久化

Prompt 说 stateless，模型仍引用之前变量。因为训练中 99% 的 REPL 都是有状态的。

🔄

Sequential Loops

Prompt 说用 Promise.all，模型用 for 循环逐个 requests.get()。

📨

Slack via Python

有专用 Slack tool 在 tool list 里，模型直接写 requests.post()。

✅ 什么才真正有效

如果无法通过 prompt 克服训练先验，怎么办？利用模型最深层的训练：error → fix 循环。

❌ 无效方式：Prompt 指令

"不要使用 sequential loops"

模型完全忽略 — 因为训练先验更强

AST 检测循环 → 返回错误信息

🔍 Freedom Reveals Intent

不是所有意外行为都应该被捕获。有些是模型在告诉你它需要什么。

file:// URLs — 自我验证
Agent 构建 HTML 文件后试图用 file:///workspace/output.html 打开。看似 bug，实际是在验证自己的输出。
Browser Self-Heal — 自主恢复
Agent 检查到死掉的 runtime 对象，写 Python 代码重启浏览器。这不是故障，是自主恢复能力。
Raw API 偏好 — 训练偏好
Agent 写 requests.post() 而非用 Slack tool。说明你的 tool 接口不如 raw API 清晰。
核心判断：Catch or Enable
给最大自由度，观察模型行为，然后决定：限制还是启用。围绕观察到的行为构建 harness。

🎯 核心方法论

越少假设，越多有效。简洁比精巧更强大。

The Method

在沙箱中给最大自由度 → 观察模型伸手去拿什么 → 决定 catch 还是 enable → 围绕观察到的行为构建 harness，而非假设的行为。

❌ 传统方式

假设行为 → 精心设计 prompt

→ 复杂的 heuristic 系统

→ 与训练先验对抗

✅ 自由度方式

观察行为 → 少量 runtime guards

→ 模型自带智能

→ 与训练先验协同

"A few robust runtime guards plus model intelligence will always beat elaborate prompt engineering or complex heuristic systems."
