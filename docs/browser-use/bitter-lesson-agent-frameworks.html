🚫 为什么抽象会破坏学习

每一个抽象都冻结了你关于"智能应该如何工作"的假设。RL 会打破这些假设。

❌ 典型 Agent Framework

数千行抽象代码

Planning modules / Verification layers / Output parsers

编码了你认为模型应该做什么

每次实验都在与 framework 对抗

✅ Minimal Approach

一个 for-loop of tool calls

模型已在训练中看过更多模式

抽象变成约束，阻止模型使用它学到的东西

Less is more

"The Bitter Lesson from ML research is clear: general methods that leverage computation beat hand-crafted human knowledge every time. Agent frameworks are just the latest instance of this mistake."

💡 核心洞察：Action Space 不完整才是问题

Agent frameworks 失败不是因为模型弱，而是因为它们的 action space 不完整。

关键反转

不要预定义所有可能的 action。从相反的假设出发：模型能做几乎任何事。然后限制。

传统：定义 actions → 限制模型
VS
新方式：最大自由度 → 根据 evals 限制

Claude Code 可以直接写 AppleScript 控制 Spotify，不需要任何 Spotify tool。模型已经知道了。你无法预见每个 use case，但模型已经知道。

🔧 BU Agent 架构

给模型原始的浏览器控制面 — CDP + 浏览器扩展 API。几乎完整的 action space。

🎮

Chrome DevTools Protocol

原始 CDP 指令。模型可以在浏览器中做几乎任何事。

🧩

Browser Extension APIs

让某些用 CDP 很笨拙的任务变得简单 — 如访问 active window。

"CDP and extension APIs each have blind spots. But together they form a nearly complete action space."

自我修复能力

当一种方法失败时，模型会自动绕行。当一个 tool 坏了，它会找到另一条路径。

"As long as in principle everything is possible, LLMs are extremely good at fixing themselves on the fly."

💭 Ephemeral Messages

Browser state 巨大 (50KB+/次)。10 次交互 = 500KB context。模型会失去 coherence。

@tool("Get browser state", ephemeral=3) # 只保留最近 3 次 async def get_state() -> str: return massive_dom_and_screenshot
问题：Context 爆炸
每次请求 browser state 都是 50KB+。20 次交互 = 1MB context，模型崩溃。
方案：Ephemeral Messages
超过 N 次调用后，自动删除之前的输出。稍微破坏 cache，但非常值得。
效果
LLMs 本就无法处理巨大 context。限制反而让模型更专注。

🛑 Done Tool 模式

朴素方法 — "没有 tool calls 就停止" — 不够好。Agent 会过早结束。

@tool('Signal that the current task is complete.') async def done(message: str) -> str: raise TaskComplete(message)

CLI Mode

当 LLM 不返回 tool calls 时停止

适合快速交互

Autonomous Mode

只有显式 done() 调用时才停止

强制明确完成，不再模糊的"我猜我们完了？"
