📚 从 Frameworks 到 Harnesses 的进化

之前说"不要包装 LLM"。但我们仍在包装它的 tools。每个 click()、type()、scroll() helper 都是抽象。

❌ V1：包装 Tools

数千行 element extractors

DOM indexers, click wrappers

每个 helper 是模型必须绕过的约束

✅ V2：Raw CDP

LLMs 已经知道 CDP

训练数据中有百万 token 的 CDP 代码

直接给模型原始控制面

"Every click(), type(), scroll() helper is an abstraction you decided the model needs. Every one of them is a constraint the RL'd model has to fight around."

🎮 为什么用 Raw CDP

我们之前说"agent 不需要了解 CDP 的细节"。结果发现我们错了。

Cross-origin Iframes
直接 attach target，不需要 frame 抽象层。
Shadow DOM
shadowRoot.querySelectorAll — 模型见过上万次这种代码。
Anti-bot Injection
Chrome 跟自己对话，无需伪装。
自动 Crash Recovery
以前用 watchdog 处理 10 种崩溃。现在给 LLM 直接 CDP access + 编辑 harness 的能力，它自己处理一切。
关键认知翻转
CDP 的"复杂性"不是要隐藏的东西，而是要让模型看到的东西。

📁 四个文件的架构

整个 harness 就是 ~600 行代码。Agent 写 Python，Python 调 helpers，helpers 说 CDP，Chrome 执行。

run.py
13 行
用预加载的 helpers 运行 Python
helpers.py
192 行
CDP 的 thin wrapper — agent 可以编辑它们
daemon.py
220 行
保持 CDP websocket 连接
SKILL.md
—
告诉 agent 如何使用以上文件
Agent 写 Python
→
Python imports helpers
→
Helpers speak CDP
→
Chrome 执行

Chrome 之上的一切都是可重写的

🔄 Self-Heal Loop

当 helper 缺失时，agent 做任何 Claude Code 用户会做的事：grep helpers.py，添加函数，重新运行。

关键洞察

Agent 不是从零写新代码。它在写"那个缺失的函数" — 就像修复一个 missing import 一样。这正是 coding agents 最擅长的事。

遇到缺失功能
→
grep helpers.py
→
添加缺失函数
→
重新运行成功

🎂

Gusto → Calendar

"The bitter lesson of agent harnesses: your helpers are abstractions too. Delete them. Let the agent write what it needs."
