🐣 早期部署 (Apr-Jun 2025)

First deploys that didn't deploy, wrong AWS regions, and installing a browser I didn't need.

第一次部署即失败

Lambda 在 private subnet 没有 NAT gateway + database security group 未包含 Lambda。两个不相关的问题，一次部署。

Fix: 没有 staging 环境来捕获它 — 因为 staging 还没建

硬编码 us-west-1

Lambda log ARNs, SNS policies, ALB certificates 全部硬编码了错误 region。实际运行在 us-east-2。逐字符对比 ARN 才发现。

Fix: 3 commits 修复 — 几个月后在 SSM ARNs 上重蹈覆辙

在 Lambda 中安装 Chromium

3 小时 + 6 commits 在 Lambda container 中安装 Chromium。最后才意识到：我们通过 CDP 连接远程浏览器，根本不需要本地浏览器。

Fix: 删除所有安装代码

💰 Billing 灾难 (Jul-Aug 2025)

Users getting free money, payments going through before anyone paid, and rounding errors that made LLM calls free.

免费 Credits 被刷

free_credits_claimed boolean 存在但从未检查。一个 if 修复。

round(0.4) = 0

任何 < 0.5 credit 的 LLM call 都免费。round() 用于 billing。

预付费 Credits

Stripe webhook 在 subscription.created 时发 credits — 支付前。

asyncio.Lock 跨 Pod

内存锁在单进程有效，跨 pod 无效 — 可 double-spend。

🔄 一天三个同样的 Bug (Aug 19)

One day, three files, the same mistake every time.

UnboundLocalError x 3

同一天修复了三个 UnboundLocalError。全部是同一模式：变量在 try 块内定义，在 except 块中引用。如果 try 在赋值前失败，变量不存在。

❌ Naive Datetime

数据库存 naive timestamps

代码用 datetime.now(timezone.utc)

Python 拒绝比较 → 崩溃

Hack: .replace(tzinfo=None)

✅ 真正的修复

62 文件 refactor

一个月后完成

这类 bug 在修根因前出现了 3 次

💧 Memory Leak 马拉松 (Feb 2026)

Seven commits in one day chasing connection leaks, dead TCP sockets that looked alive.

每次 LLM Call 创建新 httpx Client

每个 httpx client 分配一个永不关闭的 connection pool。加上 ssl.create_default_context() 耗时 ~1.8s CPU。

Fix: 整整一天学到 HTTP clients 应该是 singletons

Micro-VM 的死 TCP 连接

VM suspend 后所有 TCP socket 死掉，但 HTTP client 不知道。monotonic clock 在 suspend 期间冻结，timer 以为过了 0 秒。

Fix: 尝试了 3 种方案后，brute force 赢了 — 每次 query 销毁重建 client

💥 规模化问题 (Mar 2026)

I killed our own production machines with a load test. Then a third-party SDK froze the platform for 4 minutes.

❌ Load Test 击溃生产

将 load test 指向生产裸金属机器

45 分钟停机

运行 agent sandbox 的机器全部宕机

❌ Sync SDK 冻结 Event Loop

第三方 SDK 内部同步 HTTP 调用

API 变慢 → event loop 冻结

262 gateway timeouts in 4 minutes

最讽刺的部分

21 个调用点中的 1 个已经有了 fix。注释写着 "offload sync SDK call to thread to avoid blocking event loop"。只是从来没有应用到其他地方。

💡 五大教训

Most of my mistakes fall into a few patterns.

🤔

假设而非检查

假设 SDK 是 async，假设 keepalive 能存活 VM suspend，假设 round() 适合 billing。

🚫

没测完整路径

脑中 work 了但 deploy 崩了。然后 live 在 production 上 commit by commit 修。

🧠

选聪明方案而非简单方案

Keepalive timers vs client recreation。聪明方案总是需要更多修复。

⏳

没完成开始的事

Sync-to-async 在 21 个调用点中只修了 1 个。每个 partial fix 给了虚假信心。

🏗️

构建没人要的东西

GIF 生成，独立 billing service。602 行没人用也没人想念。

"The gap between 'works in a demo' and 'works at scale' is about 4,000 commits. This is what most of them looked like."
