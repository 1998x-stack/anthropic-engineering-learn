💡 核心理念

所有的 hackathon 技巧都建立在两个基础之上：好奇心和构建欲望。如果你同时拥有这两点，你注定会在 hackathon 中脱颖而出。

✅ 赢家心态

  • 真正的好奇心驱动
  • 以 builder 身份思考产品
  • 热情在 demo 中自然流露
  • 想法让人惊叹

❌ 常见误区

  • 只想赢比赛，不想解决问题
  • 看往期项目寻找灵感（扼杀原创性）
  • 过度优化 sponsor track
  • 忽略 demo 准备

"If you're good at hackathons, you will be good at a startup." — Reagan Hsu

📋 如何规划项目

规划的核心是让评委在短短几分钟内完全理解你的产品。Demo 的第一印象决定一切。

🔎 为什么视觉比技术深度更重要？

评委很难在几分钟内理解技术深度。但优秀的 UI/UX 是通用语言 —— 每个人都能感受到。Technical depth 应通过 slides 辅助说明，而不是期望评委自己发现。

⚙️ 如何实现

Hackathon 项目是 proof of concept。"If it works, it works" 是核心原则。以下是 7 条实战技巧。

前后端分离
Architecture
前端 mock API endpoint，后端独立开发，最后再联调。
能跑就行
Mentality
Hackathon 项目是概念验证，不是生产级代码。保持 "if it works, it works" 心态。
大量使用 Coding Agent
Tooling — ~5 个并行
Reagan 通常同时跑约 5 个 coding agent，大幅提升开发速度。
聪明地 Mock
Strategy
只 mock 非核心功能。核心产品功能必须真实可用。
保留 Demo 时间
10-20 分钟
至少预留 10 分钟（最好 20 分钟）来准备 demo。Main branch 必须保持可用。

🎤 如何 Demo

Demo 是最后一关。原则：尽可能少说话，让 demo 自己说话。

Demo 结构流程

💬 一句话 Pitch
→
🔴 问题
→
✅ 方案
→
🎬 现场 Demo

🌟 Pitch

第一句话就要一句话讲清楚你的项目。简短、清晰、甜美。

🎓 假设知识

假设评委懂全栈开发基础原理，但仅此而已。不要用行话。

🖼️ Slides 辅助

用 slides 来辅助解释，格式：one sentence pitch → problem → solution → demo。

✅ 创意健全性检查

  • Is it showstopping? 任何工程师看到都会说 "That's cool"？
  • What problem does it solve? 明确定义问题场景
  • Who is it for? 谁是目标用户？
