🤖 Auto-Research 方法

核心思路：给 Claude Code 一个 eval CLI 和一个 prompt，让它在循环中自主运行 20 个 cycle。无编排代码，多个 session 并行执行，构建搜索树。

✅ 关键策略

  • 鼓励 big bets，避免 small tweaks
  • 小改动在 run-to-run variance 中淹没
  • 只关注最佳表现者
  • TSV 代替 JSON 节省 40% tokens

🔬 Debugging CLI

  • 3 层层级结构分析 trace
  • 单个 trace 可达数百万 tokens
  • 让 agent 快速定位 root cause
  • 格式选择决定 debug 效率

💡 最大改进：Coding Agent 化

Claude Code 将 browser agent harness 升级为 coding agent —— 不再只有 click 和 type，新增了 Python 代码来解析 HTML 和提取数据。这与 LLM 的训练分布更匹配，大幅降低了 edge case 难度。

❌ 传统 Tool-based

  • 只有 click, type, scroll 等工具
  • 数据提取困难
  • Edge case 需要特殊处理
  • 与 LLM 训练分布不匹配

✅ Coding Agent

  • 新增 Python 解析 HTML
  • 数据提取变得简单直接
  • Edge case 用代码灵活处理
  • 完美匹配 LLM 代码生成能力

⚖️ Agentic Judge

原始 judge 基于截图。但现代 browser agent 会写代码、调 API、提取上千条数据。传统 judge 将此视为幻觉。能力越强的 agent 需要越强的 judge。

Screenshot-based Judge
传统方案
原始 benchmark 使用截图对比判断任务完成度，无法评估代码输出和 API 调用。
Agentic Judge
Claude Agent SDK
基于 Claude Agent SDK 构建的 agentic judge，能理解代码输出、API 结果和大规模数据提取。
Human Alignment
关键步骤
将 agentic judge 与人类判断对齐 —— 这是让 auto-research loop 可靠运行的关键。

🔬 Overfitting 与未来

Auto-research loop 天然倾向于 overfit 单个任务。团队使用 train/validation split 确保泛化能力，并持续在未见过的数据集上验证。

🛡️ 防止 Overfitting 策略

  • 使用 train/validation splits，loop 只看 training data
  • 在历史数据集上验证，确认分数全面提升
  • 大部分 merge 工作是拒绝 task-specific 的解决方案
  • 保留全部 300 个任务，不移除任何 "impossible" 任务

"We need harder benchmarks. We're building one with everything users actually care about -- including tasks like 'Extract 1000 products with subpages and compare them across platforms.'" — Magnus Muller
