🔬 为什么需要新的评估引擎

评估一个浏览真实网页的 agent 跟评估 LLM 文本 benchmark 完全不同。真实网页是混乱的、非确定性的、持续变化的。单次运行的确定性测试在这里毫无意义。

❌ 传统 LLM 评估

  • 静态文本数据集
  • 确定性输入输出
  • 单次运行即可评判
  • 合成环境模拟

✅ Web Agent 评估

  • 真实网站 — 混乱且多变
  • Non-deterministic — A/B test 影响
  • 多次运行 + Statistical bootstrapping
  • Millions of LLM-labeled user spans

"It's concerning that many AI agent benchmarks do not include error bars or variance estimations; coming from backgrounds in experimental particle physics, that lack of statistical rigor is alarming." — Alexander Yue

使用 Blacksmith runners on GitHub Actions 实现极致并行：100 个复杂 web 任务在 5 分钟内完成。LLM judge 直接内嵌在 agent 代码中。

🚫 Clustering 的失败

最初尝试对失败 trace 做 embedding + clustering 来发现共性问题 —— 完全失败。

Embedding + Clustering
初始尝试 — 失败
对失败 trace 做 embedding 并聚类，试图自动发现错误模式。结果完全不可用。
Pivot: Raw failure_reason
转折点
让 Claude Code 从 judge 中提取原始 failure_reason 字符串。
迭代分类
Actionable Buckets
Claude 阅读数百条原始原因，建议具体分类，丢弃小分类，迭代细分大分类 —— 最终得到高度具体、可操作的错误桶。

🔄 5 步 Slack 工作流

  • Step 1: 开发者在 Slack 中 ping Claude 请求运行 eval
  • Step 2: Claude 通过 MCP server 触发 Blacksmith runners
  • Step 3: Traces 流入 Laminar 和 ClickHouse
  • Step 4: Claude 执行 SQL 查询，进行统计 A/B analysis
  • Step 5: 汇总报告发回 Slack，开发者可继续 ping Claude 修改代码
