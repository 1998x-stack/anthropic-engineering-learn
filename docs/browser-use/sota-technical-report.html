关键调整

团队对原始 WebVoyager 代码库做了几项针对性修改：Prompt 微调以适配 Browser Use 的 Action Space，将纯 OpenAI SDK 迁移到 Langchain，并移除了 55 个因过期数据（航班日期、酒店预订等）而无法完成的任务。

❌ 被移除的任务类型

Apple 上无法显示价格的产品查询、过时的日期（2023 年航班/酒店）、不存在的食谱搜索结果等 55 个不可能完成的任务。

✅ 保留的任务特征

跨 15 个真实网站的 586 个多样化 Web 任务，涵盖搜索、导航、信息提取、表单填写等多种交互模式。

🔍 结果分析

步数与成功率的关系揭示了 Agent 在不同网站上的行为模式。

高成功率 + 低步数

HuggingFace（100%, 9.7 步）和 Coursera（90%, 8.5 步）代表"简单"网站——页面结构清晰、导航直观，Agent 可以高效完成任务。

高成功率 + 高步数

Google Flights（95%, 36.2 步）是特殊案例——成功率极高但步数也极多。说明该网站交互复杂（多步表单、日期选择器等），但 Agent 可以可靠地完成。

低成功率 + 高步数

Booking（80%, 32.7 步）结合了复杂交互与较低成功率，可能存在 Cloudflare 防护和动态价格加载等障碍。

整体分布

即使"最差"的 Booking.com 也达到了 80% 成功率。所有 15 个域的平均成功率为 89.1%，展示了 Browser Use 的全面能力。

"Even our 'worst' performing domain (Booking.com) still achieved an 80% success rate. Not too shabby!"

⚠️ 注意事项与透明度

团队对评测中的局限性和人工干预进行了公开说明。

📅

过期数据

部分任务的日期已过期（航班、酒店），需要从 2023→2024 或 2024→2025 调整

🛡️

Cloudflare 拦截

部分网站触发了 Cloudflare 反爬保护，导致 Agent 被阻断

🤖

Eval 模型不佳

默认 WebVoyager Evaluator 判断不准确，增加了 "unknown" 状态并人工复核

人工修正流程

对于评测模型判定为 "unknown" 或 "failed" 的任务，团队进行了人工复核和修正。虽然这可能引入偏差，但团队认为这比使用不可靠的自动评估更诚实。未来计划会让人工标注更加透明。

🚀 未来规划

SOTA 只是起点——团队正在推进多模型支持、代理旋转和更透明的标注体系。

标注透明化

引入代理旋转机制，解决 Cloudflare 等反爬拦截问题
多模型测试
在 Claude、GPT-4o、Llama 3 等多种 LLM 上运行评测对比
