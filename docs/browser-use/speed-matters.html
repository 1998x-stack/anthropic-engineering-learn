🧪 评测挑战

标准的截图评测流水线不适用于 DOM 驱动的 Agent——需要同时考虑截图和 DOM 状态。

❌ 传统评测方式

OnlineMind2Web 的 Judge 模型仅基于截图评估 Agent 的行为，无法观察到 DOM 中可交互但不在视口中的元素。对 Browser Use 的 DOM-based Agent 不公平。

✅ 适配后的评测

改造 Judge 使其同时考虑截图和 DOM 状态。这对 Vision-based 模型仍然公平（截图信息不变），同时准确捕获 DOM-based Agent 的真实能力。

🗄️ KV Cache 优化策略

通过巧妙的 Prompt 结构设计，实现 KV Cache 命中，大幅降低延迟和成本。

核心洞察：Browser Agent 的状态问题

与 Coding Agent 不同，Browser Agent 面对的浏览器状态是独立变化的——每一步都需要重新观察当前页面。传统方法将浏览器状态放在 Prompt 前面，导致每次调用都无法利用 KV Cache。

❌ 传统 Prompt 结构

[Browser State] → [History] → [Action]

Browser State 每步都变化，放在最前面会导致整个 KV Cache 失效。每次调用都需要重新计算所有 token。

✅ BU 1.0 Prompt 结构

[History] → [Browser State] → [Action]

History 不变放在前面 → KV Cache 命中。Browser State 只在末尾追加。大幅降低延迟和成本。

DOM 优先，视觉辅助

BU 1.0 默认使用 DOM 进行导航——解析页面结构、定位元素、提取文本。只有当视觉上下文确实必要时（如验证码识别、视觉布局判断）才捕获截图。这消除了大多数步骤的 Image Encoder 开销。

Computer Use 模型的做法

通过阅读截图提取信息——成本高、速度慢，且只能看到屏幕可见区域的内容。

BU 1.0 的 extract tool

直接从 DOM 查询页面的 Markdown 表示。当页面包含 20,000+ token 时，Agent 不会全部放入上下文，而是提出精确问题获取精确答案。

✂️ 极简 Output Token

Output Token 的时间成本是 Input Token 的 215 倍——极简 Action Space 设计至关重要。

Action Space 设计哲学

大多数动作可以用 10-15 个 Token 表达。Action Name 和参数都经过精心压缩——越少的 Output Token = 越快的执行。BU 1.0 在自研 LLM 基础设施上测量了这些数据，证实了极简设计的巨大收益。
