🎯 为什么需要 Stealth 基准测试

Agent 的瓶颈不是智能——而是被 CAPTCHA 和反爬系统拦截。Agent 智能和浏览器隐身是正交的两个维度。

"The bottleneck for agents is not their intelligence. On most websites users care about, agents get blocked by a CAPTCHA or an antibot challenge."

❌ 混合评测的问题

传统 benchmark 将智能和隐身混为一谈——Agent 失败时无法区分是"不够聪明"还是"被拦截了"。

✅ 正交评测

Stealth Benchmark 使用极简任务（每站仅 3 步），排除智能因素，专注测量浏览器的反检测能力。

评判标准

每个站点仅执行 3 步简单操作（搜索、访问页面、读取链接），不需要认证。使用 gemini-2.5-flash 作为 LLM Judge，仅评判 Agent 是否被拦截——而非是否正确完成任务。Page load failure 也计为被拦截。

🔬 控制实验

使用数据中心 IP 上的两种基线浏览器验证 Benchmark 的有效性。

Headless Chromium：2%

最可疑的浏览器配置——每轮运行不到 2 个任务通过。几乎所有 Anti-bot 系统都能轻松检测到 Headless 模式。

Headful Chromium：50%

同一台机器，只是渲染了可见窗口。分数从 2% 跳到 50%，证明 Headless 检测是 Anti-bot 最简单的信号之一。

"This validates that the task set consists of high-security sites and that score improvements reflect real stealth capability."

🎭 行业现状批判

大多数云浏览器供应商只是在标准 Chromium 上加了住宅代理和第三方验证码插件——然后标上"高级隐身"。

"Most cloud browser providers slap a residential proxy and a third-party CAPTCHA solver extension on a stock Chromium, put 'Advanced Stealth' on the landing page, and call it a day."

普遍的指纹泄露

大多数竞品暴露相同的指纹：headful Linux Chromium。当主流 Anti-bot 不再对这些明显泄露"网开一面"时，这些方案就会全面失效。如果你的供应商 User-Agent 以 Mozilla/5.0 (X11; Linux x86_64) 开头——赶紧换。
