🔙 问题背景

Browser Use 运行数百万 Web Agent。起初用 AWS Lambda 做浏览器隔离，后来加入了代码执行能力——问题开始了。

Phase 1：AWS Lambda
每次调用天然隔离、即时伸缩、无 Secret 泄露风险。仅支持浏览器操作。
Phase 2：加入代码执行
Agent 可以写 Python、执行 Shell 命令、创建文件。代码运行在独立 Sandbox 中（作为 tool 调用），安全性无问题。
Phase 3：问题暴露
Agent 循环仍然跑在 REST API 同一个后端进程中。重部署？所有 Agent 死掉。内存大户？API 变慢。两个完全不同的 Workload 共享一个进程。

🔀 两种隔离模式

Agent 可以运行任意代码时，它能访问机器上的一切——环境变量、API Key、数据库凭证。必须隔离。

Pattern 1：隔离 Tool

Agent 运行在你的基础设施上。危险操作（代码执行、终端访问）运行在独立 Sandbox 中。Agent 通过 HTTP 调用 Sandbox。

起步阶段

Pattern 2：隔离 Agent

整个 Agent 运行在零 Secret 的 Sandbox 中。通过 Control Plane 与外部世界通信——所有凭证由 Control Plane 持有。

最终选择

"The agent becomes disposable. No secrets to steal, no state to preserve, you can kill it, restart it, scale it independently. The control plane holds the truth."

📦 沙箱实现

同一个容器镜像，通过一个配置开关在 Unikraft Micro-VM（生产）和 Docker（开发/评测）之间切换。

Unikraft 生产环境

每个 Agent 获得独立的 Unikraft Micro-VM，启动时间不到 1 秒。通过 REST API 在 AWS 裸金属机器上按需创建。支持 Scale-to-Zero：空闲时 VM 挂起，有请求时自动恢复。

Docker 开发/评测

同一个镜像、同一个入口点、同一个 Control Plane 协议。sandbox_mode: 'docker' | 'ukc' 一个开关切换。

沙箱接收的环境变量（仅 3 个）

SESSION_TOKEN=<临时会话令牌> CONTROL_PLANE_URL=<Control Plane 地址> SESSION_ID=<会话标识> # 无 AWS Key，无数据库凭证，无 API Token

🛡️ 安全加固

三层防护：字节码编译、权限降级、环境变量清除——在任何 Agent 代码运行之前。

🔒

Bytecode-Only

Docker 构建时编译所有 Python 为 .pyc，然后删除所有 .py 源文件

👤

Privilege Drop

入口以 root 启动，立即通过 setuid/setgid 降级为 sandbox 用户

🧹

Env Stripping

读取环境变量到 Python 变量后，从 os.environ 中删除

🎛️ Control Plane 架构

无状态 FastAPI 服务——Sandbox 没有直接外部访问权，所有请求通过 Control Plane 代理。

LLM Proxying

Sandbox 仅发送新消息，Control Plane 在数据库中维护完整对话历史，在每次调用时重建完整上下文，再转发给 LLM Provider。

File Sync via Presigned URLs

Agent 在 /workspace 目录读写文件。File Sync Service 监控变更并定期同步到 S3——但 Sandbox 永远看不到 AWS 凭证。

Gateway Protocol

生产环境：ControlPlaneGateway 发送 HTTP 请求。本地开发/评测：DirectGateway 直接调用 LLM，内存中保存历史。

Scaling

Control Plane 无状态：验证 Token → 执行操作 → 返回结果。需要更多 Agent？启更多 Sandbox。需要更多吞吐？Load Balancer 后加 Control Plane 实例。

🎯 核心要点

Agent 应该没有任何值得窃取的东西，也没有任何值得保留的状态。

"Your agent should have nothing worth stealing and nothing worth preserving."

Pattern 1：隔离 Tool

Agent 在你的后端 → 代码执行在 Sandbox 中。安全但 Agent 仍然能访问基础设施。适合起步阶段。

Pattern 2：隔离 Agent

整个 Agent 在 Sandbox 中 → 通过 Control Plane 对外通信。Agent 可丢弃、可杀死、可独立伸缩。最终形态。
