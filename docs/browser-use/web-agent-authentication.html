🔐 认证困境

AI Agent 可以浏览网页、点击按钮、填写表单——但无法登录。认证阻止了 Agent 完成真正有用的任务。

❌ 未认证的 Agent

不能检查邮件、管理日历、处理退货、访问内部工具。只能在公开页面上操作——能力受到严重限制。

✅ 已认证的 Agent

可以代表用户完成跨应用的完整工作流——登录、操作、提交——就像用户本人在操作一样。

🍪 Cookie Syncing

最直接的方式——将你浏览器的 Cookie 存储复制到 Agent 的浏览器中。

Browser Use

支持一键同步真实 Chrome Profile 到云端，也支持导出 Cookie 为文件。唯一支持 Profile Sync

Browserbase

通过可复用的 Contexts 持久化认证状态。API 直观——认证一次，保存 Context，未来会话加载即可。也支持 Cookie-Sync Skill。

Steel

使用 Profiles——持久化浏览器身份，跨会话存储 Cookie、Auth Token 和指纹。

Kernel

通过 Profiles 保存 Cookie 和 Local Storage，未来会话自动带上认证状态。

🗝️ Password Manager 集成

1Password 等密码管理器让 Agent 从 Vault 获取凭证并自动填充登录表单——包括 TOTP 码。

工作原理

Agent 永远不会看到你的实际密码——所有值都通过编程方式直接填入页面。密码管理器还存储 TOTP Secret，可以自动生成那些每 30 秒刷新一次的 6 位验证码。

🔑 2FA / TOTP 自动化

如果你有 TOTP Secret Key，就可以编程生成验证码——不需要 Authenticator App。

Browser Use 的 TOTP 实现

使用以 bu_2fa_code 结尾的占位符，Agent 在输入时自动生成新鲜的 TOTP 码：

agent = Agent( task='Go to example.com/login, enter x_user, x_pass, and x_bu_2fa_code', sensitive_data={ 'x_user': 'myusername', 'x_pass': 'mypassword', 'x_bu_2fa_code': 'JBSWY3DPEHPK3PXP', # TOTP secret key }, )

Agent 只看到占位符名称（x_user），实际值直接注入页面——Agent 永远不会接触到你的真实凭证。

📧 Email / SMS 验证

部分网站通过邮件或短信发送验证码——可以用 Agent 管理的收件箱接收。

AgentMail

AgentMail 是独立的 API，用于创建 Agent 管理的邮箱。Agent 发起登录 → 网站发送验证码到 AgentMail 邮箱 → Agent 读取验证码 → 完成验证。整个流程自动化，无需人工干预。
