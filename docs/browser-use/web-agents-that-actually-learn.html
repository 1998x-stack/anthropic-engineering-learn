🔄 重复探索的代价

LLM 在互联网上训练过，但"在互联网上训练"不等于"了解每个网站"。Google Flights 的特定交互逻辑？Out of distribution。

❌ 没有 Skill 的 Agent

每次运行都为探索付全价。在 Google Flights 上输入城市、按回车——什么也不发生。需要等下拉菜单出现再点击。Agent 每次都犯同样的错。

✅ 有 Skill 的 Agent

探索只付一次费用，分摊到所有未来运行中。一个 Agent 搞清楚 Netflix 怎么用，之后每个 Agent 都直接知道。

Exploration vs Exploitation

每个 Web Agent 任务分两个阶段：Exploration（搞清楚网站怎么用）和 Exploitation（真正执行任务）。人类犯一次错就永远记住。为什么 Agent 不能？

🧠 Skill 学习机制

任务完成后，第二个 Agent 审查完整 Trajectory，提取可复用的 Skill。

Skill Agent 的核心问题

"What would you need to know to solve this in 1-3 calls?"

Skill 包含三要素：URL Pattern（适用的页面）、Recipe（操作步骤）、Skip Count（未来 Agent 可以跳过的步数）。

🎓 案例：Duo 2FA

每个大学生登录 Canvas 都会遇到 Duo 2FA。第一个 Agent 花了 8 次额外调用才搞定。254 个后续 Agent 都不需要了。

Agent #1：探索
花了 8 次额外调用搞清楚设备信任提示。发现按钮有稳定的 DOM ID：dont-trust-browser-button
Skill Agent：提取
生成 Recipe：检测提示 → 通过 getElementById 点击 → 轮询直到重定向
254 个后续 Agent
没有一个需要重新搞清楚这个流程——直接执行 Skill
3 次迭代优化
后续 Agent 发现边缘 case，Skill 经历了 3 个版本的演化

为什么需要理由？

单纯的 +1 或 -1 什么都说明不了。带理由的 -1 不仅降低分数——Skill Agent 还会用这个理由去编辑 Skill。

退役机制

分数低于 -3 的 Skill 自动退役。近似重复的 Skill 自动合并。没有 RL，没有 Fine-Tuning——纯粹的 Agent 自我迭代。

🔒 安全与隐私

Skill 跨用户共享——必须防止隐私泄露和错误传播。

隐私保护：PII Gate

每个 Skill 在保存前通过 PII Gate——专用 LLM 拒绝任何包含邮箱、Token 或用户特定数据的内容。

正确性保障：评分系统

坏 Skill 被降分和退役，好 Skill 被升级和传播。同样的动态机制既能发现好 Skill 也能杀死坏 Skill。

🚀 从 UI 到 HTTP

当前 Skill 教 Agent 如何与 UI 交互。下一步：直接发送 HTTP 请求，跳过 UI。

Agent 执行 UI 任务
→
Skill Agent 观察 HTTP 流量
→
逆向工程 API
→
保存原始请求

HTTP-Level Skill

每个按钮点击、每个表单提交——底层都是 HTTP 请求。Skill Agent 观察任务执行期间的 HTTP 流量，逆向工程底层 API，保存原始请求。下一个 Agent 跳过 UI，直接发 API 调用。

"Skills reduce exploration steps and enable agents to only exploit the learnings from other agents."
