🔎 模型逐一分析

从全托管 Cloud 到各家 Frontier LLM——每个模型的优劣和适用场景。

冠军 Browser Use Cloud (bu-ultra)

78.0%

不仅准确率最高，而且速度最快——约 14 tasks/hour。每步虽然比原始 Frontier LLM 调用慢，但 bu-ultra 用更少的步数完成任务，所以总 Wall-Clock Time 更短。

这不只是一个更好的模型——而是一个目的构建的 Agent，集成了 Stealth 浏览器基础设施、CAPTCHA 解决、持久文件系统和优化的 Tool Orchestration。16 个百分点的领先来自全栈优化。

Verdict: 最佳性能、最高吞吐量、零配置。直接用这个。

ChatBrowserUse-2 (OSS + Cloud LLM)

63.3%

专为浏览器自动化优化的 BU 自研模型，运行在开源库上。超越所有独立 Frontier 模型，同时更快、更便宜。

Verdict: 需要自定义 Tool 或自托管时的最佳选择。

Claude (Opus 62.0% / Sonnet 59.0%)

62.0% / 59.0%

Anthropic 模型是最强的独立 Frontier 选项。Claude-opus-4-6 在所有非 BU 模型中排第一。当 Agent 需要执行自定义 JavaScript 或提取复杂结构化数据时，Claude 无可匹敌。Sonnet 以约一半的成本接近 Opus 水平。

Verdict: 最强独立 Frontier 模型。工作流依赖自定义代码执行时首选。

Gemini (3-1-pro 59.3% / 2.5-flash 35.2%)

59.3% / 35.2%

Gemini-3-1-pro 与 Claude Sonnet 不相上下——强视觉、低延迟、超大上下文窗口可以无压力处理巨大 DOM。Flash 便宜但准确率严重下降。

Verdict: Pro 是 Claude 的强力替代。Flash 仅适合低风险场景。

OpenAI (GPT-5 52.4% / GPT-5-mini 37.0%)

52.4% / 37.0%

GPT-5 是 Benchmark 上最慢的模型——约 6 tasks/hour。GPT-5-mini 的 37% 没能弥补速度差距。近期 OpenAI 模型在浏览器自动化任务上没有跟上 Claude 和 Gemini。

Verdict: 落后于竞争对手。改用 Claude 或 Gemini。

🎯 选型建议

四种场景、四个推荐——根据需求直接选择。

要最好的 Agent？

用 Browser Use Cloud (bu-ultra)。78% 准确率、最快吞吐量、零配置。

需要自定义 Tool 或自托管？

用开源库 + ChatBrowserUse-2。63.3%，仍然超越所有 Frontier 模型。

想用独立 Frontier LLM？

用 claude-opus-4-6 (62%) 或 gemini-3-1-pro (59.3%)。

预算有限？

用 claude-sonnet-4-6 (59%)——接近 Opus 准确率，成本更低。
