🎯 Prompt Injection 是什么

当不可信的内容变成了指令 — 在非 AI 聊天机器人中，注入意味着模型说错话；在浏览器 Agent 中，注入意味着模型做错事。

"A Prompt Injection Vulnerability occurs when user prompts alter the LLM's behavior or output in unintended ways. These inputs can affect the model even if they are imperceptible to humans."
— OWASP

"Every webpage an agent visits is a potential vector for attack."
— Anthropic

不可信内容的形式多种多样 — 从白底白字的隐藏文本，到 Base64 编码在 QR Code 图片中的 prompt injection。关键在于：这些内容不需要对人类可见，只要能被模型解析就够了。

传统 Chatbot Injection

模型说错话

泄露 system prompt

影响范围有限

浏览器 Agent Injection

模型做错事

填写表单、下载文件、导航到恶意 URL

可能窃取敏感数据并外泄

🔥 为什么浏览器放大了风险

浏览器使用从两个维度放大了 prompt injection 的风险：攻击面巨大，而且 Agent 能做的事情正好是攻击者想要的。

攻击面 (Attack Surface)
每个网页、广告、嵌入文档、脚本
Agent 能力 (Capabilities)
填写表单、下载、导航、触发 Webhook
暴露的敏感数据
Cookies、Auth Sessions、API Tokens

当消费者将 AI 浏览器作为日常驱动时，它会吸收所有敏感信息 — cookies、认证 session 等。一旦 prompt injection 攻击成功，所有这些信息都可能被暴露。

💀 真实攻击场景

从覆盖原始目标到数据外泄 — 只需要一次成功的攻击就能打通 "读取不可信内容" 到 "移动敏感数据" 的路径。

目标覆盖 (Goal Override)

说服 Agent 放弃原始指令，转而执行攻击者的任意任务

数据外泄 (Data Exfiltration)

利用 Agent 的访问权限窃取 private keys、session cookies、API tokens

Webhook 触发

让 Agent 触发外部 Webhook 或获取恶意资源，间接外泄数据

恶意导航

在用户不知情的情况下导航到恶意 URL

PromptArmor 案例：Google Antigravity

PromptArmor 发布了一个涉及 Google 的 agentic IDE "Antigravity" 的案例。他们在 "实现指南" 中嵌入了间接 prompt injection — 使用 1pt 字体（人眼几乎不可见但 AI 可读）— 指示 Agent 收集环境变量等敏感数据，然后通过编码为 URL 进行外泄。

访问包含注入的页面
→
Agent 解析恶意指令
→
收集敏感数据
→
编码为 URL 外泄

"Out of all the prompt injection attacks that may or may not work, it'd only take one successful attempt to create a path from 'read untrusted content' to 'move sensitive data.'"

"Despite new protections against prompt injections, no browser agent is immune from potential attacks. The success rate is low, but still non-zero and carries meaningful risk."

🛡️ 遏制策略 (Containment)

你无法修补整个互联网。可扩展的缓解措施是遏制：隔离浏览器、约束它能触及的范围、让失败可存活。

❌ 无隔离

零日漏洞执行时，AI 浏览器被完全攻陷

敏感数据（.env、SSH keys）暴露给攻击者

组织级别的数据泄露

✅ VM 隔离 (Browserbase)

即使零日漏洞被执行，损害被控制在专为浏览 session 生成的虚拟机中

虚拟机通常没有组织级别的敏感信息访问权

失败可存活，爆炸半径最小

恶意内容触发
→
攻击在 VM 内执行
→
损害被控制在隔离 VM 中
