🎯 设计哲学：控制 + 灵活性

传统自动化框架精确但脆弱；全 Agent 方案灵活但不可预测。Stagehand 提供两者的最佳组合。

Playwright / Selenium
精确但脆弱
←
Stagehand
精确 + 灵活
→
OpenAI Operator
灵活但不可预测

传统自动化的痛点

Playwright、Puppeteer、Selenium 在执行显式命令时很棒

但 UI 稍有变化就可能导致整个脚本崩溃

一个小的 UI 调整 = 手忙脚乱地修复脆弱代码

全 Agent 的痛点

OpenAI Operator 等承诺从 prompt 完成全部自动化

但开发者失去了对交互细节的控制

不可预测的结果 = 不适合生产环境

🧩 核心原语 (Primitives)

三个原子级原语 + 一个动态 Agent — 从构建块到高层编排的完整能力栈。

👆

act()

精确的一对一浏览器操作 — "点击这个按钮"、"输入这段文字"

不再递归循环

📤

extract()

结构化数据提取 — 配合 Zod schema 返回类型安全的数据

Schema 驱动

👁️

observe()

观察页面状态 — 返回可用操作列表，Gemini 在此表现最佳

状态感知

// 原子操作：精确控制 await page.act("click on the contributors selection"); const { title } = await page.extract({ instruction: "the top contributor's username", schema: z.object({ title: z.string(), }), });

agent() — 动态 Agent

处理复杂的多步工作流，将高级指令分解为浏览器命令序列。agent() 缓存预览步骤以减少 LLM 调用并优化性能 — 仅在缓存的操作失败时才发起新调用。

// 高级编排：动态 Agent const { message, actions } = await stagehand.agent.execute( "Extract the top contributor's username" );

⚖️ 三种自动化方案对比

同一个任务（填写表单 + 提取 Lead 数据）在三种方案下的表现。

控制精度
Playwright：显式代码控制每个元素
Stagehand：原语 + Agent 混合控制
Operator：自然语言，低控制
UI 变化韧性
Playwright：任何变化都可能崩溃
Stagehand：多维 Self-Healing
Operator：自适应但不可预测

Playwright

写显式代码导航到表单、识别每个字段、输入数据、提交

UI 变化 = 脚本崩溃

Stagehand

用 act、extract、observe 发出精确命令 + agent() 做高级编排

精确 + 韧性

OpenAI Operator

自然语言指令："填写表单并提取 Lead 信息"

可能有效但不可控

🔬 构建中的关键发现

从 Raw DOM 到 Accessibility Tree，从单一 LLM 到最佳选型 — Stagehand 团队在构建过程中的三大发现。

从 Raw DOM 到 Chrome Accessibility Tree
最初依赖解析原始 DOM，后来发现 Chrome Accessibility Tree 提供了更干净、更可靠的页面视图，过滤掉了不必要的噪声。从可选标志变成新版本的默认行为。
理解 LLM 行为差异
Claude 擅长高级推理（适合动态决策）；GPT-4o 适合执行具体浏览器操作；Gemini 在结构化输出上挣扎但在 observe() 上表现出色。
多维 Self-Healing
如果单个元素变化，可以重新检查页面找到替代。但如果按钮完全消失呢？Stagehand 的多维 Self-Healing 让完整 Agent 介入，重新评估整体目标并使用当前上下文决定如何完成任务。

LLM 最佳选型

Claude
高级推理、动态决策
GPT-4o
浏览器操作执行
Gemini
observe() 专长

Self-Healing 层级

Level 1：元素变化 → 重新检查页面找替代

Level 2：按钮消失 → 没有明确替代

Level 3：完整 Agent 介入 → 重新评估目标

最小化停机时间

🔗 MCP 集成

通过 Model Context Protocol (MCP) 将 Stagehand 的能力带给任何外部 LLM — 与 Claude 结合提供比 OpenAI Operator 更可控可靠的替代方案。

外部 LLM (Claude)
→
Stagehand MCP Server
→
结构化浏览器操作序列

MCP 如何工作

当你给一个有 Stagehand MCP 访问权限的 Agent 发出指令时，它将自然语言 prompt 翻译成结构化的、可复现的浏览器操作序列。这等同于一个更可控、更可靠的 OpenAI Operator 替代方案。

Browserbase 是开源 MCP 社区的先驱 — 2024 年 11 月首次发布 MCP server。

Claude + Stagehand MCP

自然语言 → 结构化操作序列

可复现、可调试、可控

生产级可靠性

OpenAI Operator

自然语言 → 不透明操作

黑盒行为、难以调试

不可预测

未来愿景：Mini-Agent 生态系统

想象一个 mini-agent 生态系统 — 每个 agent 专精于自己的领域（表单填充、图像识别、数据提取等），但协同完成复杂任务。这种微服务式的方法随着 MCP 的势头正在成为现实。

或者，我们可能达到一个单一的高度 agentic AI 无需辅助就能执行所有操作的状态。无论未来如何，Stagehand 将随之进化。
