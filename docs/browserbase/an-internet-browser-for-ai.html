🌐 互联网现状与 Bot 流量

30 年来，浏览器一直是人类与软件交互的默认方式。但如果大多数网站访问者不是人类，而是其他计算机呢？

为什么 Bot 需要浏览器？

互联网充满了信息，但大多数网站没有公开 API。Bot 必须像人类一样消费数据：导航网站、渲染页面、解析内容。LLM（如 GPT-4）的训练需要从互联网持续爬取新鲜数据。而新型 Web Agent 将代替用户完成任务——想象你的 AI 助手在 United.com 上为你改签航班。

🕷️ 爬虫为什么这么难

Web Scraping 的美在于朴素方法的简单和健壮方案的深度。一个简单的 curl 命令背后隐藏着五大挑战。

1. JavaScript 渲染

现代网站不会在首次请求中加载所有内容。页面脚本需要浏览器环境来 "hydrate" 数据。

2. 页面交互

数据可能不在公开 URL 上，需要点击、输入等页面交互才能到达目标位置。

3. 反爬检测

网站通过 CAPTCHA 和交互检测来阻止爬虫。绕过这些检查需要精确模拟浏览器行为。

4. 数据解析

现代前端框架产生的 DOM 结构不可预测，CSS 类名每次编译都会变化。

5. 不可靠性

整个流程是脆弱的——结构变化会立即破坏一切，任何步骤失序都会导致整个流程停滞。

"Web Scraping 的美在于朴素方法的简单性和健壮方案的深度。"

🤖 Headless Browser 的局限

Puppeteer 和 Playwright 是最流行的 Headless Browser 方案，但它们在 2023 年依然存在严重的工程问题。

❌ 现有方案的痛点

  • Puppeteer: 282MB 依赖体积
  • 超过 AWS Lambda 250MB 限制
  • CSS Selector 脆弱，无类型检查
  • 用 "等待网络空闲" 判断加载完成
  • Emoji 需要额外安装

✅ 理想方案的特征

  • 轻量级、云原生部署
  • 快速冷启动
  • 智能页面解析（AI 驱动）
  • 可靠的状态检测
  • 开箱即用的完整功能

📊 市场格局与竞争分析

相比向量数据库，浏览器自动化在 VC 领域的投资严重不足。大多数现有公司是自筹资金或融资不到 $5M。

Browser Automation

Browserless — 市场中最接近 incumbent 的玩家，良好的渗透率和品牌认知。
Browse.ai — VC 支持，偏消费者/低代码方向。
Induced.ai — $2.3M Seed，聚焦企业 RPA。

Scraping APIs

ScrapingBee / WebScrapingAPI / ScraperAPI — 给 URL 返回非结构化数据，通常捆绑 CAPTCHA bypass 和代理服务。产品同质化严重。

Info Retrieval

Metaphor Systems / SerpAPI — 面向专业信息搜索和检索，而非通用浏览器自动化。

🎯 分发策略与风险

"创业公司和 incumbent 之间的战斗，取决于创业公司能否在 incumbent 创新之前获得分发。" — Alex Rampell

最佳产品
产品必须卓越。在等候名单上放一个漂亮着陆页，不会创造根本性变化。
开源社区
免费提供优秀软件，然后说服用户尝试付费产品。开源是强大的分发杠杆。
可信品牌
在开发者社区建立品牌几乎和产品本身一样重要。口碑是开发者工具最强的获客渠道。
开发者教育
优秀的文档和多语言 SDK。"你看过这家公司的文档吗？" 是最高赞美。
企业 Inbound
Bottom-up GTM 建立口碑，解锁企业客户。80% 收入来自 top 20% 客户。

关键风险与缓解策略

Build vs Buy 如果功能足够重要且复杂，客户自建是疯狂的。
LLM 推理成本 推理成本将随时间下降。AI 功能应为 opt-in。
Commodity 化 创新定价模型，按吞吐量而非 session 收费。
大厂竞争 LLM 无法内置浏览器（独立技术）。长尾 SMB 网站仍需浏览器自动化。
合法性 2022 年美国第九巡回法院裁定 Web Scraping 合法。
