🧠 核心问题：失忆的天才

浏览器 Agent 的真正瓶颈不是推理能力，而是记忆 — 一种人类和 Agent 都能读懂和信任的记忆形式。

"The real bottleneck for browser agents in production is memory, in a form humans and agents can both read and trust. Reasoning has stopped being the constraint."

当你把一个浏览器 Agent 部署到生产环境，第一次运行是令人兴奋的 — 它会探索页面、理解结构、最终完成任务。但第二次运行看起来几乎一模一样。到了第 100 次运行时，你已经为相同的探索支付了 100 次费用，成本曲线是一条直线上升。

❌ 传统 Agent 模式

每次运行都从零开始探索

推理成果随 session 关闭蒸发

成本线性增长，无学习曲线

没有可交付的知识产物

✅ Autobrowse 模式

首次运行学习，后续运行复用

知识固化为 Markdown Skill 文件

成本随迭代收敛急剧下降

产出可读、可编辑、可版本化的工件

真实网站充满混乱：不同 User Agent 的渲染差异、JavaScript 门控内容、未文档化的 JSON endpoint、验证码、以及可能在某个周二突然改版的页面流程。通用 Agent 循环在当下能灵活应对这些，但一旦 session 关闭，所有推理都消失了。

🔧 Autobrowse 是什么

一个用 AI 改进 AI 的工作流 — 让 Agent 在真实任务中迭代，直到找到可靠路径，然后将其固化为可复用的 Skill。

Autobrowse 类似于 Karpathy 的 autoresearch harness，但专注于更快更便宜地学习浏览器技能。第一次运行故意很贵 — 它是为后续所有运行买单的那一次。

核心理念

你给 Agent 一个真实任务（如 "在 OpenTable 上预订晚 7 点的餐厅"），它端到端执行任务、分析自己的 trace、迭代策略，直到工作流从 "碰运气" 变成 "可靠"。收敛后，它把最佳方案毕业为一个可复用的 Skill。

关键区别：产物即目标

每次 Autobrowse 运行都会产出一个持久的 Markdown 文件，任何未来的 Agent 都可以加载和执行。这不是副产品 — 这个 artifact 才是重点。

🔄 学习循环 (Learning Loop)

从 Objective 到 Graduate，一个结构化的收敛流程。

Objective
→
Run
→
Study
→
Strategy
→
Iterate
→
Converge
→
Graduate
1. Objective — 定义任务
给 Agent 一个在真实网站上的真实任务，如 "在 OpenTable 上预订晚餐"
2. Run & Study — 执行与反思
Agent 端到端执行任务，然后审查自己的 trace：哪里卡住了？哪里浪费了 token？
3. Strategy — 策略迭代
维护 strategy.md 文件作为草稿本，记录每次迭代的观察（什么有效、什么失败、下次尝试什么）
4. Converge — 收敛判定
连续迭代在成本和步骤数上不再有显著改善时，短路退出（通常 3-5 次迭代）
5. Graduate — 毕业输出
写出 SKILL.md 加辅助脚本到公共 Skills 仓库

📄 产出物：Skill 文件

不是 transcript，不是 embedding 向量，不是截图集 — 只是 Markdown。

产出是一个小型、可读的文件。如果 Agent 发现了一个未文档化的 JSON endpoint，那个 endpoint 就在文件里。如果某个表单提交前需要等待，那也在文件里。如果特定域名的辅助脚本值得保留（如 helpers/amazon.py），它会被检入到 Skill 旁边。

Skill 文件结构

Frontmatter（名称、描述、网站、分类、状态、推荐方法）+ 正文（Purpose、When to Use、Workflow 步骤、Site-Specific Gotchas）+ 可选的辅助脚本。

"Autobrowse pushes that idea one layer further: the agent writes its own skill, learned by actually doing the task."

手写的 Skills 和 Autobrowse 毕业的 Skills 是完全相同类型的工件。一旦 Skill 存在，Agent 加载和运行它时完全不关心它是人类还是另一个 Agent 写的。

📊 基准测试：Craigslist

从通用循环到毕业 Skill 的成本和时间对比。

传统 Claude Code 循环
$0.22 / 71s

绝对数字不如趋势重要。第一次运行的成本与通用 Agent 循环差不多。但毕业的 Skill 改变了后续每一次运行的单位经济学 — 一个数量级或更多的改善，因为它编码了 Agent 能找到的最短可靠路径。

🎯 适用场景与局限

Autobrowse 在特定问题形状上非常强大，但在另一种形状上是错误的工具。不用 Autobrowse 的纪律也是使用它的一部分。

✅ 适合 Autobrowse

隐藏/未文档化的 API（需要从网络流量中发现）

重度客户端渲染（内容需要交互才出现）

多步登录或向导流程

最短可靠路径不显而易见的 UI

有 token 节省机会的冗余循环

❌ 不适合 Autobrowse

确定性解析任务（静态 HTML 数据在标记中直接可见）

一个 167 行的静态目录花了 ~$24 四次迭代仍未完成

200 行确定性 Python + BeautifulSoup 亚秒完成

规则：先用 fetch 探测，干净返回就写解析器，否则才升级到 Autobrowse

"Autobrowse sits at the high-agency end of that spectrum, and like any high-agency tool, you reach for it once the cheaper, more deterministic options have given up."

联邦拨款门户案例

看起来需要爬 28 页的内容，Autobrowse 让 Agent 发现了一个未文档化的 JSON endpoint，返回所有当前拨款信息。28 页爬取坍缩为单次 browse fetch。这种模式反复出现：Agent 尝试人类不会尝试的东西，发现人类永远看不到的东西。

🔄 工作流革命

从 "信任 Agent 的输出" 到 "阅读 Agent 的剧本"。

今天，当一个 Agent 成功完成工作时，客户的工程团队得到一个 trace，也许一个 session 回放，也许一段自然语言推理。这些对实际拥有工作流的人来说都不可读。

📖

可读

工程师和 PM 都能读懂

🔧

可调试

可编辑、可 commit、可 review

📈

可复利

Skill 库随时间增长，Agent 越来越快越来越便宜

Skill 是一种客户交付物，具有 "交付" 这个词所暗示的全部分量。它是持久的、可调试的、人类可审计的、可拥有的。一个非工程师（技术 PM、技术 VP、了解其门户的拨款经理）也能读懂它，大致理解 Agent 在做什么，而无需接触任何代码。

复利效应同样重要。Agent 遇到的每个新站点都会产出一个持久的 Skill。库不断增长。Agent 在长尾重复性工作流上变得更便宜更快，因为它不再支付发现税。

🚀 未来方向

从更智能的停止标准到递归的 Autobrowse — Agent 改进自身改进能力。

Smarter Stopping — 更智能的收敛
让 Agent 不仅比较成本和步骤数，还比较 trace 的结构差异来判断收敛。保留随机变异发现更短路径的概率。
Better Priors — 更好的探索先验
确保 Agent 在启动完整浏览器 session 之前先用 fetch 和 search 原语探测。高级任务可检查浏览器 trace、网络事件和 CDP 日志。
Recursive Autobrowse — 递归自我改进
最令人兴奋的方向：用 Autobrowse 改进 Autobrowse 自身 — 更好的 prompt、更好的先验、更好的 Skill 模板。

"Even a perfect model still has to discover (on every new site) what a perfect model would already know if it had been there before. Without a place to put what the agent learns, every run is a fresh start."

关于浏览器 Agent 的主流叙事是：等底层模型变好就行了。Browserbase 不完全认同。即使是一个完美的模型，如果没有存放学习成果的地方，每次运行都是一个全新的开始。真正的瓶颈是记忆。
