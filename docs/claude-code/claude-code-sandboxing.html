🔑 审批疲劳问题

Claude Code 默认使用基于权限的模型：只读，在修改或运行任何命令前请求许可。少数安全命令（如 echo、cat）自动放行，但大多数操作仍需明确批准。

⚠️ 审批疲劳的危害

  • 不断点击"批准"拖慢开发周期
  • 用户可能不再仔细关注他们批准的内容
  • 反而使开发更不安全

✅ 沙盒的解决方案

沙盒创建预定义的边界，Claude 可以在其中更自由地工作，而不是为每个行动请求许可。内部使用中，沙盒安全地减少了 84% 的权限提示。

🏗️ 沙盒核心概念

沙盒方法建立在操作系统级功能之上，实现两个边界：

📁 文件系统隔离

确保 Claude 只能访问或修改特定目录。防止被提示注入的 Claude 修改敏感系统文件。

实现：允许对当前工作目录的读写，阻止对其外任何文件的修改。

🌐 网络隔离

确保 Claude 只能连接到批准的服务器。防止被提示注入的 Claude 泄露敏感信息或下载恶意软件。

实现：仅通过连接到沙盒外代理服务器的 unix domain socket 允许互联网访问。

🔒 为什么两者都需要

没有网络隔离

被妥协的 Agent 可以外泄 SSH 密钥等敏感文件

没有文件系统隔离

被妥协的 Agent 可以轻松逃逸沙盒并获得网络访问

只有同时使用两种技术才能为 Claude Code 用户提供更安全、更快的 Agent 体验。

沙盒架构

🖥️ 沙盒内

Claude Code + Bash 工具。只能访问当前工作目录。网络通过 unix socket 代理。任何子进程/脚本也受同样限制。

🌍 沙盒外

代理服务器：强制执行域限制 + 处理新请求域的用户确认。支持自定义代理以强制执行任意传出流量规则。

基于 OS 级原语：Linux bubblewrap + MacOS seatbelt

💻 沙盒 Bash 工具

新的沙盒运行时（Beta 研究预览）让你精确定义 Agent 可以访问哪些目录和网络主机。

📂 文件系统隔离

允许对当前工作目录的读写访问。阻止对目录外任何文件的修改。不仅覆盖 Claude Code 的直接交互，还覆盖命令生成的任何脚本、程序或子进程。

🌐 网络隔离

仅通过连接到沙盒外代理服务器的 unix domain socket 允许互联网访问。代理强制执行进程可连接域的限制，处理新请求域的用户确认。

⚙️ OS 级别强制执行

基于 Linux bubblewrap 和 MacOS seatbelt。覆盖 Claude Code 的直接交互以及任何生成的子进程。

🔧 可配置

轻松选择允许或禁止特定文件路径或域。支持自定义代理以强制执行任意传出流量规则。

✅ 即使提示注入也安全

沙盒确保即使成功的提示注入也完全隔离，无法影响整体用户安全。被妥协的 Claude Code 无法窃取 SSH 密钥，也无法回拨到攻击者的服务器。

☁️ Claude Code on the Web

在云中隔离沙盒中运行 Claude Code。每次会话在隔离沙盒中执行，在其中安全地拥有对服务器的完全访问权限。

🔐 安全设计原则

敏感凭据（如 git 凭据或签名密钥）永远不会在沙盒内与 Claude Code 一起存在。即使沙盒中运行的代码被妥协，用户也不会受到进一步伤害。

🔄 自定义代理处理 Git 交互

使用自定义代理服务透明地处理所有 git 交互：

Step 1: 沙盒内认证
沙盒内的 git 客户端使用自定义构建的范围限定凭据认证到此服务。
Step 2: 代理验证
代理验证此凭据和 git 交互的内容（例如确保只推送到配置的分支）。
Step 3: 附加正确 token
代理附加正确的认证 token，然后将请求发送到 GitHub。

✅ 安全版本控制工作流

Git 集成通过安全代理路由命令，验证认证 token、分支名称和仓库目标——允许安全的版本控制工作流，同时防止未经授权的推送。
