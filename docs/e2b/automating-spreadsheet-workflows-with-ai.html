📊 产品背景与痛点

Manaflow 源于与 200+ 企业管理者的深度对话，发现中小企业深陷手动电子表格工作流之中。

❌ 传统痛点

手动、耗时、重复的电子表格操作；数据分析全靠人工；无法规模化扩展；人为错误频发

✅ Manaflow 方案

自然语言编程 AI Agent；Notion-like UI 零代码操作；Cron 定时执行；人机协同 checkpoint 审核

"全美有数百万白领工作者，每天打开电子表格，每列代表任务的一个步骤，每行代表任务的一个实例。"

⚙️ 产品架构与工作原理

Manasheet 作为核心界面，列代表工作流步骤，行代表任务实例，内部依赖图决定执行顺序。

自然语言定义任务
→

结果填充到表格

关键特性

自定义 Tools Dependency Graph Human Checkpoint Cron 调度

用户可以创建和调用自定义工具（Tools），AI Agent 通过 dependency graph 确定每列的执行顺序，并在关键步骤设置 checkpoint 供人工审核。

集成能力

Google 搜索、Stripe 发票处理、各类已认证平台 API，实现多样化业务操作的无缝自动化。

AI Agent 角色

管理者可编程 AI Agent 自动填充数据到 cells 并执行 Manasheet，支持 Cron 定时或按钮触发。

🛠️ 技术栈选型

TypeScript 全栈 + Postgres + PartyKit + E2B，统一用户交互与代码执行环境。

架构设计决策

每个 Manasheet 由 Postgres 表支撑，执行时生成 Durable Objects 在 E2B Sandbox 中运行代码。这种设计统一了用户端 code interpreter session 与每个 cell 的执行环境。

🔒 E2B 集成与选型过程

从浏览器端 Pyodide/StackBlitz 迁移到云端 E2B，解决依赖安装、CORS、计算密集等核心限制。

"我们发现 E2B 的启动时间比我们尝试过的所有方案都要快得多。"

初始方案：浏览器端执行
使用 Pyodide（Python）和 StackBlitz（JS/TS）在用户浏览器中运行代码
瓶颈出现
用户需要安装依赖、执行计算密集任务、定时运行、解决 CORS 问题
评估替代方案
考察 Fly.io Machines、Modal、Google Cloud Run、自建 Jupyter 集群
选择 E2B
启动速度最快 + @e2b/code-interpreter 包易用性极高 = "No-brainer"

其他方案的局限

Fly.io / Modal / Cloud Run 启动慢；自建 Jupyter 运维成本高

E2B 的优势

最快启动时间；code-interpreter SDK 即插即用；安全隔离的云端沙箱

🔮 未来愿景

从内部工具自动化到 AI Agent 驱动的企业运营平台。

短期：知识工作者赋能
让非技术用户无需编码即可自动化自己的任务
中期：运营管理革新
运营管理者从协调人力转变为指挥 AI Agent
长期：内部工具消亡
AI Agent 取代传统内部工具，在统一平台上端到端自动化业务流程
终极目标
成为 Foundation Model 之上的基础设施层，让企业无缝集成最先进的 AI 模型

💡 核心洞察总结

从 Manaflow 的案例中，我们可以提取出 AI Agent 自动化领域的关键启示。

自然语言即编程

非技术用户通过自然语言描述任务，消除编码门槛，实现"每个人都是自动化工程师"的愿景。

人机协同设计

Checkpoint 机制保证人类在关键节点的干预权，平衡自动化效率与控制需求。

云端沙箱化执行

E2B 提供安全隔离的代码执行环境，解决本地执行的安全风险和性能瓶颈。

SMB 市场机遇

中小企业对自动化的需求巨大但技术能力不足，AI Agent 可以弥合这一鸿沟。
