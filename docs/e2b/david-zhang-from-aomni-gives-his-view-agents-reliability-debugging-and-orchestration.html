🔍 Aomni：AI 商业情报 Agent

Aomni 是少数专注于商业智能的 AI Agent，通过爬取网络和处理非结构化数据，完成销售研究和客户规划。

核心价值

为销售代表节省每周 10+ 小时的客户调研和关系建设准备工作。重要的是，大多数 Aomni 用户并不在 AI 领域，完全不了解 Agent 技术。

⚖️ 通用性 vs 可靠性

David 指出 Agent 领域存在核心权衡：通用性越高，可靠性越低。企业客户需要 99.9% 的可靠性。

通用 Agent (如 AutoGPT)
可靠性 ~30%
垂直化 Agent
可靠性 ~70%
深度聚焦 Agent
可靠性 ~90%
企业级要求
99.9%

"更通用的 Agent 项目会更不可靠。你当然可以让一个通用 Agent 帮你策划婚礼或写代码，但代价是大量 token 消耗和糟糕的可靠性。"

通用 Agent 的问题

Token 消耗巨大；可靠性低；调试困难；不适合企业场景

David 的策略

限制 Agent 使用的工具数量；减少 Agent 需要做的决策数；聚焦特定 niche

🔧 Agent 调试与编排挑战

David 强调不要用新框架"重新发明轮子"，而应该在现有技术之上构建 Agent 特定的能力。

Inngest 用于编排

用于 Agent 的编排和调试，但无法实现从特定步骤重试 Agent 的功能

Token 监控平台

需要统一平台来监控 token 使用量和衡量 prompt 效果

Time-Travel Debugging

从特定步骤恢复 Agent 执行 —— SW 工程中的常见概念，Agent 领域尚缺

"Time-travel debugging（时间旅行调试）是软件工程中非常常见的概念。只是时间问题，就会有人在现有引擎之上加上 Agent 逻辑。"

Agent 运行可视化

Aomni 的内部工具显示所有 Agent 运行记录（成功/失败），以及每次运行中 Agent 执行的每一步，包括失败原因。这种可视化对于诊断问题至关重要。

💬 用户沟通策略

Aomni 的 Agent 相对可靠，错误消息简单直接。关键是收集人类反馈和构建用例库。

用例仓库

💡 核心洞察

从 David Zhang 的视角总结 Agent 可靠性和调试的关键认知。

聚焦胜过通用

未来 1-2 年内的新 Agent 将高度专注于特定垂直领域

限制决策数量

减少 Agent 的工具和决策点，每减少一步，可靠性显著提升

不要重造轮子

在 Inngest/Sentry 等成熟工具上构建，而非从零开始

用户不关心技术

大多数 Agent 终端用户不在 AI 领域，他们只看到"软件"该有的标准
