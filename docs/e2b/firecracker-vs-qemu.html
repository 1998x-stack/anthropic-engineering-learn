📚 虚拟化基础

VM

隔离环境，拥有独立 CPU、内存、存储和网络，运行独立 OS

VMM/Hypervisor

管理 VM 的软件层。Type 1 直接运行于硬件，Type 2 运行于 OS 之上

KVM

Linux 内置 Hypervisor，将 Linux Kernel 变为 Type 1 Hypervisor，提供近原生性能

🔧 QEMU 全面解析

Quick EMUlator——虚拟化领域的瑞士军刀，200 万行 C 代码支持几乎所有平台。

QEMU 优势

广泛平台支持（包括古老的 s390x）；纯仿真 + KVM 加速双模式；庞大生态系统和工具链；MicroVM 模式可接近 Firecracker

QEMU 代价

~200 万行 C 代码 = 巨大攻击面；大量历史 CVE；启动慢、内存开销高；manpage 47+ 页，学习曲线陡峭

🔥 Firecracker 深度分析

AWS 为 Serverless 场景打造的轻量 VMM——Rust 编写，驱动 Lambda 每月数十万亿次函数调用。

Firecracker 局限

设备支持有限（无软驱等遗留设备），无 GPU 支持（PCIe 开发已暂停），生态系统尚小

Firecracker 采用者

AWS Lambda/Fargate、E2B（AI 代码沙箱）、Fly.io（边缘计算）

🎯 选型建议

速度+安全+效率选 Firecracker，灵活性+广泛硬件支持+全系统仿真选 QEMU。

选 QEMU

需要遗留硬件支持、完整系统仿真、跨架构开发环境、已有 QEMU 生态集成

选 Firecracker

Serverless 计算、边缘计算、AI 代码沙箱、短生命周期工作负载、安全优先场景

"E2B 使用 Firecracker 在云端安全运行 AI 生成的代码，Fly.io 使用它在边缘运行轻量的容器式 VM。"
