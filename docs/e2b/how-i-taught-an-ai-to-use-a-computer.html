🚀 项目概述

完全开源的 LLM 驱动 computer use agent，接受自然语言指令自动操控计算机完成任务。

工作原理

Agent 持续截取屏幕截图，交给 Meta Llama 3.3 LLM 判断下一步操作（点击、打字等），直到任务完成。整个过程在 E2B 提供的安全隔离 Ubuntu 环境中运行。

🔥 五大技术挑战

从安全隔离到视觉推理，构建 computer use agent 需要克服的关键障碍。

🔒 安全性

在安全隔离环境中运行 agent，防止对真实系统造成破坏。使用 E2B 的 Firecracker microVM 解决。

🖱️ 精确点击

使 AI 能精确点击 UI 元素。使用 OS-Atlas (grounded VLM) 实现坐标输出。

🧠 推理决策

基于视觉信息决定下一步操作。Llama 3.2 90B Vision + Llama 3.3 70B 协作完成。

🚀 模型部署

托管小众开源模型的成本挑战。Serverless 适合主流模型，OS-Atlas 使用 HuggingFace Space。

📺 屏幕流式传输

低延迟展示沙箱屏幕。使用 ffmpeg x11grab + HTTP 流实现。

💭 Agent 框架反思

作者认为大多数 agent 框架对实际开发帮助有限。

"Agent frameworks are mostly useless" — 框架主要抽象 LLM 输入格式化、agent prompt 和运行循环，但大多数 provider 已在标准化 OpenAI tool-use 格式，system prompt 又是需要频繁调整的部分。

不用框架的理由

Tool-use 在不同 provider 间有微妙差异；框架文档不透明；System prompt 需频繁调整不应被抽象

替代方案

直接使用 provider API；自定义简单的 run loop；精细控制每个组件的行为

🔮 未来展望

API 优先、安全认证是 computer use agent 的关键未来方向。

Standard APIs
文件系统 API、Office API、Gmail REST API 等结构化接口
Code Execution
运行 Bash/Python 脚本启动应用或解析文件
Accessibility APIs
操作系统的无障碍 API 直接与 GUI 层次交互
DOM
通过 DOM 以半结构化方式与网页交互
MCP
Model Context Protocol — 专为 agent 设计的 context 与 action 接口

认证与权限管理

安全方式应采用作用域权限（scoped permissions），类似 OAuth/iOS 权限模型。需要开发：agent 的 scoped API 访问（如只读邮件）、敏感信息脱敏（如信用卡号不经过 LLM）。
