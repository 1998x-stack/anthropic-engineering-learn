🔍 代码执行挑战

当用户搜索股价或选举数据时，背后需要运行代码生成图表——在服务数百万用户时，这带来了真实的基础设施挑战。

安全隔离

不能让 LLM 在应用运行的同一环境中执行代码和使用工具

性能要求

用户注意力短暂，LLM 生成 token 已经很慢，其他一切必须极致优化

扩展性

同时启动数千个编码运行时不是小事，可能导致性能退化

✅ 选择 E2B 的原因

Firecracker 隔离安全、Python/JS 双 SDK、有状态的高度可定制代码执行——满足 Perplexity 规模需求。

E2B 关键优势

安全隔离
Firecracker microVM
SDK 易用性
Python + JS 双 SDK
有状态执行

150-170ms

"我们现在每月运行数百万个 E2B Sandbox。" -- Denis Yarats, Perplexity CTO

⚙️ 实施过程

2024 年 7 月开始集成，8 月首版上线——E2B 工程团队深度参与功能协作。

需求确立
决定使用有状态代码执行（而非无状态），匹配搜索场景需求
基础设施扩容
提前规划负载，为企业级使用量扩展 E2B 基础设施
功能协作
共同开发沙箱功能（如 matplotlib 数据提取），匹配 Perplexity UX 细节

"我们在一周内就让 E2B 跑起来了。" -- Denis Yarats, Perplexity CTO

🚀 成果与展望

代码执行层上线后，编码相关查询的参与度显著增长，交互式图表让用户眼前一亮。

上线前

搜索结果仅文本，无法实时展示数据图表，编码类查询体验受限

上线后

交互式图表嵌入搜索结果，用户可自定义图表，前端可交互操作
