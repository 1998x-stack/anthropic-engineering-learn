📚 OverlayFS 与 Copy-on-Write 原理

OverlayFS 将只读层（lower）和可写层（upper）合并为统一视图，修改时才复制文件到上层。

Lower Dir (只读)
+
Upper Dir (可写/空)
=
Merged Dir (统一视图)

❌ 每实例复制 RootFS

1000 个实例 x 数百 MB = 严重的磁盘空间问题。每次启动都需要完整复制。

✅ OverlayFS 共享

1 份只读 RootFS + N 个空的 Overlay 层。仅修改的文件被复制，初始 0 字节开销。

"当你想修改 lower 目录中的文件时，OverlayFS 使用 Copy-on-Write：将文件复制到 upper 目录并在副本上修改，原始文件不受影响。"

📦 创建只读 RootFS

将根文件系统打包为 Squashfs 压缩只读镜像，添加 overlay-init 脚本作为入口。

挂载原始 rootfs
mount rootfs.ext4 到 /tmp/rootfs 进行修改
添加 overlay-init
在 /sbin/overlay-init 放置初始化脚本，设置 overlay 并调用真正的 init
打包 Squashfs
mksquashfs /tmp/rootfs rootfs.ext4 -noappend (压缩只读)

overlay-init 核心逻辑

pivot() { mount -o noatime,lowerdir=/,\ upperdir=${rw_root},workdir=${work_dir} \ -t overlay "overlayfs:${rw_root}" /mnt pivot_root /mnt /mnt/rom } # 然后调用 exec /sbin/init

💾 创建可写 Overlay

每个实例一个稀疏 ext4 文件——声明 5GB 但实际占用 0 字节，按需增长。

# 创建 5GB 稀疏文件（实际 0 字节） dd if=/dev/zero of=overlay.ext4 bs=1M count=5120 # 格式化为 ext4 mkfs.ext4 overlay.ext4 # ls -lh → 5.0G (声明大小) # du -h → 0 (实际占用)

1份RootFS + 稀疏文件

⚙️ Firecracker 配置

配置两个 drive（只读 rootfs + 可写 overlay），在内核参数中指定 overlay-init。

Drive 1: RootFS

"drive_id": "rootfs" "is_root_device": true "is_read_only": true

Drive 2: Overlay

"drive_id": "overlayfs" "is_root_device": false "is_read_only": false

内核参数

init=/sbin/overlay-init overlay_root=vdb # vdb = 第二个 drive (overlay.ext4) # 不需要持久存储时: overlay_root=ram
