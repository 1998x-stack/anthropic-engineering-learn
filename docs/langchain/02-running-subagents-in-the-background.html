🔮 传统子智能体的瓶颈与局限

子智能体（Subagent）是主管智能体将特定范围的工作委托给的从属智能体。这种模式本身是可行的，但随着我们赋予智能体越来越长、越来越复杂的任务，内联式子智能体（inline subagents）开始暴露出严重的架构缺陷。

子智能体是主管智能体将范围明确的工作委托给的独立智能体。这种委托模式在简单场景中运行良好。然而，当任务变得更加复杂和耗时后，内联子智能体的根本架构问题开始显现——它将任务的委派与结果的等待紧密耦合在一起，导致整个系统陷入阻塞。

问题一：子智能体工作时的死锁

由于工具调用（tool calling）在智能体内部的工作机制，主管智能体在收到子智能体的响应之前，无法进行任何其他推理或操作。这是因为 LLM 的工具调用遵循严格的请求-响应模式：主管发出一次工具调用后，必须等待该调用返回结果才能继续生成下一步推理。如果某个子智能体需要运行一个小时，那么你就必须等待整整一个小时才能再次与主管智能体交互。这种阻塞不仅浪费了主管智能体的算力，更严重破坏了用户体验——尤其是在需要人机交互（Human-in-the-Loop）的场景中。

问题二：新信息难以协调

在内联子智能体的架构下，信息协调面临多重困境：

  • 用户无法在主管智能体被阻塞时与其对话——这意味着用户无法提供新的指令、纠正方向或补充上下文
  • 多个子智能体无法并发运行——结果之间无法交叉参考，每个子任务必须严格串行执行，极大地延长了总体耗时
  • 子智能体的执行是全有或全无的——没有中间状态更新，主管智能体无法根据部分结果做出实时调整

归根结底，这些问题的本质是任务委派与结果等待的紧耦合。传统的同步工具调用模型假设工具会快速返回，但子智能体的执行时间是不可预测的。这种架构上的不匹配使得扩展到复杂的多智能体工作流变得不切实际。

💡 异步子智能体：全新的解决方案

异步子智能体的核心思想很简单：让子智能体在后台运行，而非串行阻塞。主管智能体启动一个任务后立即获得任务 ID，然后可以继续处理其他工作。这是一种"发射并引导"（fire-and-steer）而非"发射后遗忘"（fire-and-forget）的模式。

理解异步子智能体最简单的方式：它们是在后台运行的子智能体，而非顺序执行的。主管智能体启动一个任务，立即获得一个任务 ID 作为句柄，然后可以自由地继续推理、启动更多子任务或与用户交互。这是一种"发射并引导"的模式——主管智能体保持对任务的监控和控制权，同时不会被任何单个子任务阻塞。

工作原理——任务管理工具集

异步子智能体通过五个核心工具实现生命周期管理，这些工具共同构成了一个完整的异步任务编排接口：

工具名称功能说明
start_async_task在远程智能体上启动一个任务，立即返回任务 ID。主管智能体无需等待执行完成即可继续后续操作。
check_async_task轮询任务状态，并在任务完成后获取结果。支持查询中间状态（running / completed / failed）。
update_async_task向正在运行的任务发送后续指令——例如追加新的上下文信息、调整任务优先级或修改搜索方向。
cancel_async_task取消正在运行的任务。适用于任务已过时或发现更好路径时的场景。
list_async_tasks列出所有已跟踪的任务及其当前状态，为主管智能体提供全局态势感知。

基于 Agent Protocol 构建

异步子智能体基于 Agent Protocol 构建——这是一个与框架无关的 API 规范，用于管理远程智能体。它定义了创建线程（thread）、启动运行（run）、轮询状态、发送更新以及管理长期记忆（memory）的标准端点。Agent Protocol 的框架无关性意味着你可以混合使用不同框架构建的子智能体——例如用 LangGraph 构建一个研究智能体，用 CrewAI 构建另一个编码智能体，它们都可以通过统一的 Agent Protocol 接口与主管智能体协作。

灵活的部署选择：你可以使用 LangSmith 部署获得全托管体验（包括自动扩缩容、日志追踪和监控），也可以将其部署在自己的基础设施上——Docker 容器、虚拟机或 Kubernetes 集群均可。

使用示例（TypeScript）

// agents.ts
import { createAgent } from "langchain";
import { createDeepAgent } from "deepagents";

export const researcher = createAgent({
  model: "anthropic:claude-sonnet-4-6",
  instructions: "Perform deep research on the given topic.",
  tools: [searchWeb, readUrl],
});

export const agent = createDeepAgent({
  model: "anthropic:claude-opus-4-6",
  subagents: [{
    name: "researcher",
    description: "Performs deep research on a topic.",
    graphId: "researcher",
  }],
});

上面的代码展示了异步子智能体的核心设置：createAgent 定义了一个独立的研究智能体，而 createDeepAgent 创建的主管智能体通过 graphId 引用子智能体。当主管智能体需要研究某个主题时，它会调用 start_async_task 来异步启动研究任务。

自托管部署

export const agent = createDeepAgent({
  model: "anthropic:claude-opus-4-6",
  subagents: [{
    name: "researcher",
    description: "Performs deep research on a topic.",
    graphId: "researcher",
    url: "http://localhost:2024", // points to your self-hosted server
  }],
});

自托管服务器实现 Agent Protocol 端点，可以运行在任何地方——Docker 容器、虚拟机或 Kubernetes 集群均可。自托管方案适合对数据隐私有严格要求的企业场景，所有智能体通信都在你自己的网络内部完成。需要注意的是，自托管时你需要自行管理扩缩容、健康检查和日志收集。
