📖 CUDA IPC Handle Cache

Scheduler 反复打开相同的 IPC handle，产生不必要的 PyTorch wrapper 开销。修复：一个 Python dict 做缓存。

❌ 修复前

每次迭代重新打开 IPC handle，产生 StorageImpl、CUDA event recording、GIL 交互等开销。

✅ 修复后

Pool handle 永不重新分配，cache 无需 invalidation。读取无锁，写入极少。一个 dict 解决一切。

为什么 Decode 也变快了？

SGLang scheduler 是单线程的 -- 在 process_input_requests 上花的时间越少，就有越多时间 dispatch 下一个 batch。Slowness anywhere means slowness everywhere。
