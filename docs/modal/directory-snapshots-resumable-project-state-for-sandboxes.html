📸 传统快照的局限

全文件系统快照将 OS、依赖、应用代码、生成产物捆绑为一个原子单元，无法独立管理。

❌ 全量快照

安全补丁或 runtime 升级 = 废弃旧快照 + 从头重建环境，浪费分钟级延迟。

✅ Directory Snapshots

只快照你关心的目录（如 /project），base image 独立更新，互不干扰。

⚡ 核心能力

分离生命周期、预热池化、优化预加载 -- 三大关键场景。
🔁

独立生命周期

系统依赖和应用状态独立演进，补丁不影响项目代码。

🔥

预热池化

先创建通用 warm 池，分配时再挂载项目特定的 Directory Snapshot。

📦

优先预加载

Snapshot 内容优先于 base image 加载，项目文件最先可用。

🧩 Modal 快照生态

三种互补的快照类型覆盖所有场景。
类型粒度保留期适用场景
Filesystem Snapshot完整文件系统永久环境备份、自定义 base image
Directory Snapshot指定目录30 天应用状态、warm pool
Memory Snapshot内存状态按需运行中进程的极速恢复
