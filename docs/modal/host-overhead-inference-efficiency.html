⚠️ Host Overhead：GPU 空转

AI 推理的首要指令：永远不要阻塞 GPU。每纳秒空转 = 浪费百万次浮点运算。

航海者比喻

CPU 是航海士：决定做什么工作。GPU 是船：执行实际工作。好的船长不会让船停下来等航海士思考航向。

50% host overhead
GPU 成本 2x
25% host overhead
GPU 成本 1.33x
最优目标
接近 0%

🔄 避免不必要的 CPU-GPU 同步

不必要的数据传输是 host overhead 的常见原因。

❌ CPU 构建 → 传输 GPU

Position embeddings 在 CPU 上构建再传到 GPU。同步数据传输阻塞 GPU。

✅ 直接在 GPU 构建

在 decode 的特殊情况下，tensor 结构简单，可直接在 GPU 上构建，避免同步传输。

🚀 Kernel Launch 开销

每次 kernel launch ~微秒级，但小模型小输入时数百次 launch 会严重侵蚀毫秒级预算。

B200 的数学

B200 GPU 可在 1ms 内从 HBM 流式传输 8GB 模型。一个 8B 参数模型有数百个 kernel。数百微秒的 launch 开销会显著侵蚀 1ms 的预算。

🔧 修复策略

Modal 团队在开源推理引擎 SGLang 上的实战修复。
🔗

Kernel Fusion

Torch compiler 将 ~20 个 kernel 合并为 3 个，减少 30µs overhead，E2E 延迟降 20%。

📈

CUDA Graphs

将 DAG 形式的多个 kernel launch 合并为单次启动。

🧱

构建替代传输

在目标设备上直接构建 tensor，避免跨设备同步。
