✨ 原则 1：避免不可预测的魔法

Modal 应该让人感觉有点 magical，但 "魔法" 行为是双刃剑。

❌ Automounting (旧)

自动发现并包含本地包，但不可预测：可能包含多余包，用户误以为所有文件都会自动包含。

✅ 显式声明 (1.0)

明确指定哪些本地文件和包被包含在容器中。更冗长但更可预测、更易调试。

🧩 原则 2：分离核心与扩展概念

@app.function 装饰器不应该承载所有配置。新的 @modal.concurrent 独立表达并发模式。

独立装饰器模式

将 concurrency 配置从 @app.function 中分离为 @modal.concurrent，允许添加特定于每个装饰器的配置选项。

🛤️ 原则 3：唯一规范路径

减少实现同一目标的冗余方法，简化开发者心智模型。

案例：本地文件 → 容器

之前有两种方式（Image setup 或 modal.Mount）。1.0 统一到 modal.Image 下管理容器文件系统的所有初始状态。

🔮 未来方向

多语言 SDK、Agent 时代的开发者体验。
🌐

多语言 SDK

JavaScript 和 Go SDK 已有进展，扩展 Modal 的语言覆盖。

🤖

Agent 工效学

探索人类工具 vs Agent 工具的区别，适配 AI 驱动的开发工作流。

📅

可预测发布

批量发布更新，开发者可以快速了解变更并控制升级节奏。
