🎯 为什么要 Fine-tune

与 Prompt Engineering 相比，Fine-tuning 在成本和效果上都有显著优势

Prompt Engineering

  • 长 Prompt 消耗大量 input tokens
  • 需要大模型才能实现好效果
  • 高延迟、高推理成本

Fine-tuning

  • 短 Prompt 即可达到同等质量
  • Fine-tuned Llama 7B vs GPT-3.5：50x 成本降低
  • 更低延迟、更低推理成本

典型应用场景

Structured Output (JSON/HTML) Style Adherence 风格适配 Domain-specific 领域指令 RAG + Fine-tuning 混合

📋 数据集准备

数据质量和格式是 Fine-tuning 成功的关键

A. 构建 Prompt
每个样本转为带指令的字符串 Prompt，推理时需使用相同的模板
B. 添加 Special Tokens
标记响应边界、分隔列表项、高亮关键部分（可选）
C. Tokenize
使用 AutoTokenizer 自动选择匹配的分词器，处理 padding 和 truncation

🧠 高级技术

LoRA、量化和分布式训练：让 Fine-tuning 更快更高效

LoRA / QLoRA

冻结原始权重，仅训练小型 "adapter" 矩阵。QLoRA 进一步用量化减少内存占用，可在普通硬件上微调超大模型。

分布式训练

DeepSpeed (ZeRO 优化) 和 FSDP 帮助跨多 GPU 并行计算。Modal 支持最多 8 GPU 分布式训练。
