📄 公司简介与使命

Reducto 将混乱的企业文档转化为结构化数据，每天处理数百万份 PDF、表格和幻灯片

核心业务

为金融、法律、保险、医疗等敏感行业的企业和 AI 原生创业公司提供文档智能服务

工作负载特点

单次上传可达数百万页，流量高度波动，对实时交互有严格的延迟要求

🚧 基础设施痛点

从手动 EC2 到 Kubernetes，每个阶段都面临扩容瓶颈

Monolith 扩容困境
30+ 模型需要一起扩缩容，即使使用模式差异巨大，GPU 过度分配成本高昂
延迟不可控
大规模突发上传导致负载尖峰，P90 延迟无法维持可预测水平
基础设施脆弱
极端突发下的弹性维护几乎不可能，工作负载隔离能力不足

"我们在 Kubernetes 集群中使用 Ray 时挣扎到快抓狂了，工具就是不好用。能直接 modal deploy 真的太好了。Modal 让我们可以做很多在 LLM 推理服务上做不到的复杂操作。"

— Raunak Chowdhuri, Reducto 创始人

🚀 Modal 部署方案

通过 GPU Memory Snapshotting、独立模型扩容和客户级隔离实现延迟飞跃

Cold Boot（迁移前）
~70s
Cold Boot（迁移后）
~12s

🧊 GPU Snapshotting

利用 GPU Memory Snapshot 将冷启动缩短 83%，从 ~70s 降至 ~12s

📊 独立模型扩容

将部分模型打包在一个 Function 中，其余分开，最大化计算利用率

🔒 客户级隔离

使用 Parameterized Functions 为每个客户创建独立的自动扩缩容计算池

🌍 区域精细控制

延迟敏感的 Function 固定在 US West（靠近自有服务器），其他工作负载利用 Modal 全球计算池处理峰值流量。
