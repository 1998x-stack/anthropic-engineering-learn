🌟 为什么 GLM-5 重要

从 GPT-3 的 Tab 补全到 GLM-5 的长期任务，开源模型首次匹配最新闭源前沿

GPT-3 时代
Tab 补全（RIP code-davinci-002）
GPT-3.5 / Claude 2
对话式 Copilot 助手（Cursor 诞生）
GPT-4 / Claude 3
简单应用开发（Lovable 出现）
Claude Opus 4.6 / GPT 5.3
长期任务，复杂系统开发（Claude Code / OpenClaw）
GLM-5 (MIT)
开源追平闭源前沿，继 DeepSeek-R1 之后又一里程碑

🔧 如何运行 GLM-5

~700GB FP8，需要多 GPU 部署，使用 MoE 稀疏和 DeepSeek Sparse Attention

FP8 权重 ~700GB
→
超过单 GPU HBM
→
8x B200 单节点
→
SGLang 推理引擎

性能指标

交互速度 30-75 tokens/s/user（取决于副本负载和 Speculator 命中率）。MoE 层用 Tensor 并行，Attention 层用 Data 并行。

🆓 免费 Endpoint

单并发请求限制，无直接 Token 限制 — 映射到个人使用的 Coding Agent 体验

限制为单并发请求而非 Token 数量，因为请求才是真正重要的。适合一到几个活跃的 Agent 线程，每个可能跨越数千 Token。

🔗 多框架集成

OpenAI API 兼容，支持 OpenCode、OpenClaw、Claude Code（via LiteLLM）、Vercel AI SDK

OpenCode

在 opencode.json 中配置 Modal 为 Provider 即可

OpenClaw

使用 openai-completions 设置指向 Modal Endpoint

Claude Code

通过 LiteLLM Gateway 代理到 Modal Endpoint

🤖 Agent 生态与展望

OpenCode Agent 可以部署到 Modal Sandbox 上获得云基础设施加速

Modal Research 团队首次在样例代码之外发布 Endpoint。Ramp 正是这样在 Modal Sandboxes 上构建了 Inspect 背景编码 Agent。更多即将推出。
