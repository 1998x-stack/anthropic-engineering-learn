🌐 问题场景

Serverless 容器在全球数据中心运行，IP 不固定 — 但你的 MongoDB 需要 IP 白名单

❌ SOCKS5 代理

  • 需要修改应用使用特殊 socket
  • 不兼容 asyncpg/aiohttp/grpc
  • 将复杂性传递给用户

✅ WireGuard VPN (L3)

  • 所有出站流量透明路由
  • ifconfig.me 返回代理 IP
  • 应用零修改

🔒 WireGuard 方案

在代理服务器和 Modal Workers 之间建立 WireGuard 网络，TLS 处理密钥分发

🔧 Policy-Based Routing

多租户 Worker 上通过路由表编号实现容器级流量隔离

技术挑战

Linux iproute2 不支持按源 IP 路由。解决方案：为每个请求代理的容器分配编号路由表，编辑 Policy Database 实现按容器路由到对应 WireGuard 接口。

rp_filter 陷阱

不同 Linux 发行版的反向路径过滤设置不同。需要设置为 loose mode (2) 而非禁用 (0)，否则 WireGuard 包会被丢弃。

📦 开源实现

控制平面已开源：modal-labs/vprox

使用 vprox server --cloud aws 启动，自动探测实例元数据发现 IP。客户端周期性 Ping 检测连接，断开时自动重连。基于 IP 的固有不可靠性，恢复对应用透明 — TCP 层自动重试丢包。
