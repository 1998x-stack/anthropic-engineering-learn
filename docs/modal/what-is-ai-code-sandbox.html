📜 沙箱简史

从 Unix chroot 到 Java VM 再到 JSFiddle，沙箱的概念从未消失

1980s: Unix chroot
最早的沙箱 — 修改进程的根目录，阻止访问指定文件系统外的文件
Java VM
"Sandbox" 一词诞生 — 字节码验证器运行不可信 Applet
2009: JSFiddle
让"代码沙箱"品牌深入年轻开发者
容器化时代
沙箱被吸收进容器化架构的庞大范畴
2024-25: AI 复兴
LLM 生成代码的安全执行需求推动沙箱方案回归

🤖 AI Coding Agent 与沙箱复兴

97% 的开发者使用 AI 编码工具 — 代码增速与错误风险的双重力量

⚡ 加速力量

  • 特性甚至整个应用一天 Vibe-Code 完成
  • Cursor/Windsurf 集成 IDE
  • 代码产出量爆发式增长

⚠️ 风险力量

  • LLM 会幻想出整个包
  • Prompt 注入可制造安全漏洞
  • 长记忆 Agent 可能被投毒上下文影响

🔬 技术原理

VM 或容器底层 + gVisor 内核级隔离 + 编排层

VM / 容器
→
gVisor 虚拟内核
→
文件系统 API
→
网络原语 + 编排

gVisor vs runc

gVisor 拦截 Guest 进程的 syscall 并提供虚拟内核，而 runc 直接使用宿主内核。这防止了 Dirty Pipe 等漏洞的容器逃逸。

🎯 核心使用场景

从 Background Coding Agent 到 RL 训练，沙箱是 AI 代码执行的关键基础设施

Background Agent

Cursor/Devin 等需要克隆环境、修改代码并执行测试

Code Review

运行 Linter/测试评估构建安全性，代码来源外部不可信

LLM 代码解释器

ChatGPT/Poe 写代码并在沙箱中验证

强化学习

安全执行代码并评分，结果作为奖励信号反馈模型

AI 生成应用

Lovable/Replit 等工具生成的大量代码需要隔离执行
