🖥️ Shell Tool：让模型操控计算机

模型只能提议工具调用，不能直接执行。Shell Tool 让模型通过命令行与计算机交互——基于 Unix 工具链（grep、curl、awk），做任何命令行能做的事。

❌ 仅靠 Prompt

只能访问训练过的智能——无法运行服务、请求 API 数据、生成电子表格等实际产物。

✅ 模型 + 计算环境

运行服务、调用 API、处理文件、生成报告——从"文字生成器"进化为"任务执行者"。

vs Code Interpreter

Code Interpreter 只能执行 Python。Shell Tool 支持任意语言和运行时——Go、Java、Node.js 服务器等。这种灵活性让模型能完成复杂的 agentic tasks。

🔄 编排 Agent Loop

Responses API 是模型与 hosted tools 之间的编排器——接收提示、组装上下文、执行命令、流式传回结果、循环直到完成。

Responses API Agent Loop

1. 组装 Context
user prompt + history + tool instructions
→
2. 模型决策
选择 action 或 final answer
→
3. 执行 Shell
转发命令到容器
↓
4. 流式输出
近实时 relay 到模型
→
5. 评估结果
继续或返回最终答案
↻ Loop

⚡ 并行执行

模型可一次提议多条 shell 命令，Responses API 在独立 container sessions 中并发执行，多路复用流式输出到结构化 tool outputs。

📏 有界输出

模型为每条命令指定 output cap。API 保留首尾内容、标记省略部分，避免大量终端日志吞噬 context budget。

text at the beginning ... 1000 chars truncated ... text at the end

"Together, concurrent execution and bounded output make the agent loop both fast and context-efficient so the model can keep reasoning over relevant results instead of getting overwhelmed by raw terminal logs."

📦 Context Window 满了怎么办：Compaction

长时间运行的 agent 任务会填满 context window。OpenAI 内建了原生 compaction：模型分析对话历史，生成加密的 token 高效压缩表示。

Compaction 工作流

→

→

= Compaction + 高价值内容

🖥️ Server-side Compaction

配置阈值后自动处理压缩时机。支持稍大的有效 input context 窗口以容忍边界溢出——接近限制的请求可以处理后再压缩，而非直接拒绝。

🔌 /compact Endpoint

独立端点，开发者可主动触发压缩。随模型训练演进，每个 OpenAI 模型发布的原生 compaction 方案自动升级。

💡 Codex 的自我参照

Codex 帮助构建了 compaction 系统，同时也是该系统的早期用户。当一个 Codex 实例遇到 compaction error，团队会启动第二个 Codex 实例来排查。"Most tools only require the user to learn how to use them; Codex learns alongside us."

📂 Container Context：文件、数据库与网络

容器不仅是运行命令的地方，更是模型的工作上下文——文件系统、结构化数据库和受控网络访问。

📁

文件系统

上传、组织和管理资源。模型获得文件地图，执行定向文件操作而非盲目扫描。

🗄️

SQLite 数据库

结构化数据存入数据库。模型通过表描述精准查询所需行，而非扫描整个电子表格。

🌐

受控网络访问

通过 sidecar egress proxy 强制执行 allowlists。凭证通过 domain-scoped secret injection 在出口注入。

❌ Anti-pattern：全塞进 Prompt

将所有输入直接打包到 prompt context。输入增长时变得昂贵且模型难以导航——效率低下。

✅ Best practice：暂存到文件系统

将资源暂存到容器文件系统，让模型决定打开、解析或用 shell 命令转换什么——就像人类处理组织化信息一样。

🔐 网络安全设计

所有出站请求经过集中策略层，执行 allowlists 和访问控制并保持流量可观测。模型和容器只看到占位符（placeholders），原始 secret 值不进入模型可见上下文，只在批准的目标域注入。降低泄露风险的同时仍支持认证外部调用。

🧩 Agent Skills：可复用的工作流积木

Shell 命令很强大，但许多任务重复相同的多步模式。Agent Skills 将这些模式打包为可复用、可组合的构建块。

Skill 的结构

一个 skill 是一个文件夹 bundle：

  • SKILL.md — 元数据和指令
  • 支持资源 — API specs、UI assets 等

这自然映射到前面的运行时架构：容器提供持久文件和执行上下文，shell tool 提供执行接口。模型可以通过 shell 命令（ls、cat）发现 skill 文件，解释指令并运行 skill 脚本——全部在同一个 agent loop 中。

1. Fetch Skill Metadata
获取 skill 的 name 和 description，用于模型判断是否相关。
2. Fetch & Unpack Bundle
获取 skill bundle，复制到容器中并解包。版本化存储在 OpenAI 平台。
3. Update Model Context
将 skill metadata 和容器路径注入模型上下文。模型渐进探索指令并通过 shell 执行脚本。

"Agents have to rediscover the workflow each run — replanning, reissuing commands, and relearning conventions — leading to inconsistent results and wasted execution. Agent skills package those patterns into reusable, composable building blocks."

🏭 Agent 全貌：五大原语的组合

Responses API 提供编排，Shell Tool 提供执行，Container 提供运行上下文，Skills 叠加可复用工作流，Compaction 保障长时间运行——一个 prompt 就能展开端到端工作流。

Agent 原语栈

Responses API
编排层 — 接收 prompt、组装 context、循环执行直到完成
Shell Tool
执行层 — 通过命令行运行任意操作（grep、curl、python、node...）
Container
上下文层 — 文件系统 + SQLite + 受控网络 = 模型的工作环境
Agent Skills
复用层 — 版本化 bundle 将多步模式打包为可发现、可组合的积木
Compaction
持久层 — 压缩对话历史保留关键状态，支撑跨 context window 的长任务

原语解决什么问题关键特性
Responses API 模型与 tool 之间的编排循环 streaming、并发执行、有界输出
Shell Tool 让模型实际执行操作 任意语言/运行时、Unix 工具链
Container 隔离运行环境 + 工作上下文 文件 API、SQLite、egress proxy
Skills 避免每次重新发现工作流 版本化 bundle、SKILL.md、平台 API
Compaction 长任务的 context 管理 原生压缩、server-side 自动、/compact endpoint
