🔥 为什么需要新的网络设计

大规模 AI 训练中，单次训练步骤涉及数百万次数据传输。一次传输延迟就能让整个集群的 GPU 闲置——网络拥塞、链路和设备故障是延迟和抖动的主要来源。

❌ 传统网络的问题

• 单次链路故障导致训练崩溃，需从 checkpoint 重启
• 网络重新计算路由需数秒到数十秒
• 集群越大，故障概率越高
• GPU 空闲成本极高
• 拥塞导致同步训练的最慢传输拖慢所有 GPU

✅ MRC 的目标

• 微秒级故障检测和绕行
• 网络拥塞几乎为零
• 链路故障不影响训练作业
• 简化网络控制平面
• 更少的组件、更低的功耗

⚡ 核心挑战

同步预训练（Synchronous Pretraining）中，多台计算机上的 GPU 需要步调一致地协作训练同一个模型。这意味着任何单个链路的抖动或故障会被放大——集群越大，单次故障的影响越严重。这种工作负载本质上是一个"故障放大器"。

🏗️ MRC 协议概览

Multipath Reliable Connection（MRC）是 OpenAI 与 AMD、Broadcom、Intel、Microsoft、NVIDIA 合作开发的新型网络协议，内置于最新的 800Gb/s 网络接口中。

🔗 多路径传输

单个传输的数据包被分散到数百条路径上，跨越所有网络平面，消除热点。

⚡ 微秒级故障恢复

检测到路径故障后，立即停止使用该路径并重传丢失的数据包，无需等待路由重计算。

📋 静态源路由

使用 SRv6 让发送方指定数据包路径，消除动态路由协议的整类故障。

"Our goal was not just to build a fast network, but also to build one that delivers very predictable performance, even in the presence of failures, to keep training jobs moving."

⚠️ 多平面的挑战

丰富的路径多样性难以被传统协议充分利用。传统 RoCE 协议要求每次传输走单一路径以保证数据包顺序，这导致两个问题：不同流量可能在同一链路上碰撞造成拥塞，每个流只能使用一个平面。如果不解决这些问题，多平面网络反而会产生严重的拥塞。

🌊 Packet Spraying：数百条路径的自适应分发

MRC 从根本上改变了传输模型：不再将传输分配到单一路径，而是将同一传输的数据包分散到数百条路径上，跨越所有网络平面。

Spray 分发
每个传输的数据包被分散到数百条路径上。每个 MRC 数据包都包含最终内存地址，目标端可以在数据包到达时立即写入内存，无需等待排序。
自适应负载均衡
每个 MRC 连接维护少量路径状态。检测到路径拥塞时，自动切换到其他路径，在整个网络上均匀分配负载。
快速故障隔离
丢包时采取保守策略：假设路径可能故障，立即停止使用并重传。然后发送探测包确认是否真的故障及是否已恢复。
Packet Trimming
交换机在拥塞时不丢弃整个数据包，而是裁剪掉 payload 只转发 header。目标端收到 header 后触发显式重传请求，减少将拥塞误判为故障的误报。

📊 核心效果

多平面拓扑 + Spraying + 负载均衡 + Trimming 的组合使 MRC 能在微秒级检测网络故障并绕行，而传统网络可能需要数秒甚至数十秒才能稳定。对同步训练作业的影响被最小化。

🗺️ SRv6 静态源路由：消除动态路由故障

MRC 用 IPv6 Segment Routing（SRv6）取代了传统的 BGP 动态路由协议。发送方直接在数据包地址中编码完整路径，交换机只需按静态表转发。

❌ 动态路由（BGP）

• 交换机运行复杂路由软件
• 微妙故障难以诊断
• 路由收敛需要时间
• 故障传播范围不可预测
• 路由表持续更新

✅ SRv6 静态源路由

• 路由表在首次配置后永不更改
• 发送方确定性地选择路径
• 路径故障时 MRC 直接停用
• 交换机无需重计算路由
• 消除整类动态路由故障

"SRv6 allows the sender to encode the full path each packet should take to the network. Because this is deterministic, the sender can independently react to congestion or loss on a given path."

🏭 生产环境表现

MRC 已部署在 OpenAI 所有最大的 NVIDIA GB200 超级计算机上，包括与 Oracle Cloud Infrastructure (OCI) 合作的 Abilene 数据中心和 Microsoft 的 Fairwater 超级计算机。

✅ 链路故障透明

训练中每分钟观测到多次 Tier-0 至 Tier-1 链路抖动，MRC 确保对同步预训练作业无可测量影响。甚至不需要优先修复这些链路。

✅ 交换机重启无感

训练一个前沿模型期间需要重启 4 台 Tier-1 交换机。以前需要小心协调避免中断训练。使用 MRC 后，甚至无需通知训练团队。

✅ 端口降级优雅

8 端口网络接口丢失 1 个端口时，最大速率仅降低 1/8。MRC 重算路径避开故障平面，大多数故障在一分钟内恢复。

🔧 运维变革

以前，链路维修前需要与运维团队协调禁用链路。现在可以在链路仍在服务状态下进行维修。如果链路工作良好，MRC 会使用它；如果不行，MRC 会自动避开直到修复完成。这从根本上改变了超大规模集群的运维模式。

🏆 三大核心优势

MRC 在扩展超级计算机规模时带来三个关键优势。

🔗 简化拓扑

用仅 2 层以太网交换机构建连接超 10 万 GPU 的多平面高速网络。比传统 3-4 层单平面网络更低功耗、更少组件故障。

⚖️ 零核心拥塞

自适应 Packet Spraying 负载均衡效果极佳，网络核心基本无拥塞。消除了同步训练中流量吞吐量的变异性，多作业共享集群时互不影响。

🛡️ 静态控制平面

SRv6 源路由快速绕过故障，只在正常路径上发包。运行简单的静态网络控制平面，消除整类动态路由故障行为。

🌍 开放协议与行业生态

MRC 规范通过 Open Compute Project（OCP）公开发布，供整个行业使用和构建。这是 OpenAI 整体计算战略的一部分：关键基础设施层的共享标准帮助更高效、可靠地扩展 AI 系统。

🤝 合作伙伴生态

AMD、Broadcom、Intel、Microsoft、NVIDIA 共同参与开发。MRC 已用于训练多个 OpenAI 模型，利用 NVIDIA 和 Broadcom 硬件。各合作伙伴都在其博客发布了相关技术文章。

📄 开放贡献

MRC 1.0 规范通过 OCP 发布，附带联合论文"Resilient AI Supercomputer Networking using MRC and SRv6"，详述了部署经验和技术细节。

🏗️ Stargate 基石

MRC 是 Stargate 超级计算机网络设计的关键部分。在 Stargate 规模下高效使用计算资源需要从根本上减少堆栈每一层的复杂性。

🔮 未来展望

随着训练集群继续增长，网络设计越来越决定了可用计算的实际利用率。MRC 帮助 GPU 在拥塞、链路故障和维护事件中保持协同运转。

"At meaningful scale, that reliability and efficiency is not a nice-to-have; it is part of what makes synchronous frontier model training possible."

📌 总结

🎯 核心要点

  • 多平面拆分：800Gb/s → 8×100Gb/s，2 层交换机连接 131K GPU
  • Packet Spraying：数据包分散到数百条路径，消除网络热点
  • 自适应故障恢复：微秒级检测、绕行、重传
  • SRv6 源路由：消除 BGP 动态路由的整类故障
  • Packet Trimming：减少拥塞误报，精确区分拥塞和故障
  • 生产验证：链路故障和交换机重启对训练零影响
  • 开放标准：通过 OCP 向整个行业开放
