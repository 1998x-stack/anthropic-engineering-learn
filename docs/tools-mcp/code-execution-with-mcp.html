🌐 MCP 背景与问题

Model Context Protocol (MCP) 是连接 AI Agent 到外部系统的开放标准。自 2024 年 11 月发布以来，社区已构建数千个 MCP 服务器，SDK 覆盖所有主流编程语言，行业已将 MCP 作为连接 Agent 到工具和数据的默认标准。

🔥 扩展性问题

当 Agent 连接到数百或数千个工具时，一次性加载所有工具定义并让中间结果穿过上下文窗口会拖慢 Agent 速度并增加成本。

💸 两种 Token 消耗痛点

随着 MCP 使用量增长，两种常见模式导致 Agent 成本和延迟上升：

❌ 痛点 1: 工具定义过载上下文窗口

大多数 MCP 客户端一次性将所有工具定义直接加载到上下文中。对于连接到数千个工具的 Agent，需要在读取请求之前处理数十万 token。

gdrive.getDocument Description: Retrieves a document from Google Drive Parameters: documentId (required, string) fields (optional, string) Returns: Document object with title, body, metadata... salesforce.updateRecord Description: Updates a record in Salesforce Parameters: objectType (required, string) recordId (required, string) data (required, object)

❌ 痛点 2: 中间结果消耗额外 Token

每个中间结果必须穿过模型。下载会议记录并附加到 Salesforce lead：
相同数据流过两次！

TOOL CALL: gdrive.getDocument("abc123") → returns "Discussed Q4 goals...\n[完整转录文本]" (加载到模型上下文) TOOL CALL: salesforce.updateRecord({ Notes: "Discussed Q4 goals...\n[同样的完整转录文本]" }) （模型需要再次写入整个转录到上下文）

对 2 小时销售会议，意味着额外处理 ~50,000 token

⚡ 代码执行方案

将 MCP 服务器呈现为代码 API而非直接工具调用。Agent 编写代码与 MCP 服务器交互。只加载需要的工具，在代码环境中处理数据后再返回结果。

📂 文件树结构

每个工具对应一个 TypeScript 文件。Agent 通过浏览文件系统发现可用工具。

✨ 核心改进

传统 MCP 加载全部
150,000 tokens
代码执行按需加载
2,000 tokens

时间 + 成本节省 98.7% 🔥

"LLMs are adept at writing code and developers should take advantage of this strength to build agents that interact with MCP servers more efficiently." — Cloudflare "Code Mode"

🗺️ 渐进式发现

模型擅长浏览文件系统。将工具作为代码呈现在文件系统中，Agent 可以按需读取工具定义，而不是一开始就全量加载。

🔍 搜索工具增强

  • search_tools 工具搜索相关定义
  • detail_level 参数："name only" / "name + description" / "full definition"
  • Agent 按需要的详细程度选择加载级别，节省上下文

📊 上下文高效的结果

处理大型数据集时，Agent 可以在代码中过滤和转换结果，然后再返回给模型。

❌ 无代码执行

// 所有行流经上下文 TOOL CALL: gdrive.getSheet('abc123') → returns 10,000 rows in context to filter manually

✅ 有代码执行

const allRows = await gdrive .getSheet({sheetId:'abc123'}); const pendingOrders = allRows.filter( row => row["Status"] === 'pending' ); console.log(pendingOrders.slice(0, 5)); // Agent 只看 5 行！

🔄 更强大的控制流

循环、条件语句、错误处理可以用熟悉的代码模式完成，而不是逐个串联工具调用：

// 等待 Slack 部署通知（无需代理循环） let found = false; while (!found) { const messages = await slack .getChannelHistory({channel:'C123456'}); found = messages.some(m => m.text.includes('deployment complete') ); if (!found) await new Promise(r => setTimeout(r, 5000) ); } console.log('Deployment notification received');

不仅更高效，还节省了 "首次 token 时间"——代码执行环境直接评估条件逻辑。

🔒 隐私保护操作

使用代码执行 + MCP 时，中间结果默认保留在执行环境中。只有显式日志或返回的数据才进入模型上下文。

🛡️ PII 自动脱敏

MCP 客户端拦截数据并在到达模型前自动标记 PII：

原始数据（不在模型中）

{ email: 'user@example.com', phone: '+1-555...' };

Agent 看到的（已脱敏）

{ email: '[EMAIL_1]', phone: '[PHONE_1]' };

真实 email/phone/name 从 Google Sheets 流转到 Salesforce，但从不穿过模型。

💾 状态持久化与技能

带文件系统的代码执行允许 Agent 跨操作维护状态。

📁 中间结果保存

Agent 可以将中间结果写入文件以恢复工作和跟踪进度。

🔧 可复用函数

Agent 可以将其工作代码保存为可复用的函数。

📦 Skills 集成

添加 SKILL.md 到这些保存的函数中创建结构化技能。长期积累形成高级能力工具箱。

⚠️ 安全考量

需要安全的执行环境 + 沙箱 + 资源限制 + 监控。

⚖️ 权衡分析

代码执行引入自己的复杂性：运行 Agent 生成的代码需要安全措施和操作开销。应将收益（减少 token 成本、降低延迟、更好的工具组合）与实现成本进行权衡。
