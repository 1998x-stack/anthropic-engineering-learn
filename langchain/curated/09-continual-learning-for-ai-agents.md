# AI Agent 的持续学习：三层学习架构全解析

**作者:** LangChain Team  
**来源:** [LangChain Blog](https://www.langchain.com/blog/continual-learning-for-ai-agents)  
**日期:** 2026 年 5 月  
**阅读时间:** 约 8 分钟

---

> **一句话总结**  
> AI Agent 的持续学习 (Continual Learning) 发生在三个层次 —— 模型层、线束层、上下文层。每一层的学习机制不同，但它们共享同一个核心燃料：执行轨迹 (Traces)。

---

## 核心要点

1. **模型层学习最强大但最危险** —— 通过微调 (SFT) 和强化学习 (RL) 更新权重，但面临灾难性遗忘 (Catastrophic Forgetting) 的核心挑战
2. **线束层学习最自动化** —— 编码 Agent 分析执行轨迹，自动建议线束代码改进，形成"Agent 改进 Agent"的闭环
3. **上下文层学习最灵活** —— 从 Agent 级到租户级的记忆系统，支持离线"做梦"和在线即时学习两种模式
4. **轨迹是一切学习的原材料** —— 无论哪一层的学习，都从收集和分析执行轨迹开始
5. **显式 vs 隐式记忆并行运行** —— 用户主动要求记住的（显式）和 Agent 自行判断该记住的（隐式）共同构成完整的学习系统

---

## 一、三层学习架构总览

AI Agent 的持续学习不是单点优化，而是一个分层系统。每一层有自己的学习机制、更新速度和风险特征：

```
┌─────────────────────────────────────────────────────────────┐
│                   AI Agent 三层学习架构                       │
│                                                             │
│  ┌──────────────────────────────────────────────────────┐   │
│  │  第一层：模型层 (Model Layer)                          │   │
│  │                                                      │   │
│  │  · 更新方式：SFT / RL (如 GRPO)                       │   │
│  │  · 更新频率：低（天/周级别）                            │   │
│  │  · 风险：灾难性遗忘                                   │   │
│  │  · 粒度：通常 Agent 级，理论上可 per-user (LoRA)       │   │
│  └──────────────────────────────────────────────────────┘   │
│                          ▲                                  │
│                          │ 轨迹驱动                          │
│                          │                                  │
│  ┌──────────────────────────────────────────────────────┐   │
│  │  第二层：线束层 (Harness Layer)                        │   │
│  │                                                      │   │
│  │  · 更新方式：编码 Agent 分析轨迹 → 修改线束代码          │   │
│  │  · 更新频率：中（小时/天级别）                          │   │
│  │  · 风险：较低（代码可 review、可回滚）                  │   │
│  │  · 粒度：Agent 级                                     │   │
│  └──────────────────────────────────────────────────────┘   │
│                          ▲                                  │
│                          │ 轨迹驱动                          │
│                          │                                  │
│  ┌──────────────────────────────────────────────────────┐   │
│  │  第三层：上下文层 (Context Layer)                       │   │
│  │                                                      │   │
│  │  · 更新方式：记忆文件读写 / 向量存储                    │   │
│  │  · 更新频率：高（实时或近实时）                         │   │
│  │  · 风险：最低（配置级变更）                             │   │
│  │  · 粒度：Agent / 租户 / 用户 级                       │   │
│  └──────────────────────────────────────────────────────┘   │
│                                                             │
│              ▲▲▲  所有层的燃料：执行轨迹 (Traces)  ▲▲▲       │
└─────────────────────────────────────────────────────────────┘
```

> **类比理解**  
> 把 Agent 想象成一个员工。**模型层学习**相当于送员工去培训班，系统地提升底层能力，但培训新技能可能导致旧技能退化。**线束层学习**相当于优化工作流程和工具，让同一个员工更高效。**上下文层学习**相当于给员工一本不断更新的备忘录，记录客户偏好和项目要点。三者协同，才是一个持续成长的员工。

## 二、模型层：更新权重，最强大也最危险

### 工作原理

模型层学习通过修改模型的权重参数来改变其行为，主要技术包括：

| 技术 | 全称 | 机制 |
|------|------|------|
| **SFT** | Supervised Fine-Tuning | 在标注好的轨迹数据上微调，让模型模仿"好的行为" |
| **RL** | Reinforcement Learning | 通过奖励信号优化策略，如 GRPO (Group Relative Policy Optimization) |
| **LoRA** | Low-Rank Adaptation | 低秩适配器，理论上可以为每个用户维护独立的适配层 |

### 核心挑战：灾难性遗忘

灾难性遗忘 (Catastrophic Forgetting) 是模型层学习的致命问题：

```
训练前                        训练后
┌──────────────────┐        ┌──────────────────┐
│  模型知识          │        │  模型知识          │
│                  │        │                  │
│  ■■■■ 数学推理    │        │  ■■□□ 数学推理 ↓  │
│  ■■■■ 代码生成    │        │  ■■■□ 代码生成 ↓  │
│  ■■■■ 语言理解    │        │  ■■■■ 语言理解    │
│  □□□□ 新领域知识  │        │  ■■■■ 新领域知识 ↑ │
│                  │        │                  │
│  总能力：稳定      │        │  新能力 ↑ 旧能力 ↓ │
└──────────────────┘        └──────────────────┘
```

> **类比理解**  
> 灾难性遗忘就像一个学生疯狂补习物理，结果数学考试成绩反而下降了。大脑容量有限，新知识"覆盖"了旧知识的神经通路。

### 为什么重要

模型层学习是目前**最深层的改变** —— 它直接修改了 Agent 的"思维方式"。但正因为如此，每次更新都是一次赌博：你无法完全预测新训练数据会破坏模型的哪些现有能力。这就是为什么大多数实践者选择在**线束层和上下文层**进行更频繁、更安全的学习迭代。

## 三、线束层：Agent 改进 Agent

### 工作原理

线束 (Harness) 是驱动 Agent 的代码 —— 包括指令、工具定义、编排逻辑等。线束层学习的核心思路是：**用一个编码 Agent 来分析执行轨迹，自动改进线束代码。**

这一方法在论文 *Meta-Harness: End-to-End Optimization of Model Harnesses* 中被系统阐述：

```
┌─────────────────────────────────────────────────────┐
│             线束层学习闭环                              │
│                                                     │
│  ┌─────────┐    ┌──────────┐    ┌───────────────┐  │
│  │ Agent   │───→│ 执行任务  │───→│ 收集执行轨迹   │  │
│  │ (线束)   │    │          │    │ (Traces)      │  │
│  └─────────┘    └──────────┘    └───────┬───────┘  │
│       ▲                                 │          │
│       │                                 ▼          │
│  ┌────┴────────┐              ┌─────────────────┐  │
│  │ 更新线束代码 │◀─────────────│ 编码 Agent 分析  │  │
│  │             │  建议改进     │ 轨迹日志         │  │
│  └─────────────┘              └─────────────────┘  │
│                                                     │
│  评估 → 存储日志 → 分析 → 修改 → 再评估              │
└─────────────────────────────────────────────────────┘
```

### 具体流程

1. **运行 Agent** —— 在一组任务上执行，收集完整的执行轨迹
2. **评估结果** —— 标注哪些任务成功、哪些失败、哪些低效
3. **存储日志** —— 将轨迹和评估结果持久化
4. **分析轨迹** —— 用编码 Agent 阅读轨迹，识别失败模式和改进机会
5. **建议修改** —— 编码 Agent 提出线束代码的具体修改方案
6. **验证改进** —— 在相同任务上重新评估，确认改进有效

> **为什么重要**  
> 线束层学习是一种"元优化" —— 不是教模型新东西，而是优化模型的工作环境。这类似于不培训员工，而是改进员工的工作流程、工具和标准操作规程 (SOP)。风险更低，因为代码修改可以被 review、测试和回滚。

## 四、上下文层：最灵活的学习机制

### 什么是上下文层

上下文层 (Context Layer) 位于线束之外，但用于配置线束。它包含指令 (Instructions)、技能 (Skills)、工具定义 (Tools) —— 也就是通常所说的**记忆 (Memory)**。

> **类比理解**  
> 如果模型层是"改造大脑"，线束层是"改进工作流程"，那么上下文层就是"更新备忘录"。备忘录不改变员工的能力，也不改变工作流程，但它告诉员工"这个客户喜欢什么"、"上次那个方案效果不好"。

### 多层级的学习上下文

上下文层学习的独特之处在于它可以在多个粒度上运作：

| 层级 | 含义 | 示例 |
|------|------|------|
| **Agent 级** | 整个 Agent 共享的持久记忆 | OpenClaw 的 SOUL.md —— Agent 随时间更新的"灵魂文件" |
| **租户级** | 每个用户/组织/团队独立的上下文 | Hex 的 Context Studio、Decagon 的 Duet、Sierra 的 Explorer |
| **混合模式** | 多个层级同时生效 | Agent 级通用知识 + 用户级个性化偏好 |

┌─────────────────────────────────────────────────────┐
│               上下文层级结构                           │

│  │  (所有用户共享的通用知识和技能)                  │    │
│  │                                             │    │
│  │  ┌──────────────────────────────────────┐   │    │
│  │  │  租户级上下文 (组织 A)                  │   │    │
│  │  │  (组织 A 的特定流程和偏好)              │   │    │
│  │  │                                      │   │    │
│  │  │  ┌──────────┐  ┌──────────┐          │   │    │

│  │  │  │ 个人偏好  │  │ 个人偏好  │          │   │    │
│  │  │  └──────────┘  └──────────┘          │   │    │

### 两种更新时机

上下文更新有两种截然不同的时机：

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│  离线学习 ("做梦" 模式)          在线学习 (即时模式)        │
│                                                          │
│  ┌────────────────────┐       ┌────────────────────┐    │
│  │ 回顾近期轨迹        │       │ 执行核心任务         │    │
│  │       ↓             │       │       ↓             │    │
│  │ 提取关键洞察        │       │ 同时更新记忆         │    │
│  │       ↓             │       │       ↓             │    │
│  │ 更新记忆文件        │       │ 继续执行任务         │    │
│  │                    │       │                    │    │
│  │ 📌 不影响当前任务    │       │ ⚡ 立即生效          │    │
│  │ 📌 批量处理更高效    │       │ ⚡ 但增加任务延迟     │    │
│  │ 📌 如 OpenClaw      │       │                    │    │
│  │    的 "Dreaming"    │       │                    │    │
│  └────────────────────┘       └────────────────────┘    │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

### 显式 vs 隐式记忆

另一个关键维度是：记忆的触发方式。

| 类型 | 触发方式 | 示例 |
|------|---------|------|
| **显式记忆** | 用户主动要求 Agent 记住某事 | "记住我偏好 TypeScript 而不是 JavaScript" |
| **隐式记忆** | Agent 根据线束指令自行判断什么值得记住 | Agent 发现用户反复手动修改缩进风格，自动记录偏好 |

> **为什么重要**  
> 显式记忆简单可控，但依赖用户主动操作。隐式记忆更智能，但存在"过度记忆"或"记错"的风险。成熟的 Agent 系统需要两者兼备 —— 显式记忆确保精确性，隐式记忆提供便利性。

## 五、轨迹：一切学习的燃料

三层学习看似独立，但它们共享一个核心依赖 —— **执行轨迹 (Traces)**。轨迹记录了 Agent 的每一步操作：调用了什么工具、生成了什么内容、用户给了什么反馈、最终结果如何。

│                                                         │
│                 ┌──────────────┐                        │

│                 │  (Traces)    │                        │
│                 └──────┬───────┘                        │
│                        │                                │
│           ┌────────────┼────────────┐                   │
│           ▼            ▼            ▼                   │
│   ┌──────────────┐ ┌──────────┐ ┌──────────────────┐   │
│   │ 更新模型      │ │ 改进线束  │ │ 学习上下文        │   │
│   │              │ │          │ │                  │   │
│   │ 收集轨迹      │ │ 编码Agent│ │ 线束支持          │   │

### 三层学习对比总结

| 维度 | 模型层 | 线束层 | 上下文层 |
|------|--------|--------|---------|
| **更新对象** | 模型权重 | 线束代码 | 记忆/配置文件 |
| **更新速度** | 慢（天/周） | 中（小时/天） | 快（实时） |
| **更新风险** | 高（灾难性遗忘） | 中（可回滚） | 低（配置级） |
| **更新粒度** | Agent 级为主 | Agent 级 | Agent / 租户 / 用户级 |
| **核心技术** | SFT, RL, LoRA | 轨迹分析 + 代码修改 | 记忆文件 + 向量存储 |
| **谁执行更新** | 训练工程师 | 编码 Agent | Agent 自身 / 用户 |

## 延伸思考

1. **三层学习的最优配比是什么？** 在实际 Agent 产品中，应该在哪一层投入最多的工程资源？随着模型能力增强，这个配比会如何变化？
2. **灾难性遗忘的工程解法：** LoRA per-user 在理论上可以实现用户级的模型层学习。如果这条路走通，是否意味着上下文层记忆的重要性会下降？
3. **"做梦"机制的边界：** OpenClaw 的离线学习（"Dreaming"）从轨迹中提取洞察 —— 但如何确保提取的洞察是正确的？错误的隐式记忆会如何影响 Agent 的长期行为？
4. **轨迹的隐私问题：** 轨迹是一切学习的燃料，但轨迹包含了用户的完整操作记录。在多租户场景下，如何在保护用户隐私的同时最大化轨迹的学习价值？
