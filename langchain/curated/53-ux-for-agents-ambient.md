# AI Agent 的用户体验（二）：环境式 Agent

> 一句话总结：环境式 Agent（Ambient Agent）在后台默默干活，用户不需要盯着它。关键挑战是如何建立信任、如何让人类在必要时介入。

---

## 核心要点

| 要点 | 说明 |
|------|------|
| 从"人在环中"到"人在环上" | Agent 在后台自主运行，人类从逐步审批变为事后监督 |
| 信任需要透明性 + 可纠正性 | 用户能看到 Agent 的每一步，并且能回退纠正 |
| Agent 也需要"求助"机制 | 遇到自己搞不定的事，Agent 应主动请求人类输入 |

---

## 一、什么是环境式 Agent？

在上一篇文章里我们讨论了聊天式交互 -- 你和 Agent 面对面对话。但现实中有大量任务不需要你全程盯着。环境式 Agent（Ambient Agent）就是在后台自动运行的 Agent，它默默完成任务，你该干嘛干嘛。

但这带来一个根本性问题：**你怎么敢放心让一个 AI 在后台替你做事？**

```
聊天式 Agent:     你 <--实时对话--> Agent
                  (你全程参与)

环境式 Agent:     你在做别的事...    Agent 在后台运行
                       |                    |
                       |                    v
                       |            [步骤1] --> [步骤2] --> [步骤3]
                       |                                      |
                       +------------ 需要你时才通知 <---------+
```

---

## 二、建立信任：从"人在环中"到"人在环上"

让 Agent 在后台运行需要信任。信任不是凭空产生的，它需要通过设计来构建。

### 第一步：让用户看到一切

最直接的方式就是**展示 Agent 正在做什么**。虽然信息不像流式聊天那样实时弹到你面前，但它应该随时可查。用户想看的时候，能点进去看到 Agent 走的每一步。

这就是从"人在环中"（Human-in-the-loop）到"人在环上"（Human-on-the-loop）的转变：

| 模式 | 含义 | 类比 |
|------|------|------|
| Human-in-the-loop | Agent 每一步都要人类批准 | 实习生每做一件事都来问你 |
| Human-on-the-loop | Agent 自主运行，人类监督 | 成熟员工自己干活，你定期 check |

### 第二步：让用户能纠正 Agent

光看还不够，用户需要能**纠正** Agent 的错误。如果 Agent 在第 4 步做错了（一共 10 步），用户应该能回到第 4 步进行修正。

纠正的方式有三种，拿"Agent 错误调用了一个工具"来举例：

| 纠正方式 | 具体做法 | 特点 |
|----------|---------|------|
| 方式一：直接替换 | 你手动写出正确的工具调用，替换掉 Agent 的错误输出，然后从这里继续 | 最精确，但对用户要求高 |
| 方式二：明确指导 | 告诉 Agent "用参数 X 而不是参数 Y 来调用"，让 Agent 自己修正 | Agent 知道自己错了，能学习 |
| 方式三：更新上下文重跑 | 修改 Agent 在那个时间点的指令或状态，从那一步重新运行 | Agent 不知道之前错了，干净重来 |

方式二和方式三的关键区别在于：**Agent 是否知道自己之前犯了错**。方式二让 Agent 看到自己的错误输出并纠正；方式三则是"洗掉记忆"，用新的指令重新开始。

```
Agent 运行过程:

  [步骤1] --> [步骤2] --> [步骤3] --> [步骤4:出错!] --> [步骤5] --> ...
                                          |
                                    用户发现错误
                                          |
                          +---------------+---------------+
                          |               |               |
                     方式一:替换      方式二:指导      方式三:重跑
                    "我来写正确的"  "你应该用X不用Y"  "更新指令,重来"
                          |               |               |
                          v               v               v
                     [步骤4:修正] --> [步骤5] --> [步骤6] --> 完成
```

### 类比理解

这三种纠正方式就像你管理团队时的三种风格：

- **方式一（替换）**：你直接改同事的代码提交上去 -- "我来吧"。
- **方式二（指导）**：你在 code review 里写评论 -- "这里应该用 map 不是 for 循环"。同事看到反馈后自己改。
- **方式三（重跑）**：你改了需求文档，然后让同事重新从头做 -- 同事不知道之前版本有什么问题。

## 三、Agent 也需要"求助"：人类输入的集成

环境式 Agent 在后台运行，不代表它必须完全自主。有些时刻它需要人类的判断。

一个具体的例子：作者搭建了一个邮件助手 Agent（Email Assistant）。这个 Agent 能自动回复简单邮件，但遇到以下情况时会主动来问：

- 复杂的技术 bug 报告，需要人类判断优先级
- 是否参加某个会议或活动，需要人类做决策

注意关键区别：Agent 不是让你直接回邮件，而是**征求你的意见**，然后它自己去写一封得体的回复或安排日历。

作者把这个助手接入了 Slack。Agent 在 Slack 里 ping 他一个问题，他在 thread 里回复，完美融入了日常工作流。

### Agent Inbox：一个有点细思恐极的概念

如果把这个模式放大，你会得到一个类似客服工作台的界面 -- 展示所有 Agent 需要人类帮助的地方、请求的优先级、相关的上下文信息。

作者给它取了个名字叫"Agent Inbox"（Agent 收件箱）。但仔细想想，这其实是**人类帮 Agent 处理任务的收件箱** -- 角色完全反转了。以前是人类把任务分配给 AI，现在是 AI 把任务分配给人类。

```
传统模式:   人类 --> 分配任务 --> AI 执行
                                    
Agent Inbox: AI 运行中... --> 遇到难题 --> 发到"人类收件箱"
                                              |
                                         人类处理后回复
                                              |
                                         AI 继续运行
```

### 类比理解

想象一个超级高效的助理。他能独立处理 90% 的日常事务，但遇到需要你拍板的事情（比如要不要接受一个合作邀请），他会把问题整理好，简明扼要地问你："老板，这个合作你怎么看？我需要知道你的态度才能回复对方。"你回复一句"拒绝，太忙了"，他就去写一封礼貌的拒绝信发出去。

## 四、为什么环境式 Agent 是关键

作者对环境式 Agent 的前景非常看好，认为它是**让人类突破自身能力上限的关键**。

原因很简单：你一天只有 24 小时，但需要处理的事情远超你的精力。如果有多个 Agent 在后台帮你处理琐事，你就能把注意力集中在真正需要人类判断力的事情上。

LangGraph 团队在构建基础设施时，正是围绕这些 UX 模式来设计的：

- **状态检查点（Checkpoint）**：保存 Agent 运行的每个状态，方便回溯和审查
- **回退和编辑**：支持用户回到任意步骤进行修正
- **等待人类响应**：Agent 能暂停运行，等待人类输入后继续

---

## 为什么重要

| 角色 | 影响 |
|------|------|
| 产品设计者 | 必须设计"信任递进"机制：先让用户在小任务上信任 Agent，再逐步扩大自主权 |
| 开发者 | 需要为 Agent 构建完善的状态管理、回退、和人类介入接口 |
| 用户 | 学会"委托"是一种新技能 -- 知道什么时候该盯着看，什么时候该放手 |

---

## 延伸思考

1. **你愿意让 AI 在后台帮你回邮件吗？** 如果愿意，你的底线在哪里？哪些邮件绝对不能让 AI 自动处理？
2. **"人类帮 AI 干活"这件事** -- Agent Inbox 的概念是不是让你感到一丝不安？当 AI 成为主导者，人类变成"审批节点"，工作的意义会发生什么变化？
3. **信任是可以量化的吗？** 能不能设计一个"信任分数"，根据 Agent 过去的表现自动调整它的自主权限？
