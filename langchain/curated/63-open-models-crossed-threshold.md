# 开源模型已经跨过临界点

> 一句话总结：GLM-5 和 MiniMax M2.7 等开源模型在文件操作、工具调用、指令遵循等核心 Agent 任务上，已经接近甚至追平闭源前沿模型（Claude Opus、GPT-5.4），而成本低 8-10 倍、延迟低 4 倍——开源模型用于 Agent 的时代正式到来。

---

## 核心要点

| 要点 | 说明 |
|------|------|
| 开源模型追平闭源模型 | GLM-5 正确率 0.64（通过 94/138），Claude Opus 4.6 正确率 0.68（通过 100/138），差距极小 |
| 成本差距巨大 | 同样日输出 1000 万 Token，Opus 约 $250/天，MiniMax M2.7 仅 $12/天，年省 $87k |
| 延迟优势明显 | GLM-5 延迟 0.65 秒、70 token/s；Opus 延迟 2.56 秒、34 token/s |
| 一行代码切换 | Deep Agents 框架自动适配上下文窗口、工具格式、系统提示词 |
| 混合架构是未来 | 前沿模型做规划、开源模型做执行，运行时可动态切换 |

## 评测方法论

LangChain 团队用 Deep Agents 的评测套件（Eval Suite）测试了 7 个能力维度，这些是判断一个模型能否在 Agent 场景中"能用"的最低门槛：

```
评测维度          测什么
+-----------+     模型能否可靠地读写文件？
| 文件操作   |
+-----------+
| 工具调用   |     模型能否正确调用外部工具？
+-----------+
| 检索       |     模型能否从上下文中找到正确信息？
+-----------+
| 对话       |     模型能否维持多轮对话的连贯性？
+-----------+
| 记忆       |     模型能否记住之前的上下文？
+-----------+
| 摘要       |     模型能否准确总结长文本？
+-----------+
| 单元测试   |     模型能否通过基础功能测试？
+-----------+
```

评测产出 4 个核心指标：

| 指标 | 含义 | 理想值 |
|------|------|--------|
| Correctness（正确率） | 通过的测试用例比例 | 越高越好 |
| Solve Rate（解决率） | 综合衡量正确性和速度 | 越高越好 |
| Step Ratio（步数比） | 实际步数 / 预期步数 | 1.0（低于 1.0 = 更高效） |
| Tool Call Ratio（调用比） | 实际工具调用数 / 预期数 | 1.0（低于 1.0 = 更高效） |

## 如何使用开源模型

在 Deep Agents 框架里切换到开源模型，只需要改一行代码：

```
# GLM-5（通过 Baseten 托管）
pip install langchain-baseten
agent = create_deep_agent(model="baseten:zai-org/GLM-5")

# MiniMax M2.7（通过 OpenRouter）
pip install langchain-openrouter
agent = create_deep_agent(model="openrouter:minimax/minimax-m2.7")
```

框架会自动处理差异：
- 自动检测模型的上下文窗口大小
- 禁用模型不支持的模态
- 在系统提示词中注入正确的模型身份信息
- 根据上下文窗口大小调整压缩策略（4K 窗口的模型比 1M 窗口的 Opus 需要更激进的压缩）

同一个模型还可以通过不同服务商使用。比如 GLM-5 可以是 `baseten:zai-org/GLM-5`、`fireworks:fireworks/glm-5`，或者通过 Ollama 自托管。同一个模型，同一套框架，不同的基础设施。

## 类比理解

想象你在选择快递公司：

- **闭源前沿模型** = 顺丰次晨达。服务好、速度快、贵。适合重要文件和紧急件
- **开源模型（现在）** = 京东快递。速度已经非常接近顺丰，价格却便宜一大截。对大多数包裹来说，完全够用
- **混合架构** = 重要文件用顺丰，日常包裹用京东。这是最聪明的策略

Deep Agents CLI 甚至支持**运行时切换模型**——你可以在一个会话中用闭源模型做规划（需要最强推理能力），然后切换到开源模型做执行（需要高吞吐低成本）。这就像"关键谈判派顺丰，日常文件走京东"。

## 为什么重要

这篇文章标志着 AI Agent 领域的一个重要拐点：

- **开源模型不再是"廉价替代品"。** 在文件操作、工具调用、指令遵循这些 Agent 核心能力上，它们已经是正经的一线选手。
- **成本优势决定了规模化的可能性。** 年省 $87k 的差价意味着更多初创公司和中小团队能负担得起大规模 Agent 部署。
- **延迟优势影响用户体验。** 对于交互式产品，0.65 秒 vs 2.56 秒的响应时间差异是用户能直接感知到的。
- **"模型无关"成为好框架的标配能力。** Deep Agents 框架自动适配不同模型的能力，意味着你的 Agent 代码可以随时跟着"最高性价比"的模型走。

## 延伸思考

1. 开源模型在"对话"维度的得分远低于其他维度（GLM-5 只有 0.38），闭源模型也好不到哪去（Opus 只有 0.05）。这是否意味着当前的评测方法对多轮对话的衡量存在问题？还是说所有模型在这方面都还有很大提升空间？

2. 文章提到"前沿模型做规划 + 开源模型做执行"的混合架构。这种模式能推广到多大规模？会不会出现"规划模型"和"执行模型"的分化市场？

3. 如果开源模型持续追赶，闭源模型公司的护城河在哪里？是继续拉大能力差距，还是转向平台和生态？
