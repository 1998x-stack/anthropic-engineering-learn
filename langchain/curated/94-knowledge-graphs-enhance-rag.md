# 94 | 用知识图谱增强 RAG 的检索准确性

> 原文: Enhancing RAG-based application accuracy by constructing and leveraging knowledge graphs (LangChain Blog, 2024-03)

## 一句话总结

用 LLM 自动从文本中提取实体和关系、构建知识图谱(Knowledge Graph)，再将图谱检索与向量检索混合起来，让 RAG 回答更准确、更有上下文。

---

## 核心要点

### 1. 向量检索的短板：丢失结构

传统 RAG 把文档切成碎片再做向量相似度搜索，擅长处理非结构化文本。但遇到"伊丽莎白一世属于哪个王朝"这类需要明确实体关系的问题时，碎片化的文本很难给出精确答案。知识图谱用"节点 + 关系"的方式把实体之间的联系显式存储下来，正好补上这个短板。

### 2. LLM 自动构建知识图谱

过去构建知识图谱需要领域专家手工标注，门槛很高。LangChain 新增的 `LLMGraphTransformer` 模块让你可以直接用 GPT-4 等大模型从文本中抽取实体和关系，自动生成图谱文档(Graph Documents)，再一键导入 Neo4j。整个过程只需几行代码。

### 3. 混合检索 = 向量 + 关键词 + 图谱

最终方案不是二选一，而是三路并行：向量搜索找语义相似段落、关键词搜索做精确匹配、图谱检索拿到结构化事实。三路结果拼接后交给 LLM 生成最终答案，兼顾了语义理解和事实精确性。

### 4. 图谱检索的实现路径

图谱检索分两步：先用 LLM 从用户问题中提取实体名称(Entity Extraction)，再用全文索引(Full-text Index)在图谱中定位对应节点，最后通过 Cypher 查询返回该节点的"邻域"——所有直接关联的关系和属性。

### 5. 对话式查询改写

为了支持多轮对话中的追问(如"她什么时候出生的？")，系统加入了查询改写(Query Rewriting)环节，把代词解析回具体实体名，确保后续检索能命中。

## 类比理解

把知识图谱想象成一张"人物关系图"。传统向量检索就像在一本厚书里搜索关键词，你能找到提到"伊丽莎白"的段落，但不一定能快速回答"她爸爸是谁"。而知识图谱就像挂在墙上的家族谱系图——你一眼就能顺着线找到"伊丽莎白一世 -> 父亲 -> 亨利八世"。混合检索相当于同时翻书和看谱系图，两种方式互补，回答又准又全。

---

## 为什么重要

1. **精确回答实体关系类问题**：向量检索对"谁属于哪个家族"这类需要跨段落推理的问题表现不佳，图谱检索可以直接给出结构化答案。
2. **LLM 降低了构建门槛**：以前知识图谱是"重资产"项目，现在几行代码就能从文本自动生成，大幅降低了采用成本。
3. **混合架构是 RAG 的演进方向**：单一检索方式都有盲区，多路混合是目前业界公认的提升 RAG 质量的最有效手段之一。

1. LLM 自动生成的知识图谱质量高度依赖模型能力，如果换成较弱的模型，图谱中会出现哪些典型错误？你会如何做质量校验？
2. 知识图谱的实体和关系类型需要预先定义吗？如果不限制，自由抽取会带来什么问题（比如同义实体、关系爆炸）？
3. 当文档频繁更新时，知识图谱的增量更新策略应该如何设计，才能避免全量重建的开销？
