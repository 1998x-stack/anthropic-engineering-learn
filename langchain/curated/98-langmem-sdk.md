# LangMem SDK：给 Agent 装上长期记忆的三种方式

> 一句话总结：LangMem 是 LangChain 推出的 Agent 长期记忆 SDK，它把记忆分为三种类型——语义记忆（Semantic Memory）存事实、程序记忆（Procedural Memory）改行为、情景记忆（Episodic Memory）记经历——帮助你按需给 Agent 装上"越用越聪明"的能力。

---

## 核心要点

### 1. 在加记忆之前，先回答三个问题

LangChain 团队的经验是：别急着写代码，先想清楚三件事。这三个问题决定了你该用哪种记忆、怎么存、怎么取。

| 问题 | 思考方向 | 影响的设计决策 |
|------|----------|----------------|
| 哪些行为该学习，哪些该固定？ | 有些行为需要随反馈进化，有些必须始终一致 | 决定是否需要程序记忆（Procedural Memory） |
| 该追踪哪些知识或事实？ | 用户偏好？领域知识？还是两者都要？ | 决定是否需要语义记忆（Semantic Memory） |
| 什么条件应该触发记忆回忆？ | 始终加载？按相似度检索？还是按上下文+时间？ | 决定记忆的存储和检索模式 |

### 2. 三种记忆类型一览

| 记忆类型 | 目的 | Agent 示例 | 人类类比 | 典型存储方式 |
|----------|------|------------|----------|-------------|
| 语义记忆（Semantic） | 存事实和知识 | 用户偏好、知识三元组 | 知道 Python 是编程语言 | Profile 或 Collection |
| 情景记忆（Episodic） | 存过去经历 | Few-shot 示例、历史对话摘要 | 记得入职第一天 | Collection |
| 程序记忆（Procedural） | 存行为模式 | 核心人格和响应风格 | 知道怎么骑自行车 | Prompt 规则或 Collection |

### 3. 语义记忆：用 `create_memory_manager` 管理事实

语义记忆是最常见的需求。LangMem 提供 `create_memory_manager` 来从对话中自动提取事实，并支持增量更新——新信息来了，旧记忆会被合并或更新，而不是简单覆盖。

```
对话内容 ──> create_memory_manager ──> 提取事实
                                        |
                                   存入 Memory Store
                                        |
新对话 + 已有记忆 ──> manager.invoke ──> 更新/合并记忆
```

它和传统 RAG 的区别在于：RAG 的知识来自离线数据导入（文档、代码库），而语义记忆的知识来自交互过程中的学习。如果知识是关于"用户个人偏好"或"对话中涌现的关系"，那语义记忆比 RAG 更合适。

### 4. 程序记忆：用 `create_prompt_optimizer` 进化行为

这是最有意思的部分。程序记忆不是存"知道什么"，而是存"该怎么做"。LangMem 通过分析成功和失败的交互轨迹（Trajectory），自动优化 Agent 的系统提示词（System Prompt）。

LangMem 提供三种优化算法：

| 算法 | 工作方式 | 适用场景 |
|------|----------|----------|
| `metaprompt` | 先反思对话，再用元提示词生成更新 | 需要深度思考的复杂场景 |
| `gradient` | 分两步：先批评、再提出修改建议 | 每步任务更简单，更可控 |
| `prompt_memory` | 一步完成批评和修改 | 快速迭代、简单场景 |

### 5. 情景记忆：尚在建设中

情景记忆关注的是"具体经历"而非"通用知识"——它回答的是"上次碰到类似问题时我是怎么解决的"。通常以 Few-shot 示例的形式存在，每个示例从一段完整交互中提炼而来。LangMem 目前还没有为情景记忆提供专门的工具，但这是路线图上的计划。

### 6. 记忆的隐私和隔离

LangMem 用命名空间（Namespace）来隔离记忆。最常见的做法是在命名空间中包含 `user_id`，防止用户之间的记忆串通。记忆可以限定在特定路由、特定用户，也可以在团队之间共享，甚至让 Agent 跨所有用户学习通用规则。

## 类比理解

把 Agent 的三种记忆想象成一个新员工的成长过程：

- **语义记忆**就像员工的"通讯录和项目文档"——记住同事的名字、项目的背景、客户的偏好。
- **程序记忆**就像员工积累的"工作习惯"——刚开始写邮件可能啰嗦，被主管纠正几次后学会了简洁专业的风格，以后就自动这样写了。
- **情景记忆**就像员工的"工作日志"——上次客户投诉时我是怎么处理的？那次成功的演示我用了什么策略？

一个成熟的员工三种记忆都很强。一个成熟的 Agent 也应该如此。

---

## 为什么重要

1. **从"无状态工具"到"有记忆的助手"**：没有长期记忆的 Agent 每次对话都是"失忆"重来。LangMem 让 Agent 真正能跨会话学习和成长。
2. **程序记忆是最被低估的能力**：大多数人想到"记忆"就想到存事实。但让 Agent 通过反馈自动优化自己的行为模式，这才是真正"越用越聪明"的关键。
3. **记忆设计决定 Agent 天花板**：在加记忆之前先回答"学什么、存什么、什么时候取"这三个问题，能避免你走弯路。记忆不是越多越好，而是"对的记忆在对的时机被回忆"才有价值。

## 延伸思考

1. 程序记忆的自动优化会不会"跑偏"？如果 Agent 学到了错误的模式怎么办？你需要考虑加入人工审核环节，或者设置"不可修改的核心规则"。
2. 语义记忆和 RAG 的边界在哪里？如果你的知识源是文档库，RAG 就够了。如果你的知识源是"和用户的交互本身"，那才需要语义记忆。两者可以互补。
3. 三种记忆类型之间可能存在冲突——语义记忆说"用户喜欢详细解释"，但程序记忆学到了"用户更喜欢简洁回答"。如何处理这种矛盾，是记忆系统设计中需要深入思考的问题。
