# Agent 记忆系统：让 AI 记住你是谁、说过什么

> **一句话总结：** LlamaIndex 的 Memory 组件为 Agent 提供了短期记忆（聊天历史）和长期记忆（静态信息、事实提取、向量检索）两层记忆系统，解决了"说过的话转头就忘"的问题。

---

## 核心要点

1. **没有记忆的 Agent 是健忘症患者。** 如果不存储对话历史，Agent 连"那里"指代什么都理解不了——每次对话都是从零开始。
2. **短期记忆 = 聊天历史窗口。** 把最近的对话存入 SQLite，发给 LLM 做上下文。超过 token 限制时，最老的消息被丢弃或刷入长期记忆。
3. **长期记忆有三种形态。** 静态信息块（Static）存不变的事实，事实提取块（Fact Extraction）用 LLM 从对话中自动抽取关键信息，向量记忆块（Vector）把历史对话嵌入向量库供语义检索。
4. **记忆模块可自定义扩展。** 继承 `BaseMemoryBlock` 就能实现你自己的记忆逻辑，比如统计某个名字被提到了多少次。

---

## 记忆类型对比

| 记忆类型 | 存什么 | 怎么用 | 适合场景 |
|----------|--------|--------|----------|
| 短期记忆（Short-term） | 最近 N 条聊天消息 | 直接拼入 LLM 上下文 | 所有需要多轮对话的应用 |
| StaticMemoryBlock（静态块） | 预设的固定信息 | 作为系统提示的一部分 | 用户姓名、偏好等不变信息 |
| FactExtractionMemoryBlock（事实提取块） | 从对话中自动抽取的事实列表 | LLM 驱动的结构化提取 | 需要逐步了解用户的场景 |
| VectorMemoryBlock（向量块） | 历史对话的向量嵌入 | 语义相似度检索相关历史 | 长对话、跨会话的上下文召回 |

## 代码速览：三种长期记忆块的初始化

```
# 1. 静态信息块 -- 存放不会变的背景信息
StaticMemoryBlock(
    name="core_info",
    static_content="用户叫小明，住在北京",
    priority=0              # 优先级最高
)

# 2. 事实提取块 -- LLM 自动从对话中抽取事实
FactExtractionMemoryBlock(
    name="extracted_info",
    llm=OpenAI("gpt-4o-mini"),
    max_facts=50,           # 最多存 50 条事实
    priority=1
)
# 对话后自动生成: ["用户29岁", "用户有一个姐姐"]

# 3. 向量记忆块 -- 把对话嵌入向量库做语义检索
VectorMemoryBlock(
    name="vector_memory",
    vector_store=qdrant_store,  # 需要外部向量库
    embed_model=embed_model,
    similarity_top_k=2,         # 每次检索 top-2 相关对话
    priority=2
)
```

## 类比理解

把 Agent 的记忆系统想象成**你自己的记忆方式**：

- **短期记忆**就像你正在进行的对话——你记得刚才说了什么，但如果话题太长，最开始聊的内容你会逐渐模糊。
- **StaticMemoryBlock** 就像你护照上的信息——姓名、国籍、出生日期，几乎不会变，但随时可能被问到。
- **FactExtractionMemoryBlock** 就像你和朋友聊天后在心里默默记下的要点——"哦，他下个月要结婚了"、"她最近换了工作"。你不会逐字记住对话，但会记住关键事实。
- **VectorMemoryBlock** 就像你的日记本——当有人提到某个话题时，你能翻回去找到相关的记录，即使那是很久以前的对话。

---

## 为什么重要

- **多轮对话的基础设施。** 没有记忆的 Agent 无法做客服、无法做私人助理、无法做任何需要上下文的应用。记忆不是锦上添花，而是刚需。
- **短期 + 长期的分层设计解决了 token 限制。** LLM 的上下文窗口是有限的（即使是 128K 也会用完）。分层记忆让 Agent 在有限窗口内保持"记性好"的体验。
- **事实提取是最有价值的创新。** 不是把所有对话都存下来，而是用 LLM 提取关键事实——这比暴力存储高效得多，也更接近人类记忆的工作方式。

## 延伸思考

1. **记忆的遗忘策略。** 人会主动遗忘不重要的信息。Agent 的记忆系统是否也需要"遗忘机制"？比如 6 个月没被检索到的事实自动降低优先级？
2. **隐私与记忆的冲突。** 如果 Agent 记住了用户的敏感信息（健康状况、财务数据），如何确保这些信息不被泄露或滥用？GDPR 的"被遗忘权"在 Agent 记忆中如何实现？
3. **记忆作为工具而非后端。** 文中提到未来可能让 Agent 把记忆当作工具来调用（而不是自动注入上下文）。这意味着 Agent 可以主动决定"我需要回忆什么"——更接近人类的主动回忆过程。
