# 弯而不断：Agent 设计的最优模式

> **一句话总结：** 最好的 Agent 系统既不是全自动的"放养模式"，也不是写死每一步的"流水线模式"，而是在确定性流程中嵌入 LLM 自主决策的**混合模式**——用 Workflow 实现。

---

## 核心要点

1. **完全自主 vs 完全确定，两端都有缺陷。** 全自主 Agent 给个目标就放手，灵活但不可靠，容易跑偏；全确定的管道（Pipeline）写死每一步，可靠但僵化，无法处理意外输入。
2. **Workflow 是混合模式的落地方案。** LlamaIndex 的 Workflow 是一个事件驱动系统，用普通函数实现执行步骤，通过事件（Event）触发和串联。它天然支持链式、分支、循环、扇出（Fan-out）等所有模式。
3. **结构和自主的边界有规律可循。** 流程明确、后果严重的环节用结构（代码）锁死；输入模糊、需要判断的环节交给 LLM 自主决策。
4. **六大好处。** 混合模式带来更高可靠性、更清晰的错误处理、更容易调试、更好的性能、保留 LLM 的灵活性、以及对人工监督（Human-in-the-Loop）的原生支持。

---

## 自主性光谱

| 维度 | 完全确定（Pipeline） | 混合模式（Workflow） | 完全自主（Autonomous Agent） |
|------|---------------------|---------------------|---------------------------|
| 控制流 | 代码写死 | 代码 + LLM 共同决策 | 完全由 LLM 决定 |
| 灵活性 | 低：无法处理意外 | 高：结构化路径 + 弹性处理 | 最高：什么都能尝试 |
| 可靠性 | 最高（在已知场景下） | 高 | 低：容易跑偏或死循环 |
| 可调试性 | 容易 | 较容易 | 困难 |
| 适用场景 | 流程固定、规则明确 | 大多数实际业务场景 | 纯探索性任务 |

## 何时用结构、何时给自主权

```
+------------------------------------------------------------------+
|                    Agent 设计决策树                                |
+------------------------------------------------------------------+
|                                                                   |
|   流程是否已知且固定？                                             |
|   |                                                               |
|   +-- 是 --> 操作是否不可逆或代价很高？                            |
|   |          |                                                    |
|   |          +-- 是 --> 【用结构锁死】                             |
|   |          |         例：计费、转账、删除                         |
|   |          |                                                    |
|   |          +-- 否 --> 【用结构为主，少量弹性】                    |
|   |                    例：表单收集、多步输入                       |
|   |                                                               |
|   +-- 否 --> 输入是否非结构化？                                    |
|              |                                                    |
|              +-- 是 --> 【交给 LLM 自主处理】                      |
|              |         例：合同解析、邮件分类、客服问答              |
|              |                                                    |
|              +-- 否 --> 规则是否灵活、边界模糊？                   |
|                        |                                          |
|                        +-- 是 --> 【交给 LLM 自主处理】            |
|                        |         例：优先级排序、边缘案例判断       |
|                        |                                          |
|                        +-- 否 --> 【用结构为主】                   |
+------------------------------------------------------------------+
```

## 混合模式的六大好处

| 好处 | 具体表现 |
|------|---------|
| 可靠性（Reliability） | 关键操作走确定性路径，不依赖 LLM 的"心情" |
| 错误处理（Error Handling） | 每个步骤有明确的异常捕获和恢复机制 |
| 可调试性（Debuggability） | 事件流可追踪，出问题能定位到具体步骤 |
| 性能（Performance） | 已知场景走优化路径，不需要 LLM 做无谓推理 |
| 灵活性（Flexibility） | 在需要判断的环节保留 LLM 的自主能力 |
| 人工监督（Human-in-the-Loop） | 原生支持在关键节点暂停、等待人工确认 |

## Workflow 事件驱动架构示意

```
[StartEvent]
     |
     v
+-----------+    EventA    +-----------+    EventB    +-----------+
| Step 1    | -----------> | Step 2    | -----------> | Step 3    |
| (确定性)  |              | (LLM决策) |              | (确定性)  |
+-----------+              +-----------+              +-----------+
                                |                          |
                                | EventC (分支)            |
                                v                          |
                          +-----------+                    |
                          | Step 2b   |                    |
                          | (LLM决策) |                    |
                          +-----------+                    |
                                |                          |
                                +-------> EventD <---------+
                                              |
                                              v
                                        +-----------+
                                        | Step 4    |
                                        | (汇合)    |
                                        +-----------+
                                              |
                                              v
                                        [StopEvent]
```

每个 Step 是一个普通函数，通过发出事件（Event）来触发下一个 Step。控制流可以由代码决定（确定性分支），也可以由 LLM 决定（哪个事件该发、发给谁）。

## 类比理解

想象你在经营一家餐厅。

- **完全确定模式**就像快餐连锁店的标准操作流程（SOP）：每道菜的做法、每个工位的动作都写死了。效率极高，但如果客人说"我对花生过敏，能不能把酱换一下？"——SOP 里没这条，系统就卡住了。
- **完全自主模式**就像把一个天才厨师扔进厨房，什么规矩都不给。他可能做出惊艳的创意菜，也可能因为找不到盐而浪费 20 分钟，甚至做出客人根本没点的东西。
- **混合模式（Workflow）** 就像一家管理有方的高档餐厅：备菜、出餐、上菜的流程是标准化的（结构），但厨师在调味、替换食材、处理特殊需求时有自主权（自主）。关键环节（比如过敏食材）有强制检查点（人工监督）。

---

## 为什么重要

Agent 设计模式的选择直接决定了系统的上限。选错了模式，后续的 Prompt 优化、工具设计、错误处理都是在错误的地基上修补。这篇文章提供的核心框架——"什么时候用结构、什么时候给自主权"——是一个可以反复使用的决策模型。

特别值得注意的是，Anthropic、OpenAI 和 LlamaIndex 三家在这个问题上达成了高度共识：**混合模式优于纯自主模式**。这不是偶然——它反映了当前 LLM 能力的现实边界。LLM 在理解意图和处理模糊性上很强，但在精确执行、状态管理和因果推理上仍然不够可靠。混合模式恰好把两者放在了各自擅长的位置上。

---

## 延伸思考

1. **结构和自主的比例会随模型进化而变化。** 今天你需要用代码锁死的环节，明天更强的模型可能可以自主处理。设计 Workflow 时要留好"从结构升级到自主"的扩展点。
2. **事件驱动 vs 图（Graph）驱动。** LlamaIndex 选择了事件驱动而非图驱动（如 LangGraph），认为前者更灵活。两种方案各有优劣：图的可视化更直观，事件的组合性更强。选择取决于你的团队更习惯哪种心智模型。
3. **人工监督的粒度。** Human-in-the-Loop 听起来很安全，但如果每个步骤都要人确认，系统就退化成了一个花哨的表单。关键是只在"不可逆操作"和"低置信度决策"处设置检查点，其余环节放手让 Agent 跑。
