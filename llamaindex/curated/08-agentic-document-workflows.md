# 智能体文档工作流：超越 RAG 的实战指南

**来源:** [LlamaIndex Blog](https://www.llamaindex.ai/blog/introducing-agentic-document-workflows)  
**阅读时间:** 约 5 分钟

---

> **一句话总结**  
> 智能体文档工作流 (Agentic Document Workflows, ADW) 是 LlamaIndex 在 2025 年初提出的架构模式——它把文档解析、检索、结构化输出和智能体编排组合在一起，让 AI 不只是"回答关于文档的问题"，而是端到端地完成知识型工作。

---

## 核心要点

1. **RAG 不够用了** —— 真实的文档工作流不是"问一个问题、找一段文本"，而是多文档协作、多步骤决策、跨系统协调
2. **ADW = 文档解析 + 检索 + 业务规则 + 智能体编排** —— 四者缺一不可
3. **文档智能体维护状态** —— 它记得自己处理到哪一步、当前文档的上下文是什么，能做多步推理
4. **四个落地场景验证了模式** —— 合同审查、患者病例摘要、发票处理、车险理赔

---

## 一、为什么 RAG 不够用？

RAG（检索增强生成）是一个强大的模式，但它解决的是一个相对简单的问题：用企业数据给 LLM 提供上下文。真实的文档工作流要复杂得多。

| 真实世界的挑战 | RAG 能解决吗？ |
|--------------|--------------|
| 文档不是孤立的——合同、政策、邮件、表格要协同工作 | 勉强 |
| 决策跨越多步——从提取到验证到审批到建议 | 不行 |
| 上下文和状态必须在整个流程中保持 | 不行 |
| 多系统需要协调——解析器、检索器、业务逻辑引擎 | 不行 |

> **类比理解**  
> RAG 像一个能帮你在图书馆找到正确书页的助手。但真实的工作不是"找到信息"就完了——你还要理解它、交叉验证、做判断、写报告、触发下一步动作。ADW 就是把这个助手升级成一个能独立完成整个研究项目的研究员。

### ADW 怎么解决这些问题

智能体文档工作流把文档当作更广泛业务流程的一部分来处理。ADW 系统可以跨步骤维护状态、应用业务规则、协调不同组件、并基于文档内容采取行动——不仅仅是分析它。

---

## 二、文档智能体是怎么工作的？

每个 ADW 的核心是一个文档智能体 (Document Agent)，它编排整个流程。

```
文档智能体工作流程

输入文档                    知识库
   │                         │
   ▼                         ▼
┌──────────────────────────────────┐
│           文档智能体              │
│                                  │
│  1. 解析 ─→ 用 LlamaParse       │
│     提取并结构化文档内容          │
│                                  │
│  2. 维护状态 ─→ 记住文档上下文   │
│     和当前处理阶段               │
│                                  │
│  3. 检索 ─→ 从知识库拉取         │
│     相关参考资料                  │
│                                  │
│  4. 推理 ─→ 基于业务规则         │
│     生成可执行建议               │
└──────────────────────────────────┘
                │
                ▼
          结构化输出 + 建议
```

关键在于**状态维护**。传统 RAG 是无状态的——每次查询都是独立的。文档智能体在整个流程中积累上下文，能做多步推理、处理分支逻辑、在不同组件之间协调。

## 三、四个落地场景

### 3.1 合同审查：智能合规分析

| 环节 | 智能体做什么 |
|------|------------|
| 解析 | 理解复杂的合同结构（条款嵌套、交叉引用） |
| 比对 | 将条款与法规/公司标准进行对照 |
| 标记 | 非标准条款、缺失条款、可能的法规冲突 |
| 输出 | 结构化建议 + 需要律师审查的清单 |

系统是智能助手，不是替代者——最终决策权始终在人手里。

### 3.2 患者病例摘要：上下文理解

医疗文档量爆炸性增长。文档智能体可以解析复杂的医疗文档（化验结果、临床笔记），在保持患者病史完整上下文的同时，与存储的医疗指南比对，生成突出关键临床发现的综合病例摘要，供医生审查。

### 3.3 发票处理：业务运营优化

智能体不只是提取发票上的数字——它还能用提取的行项目和付款条款，与合同约定价格做验证，并建议最优付款策略。一个简单的文档处理任务变成了一个营运资金优化工具。

### 3.4 车险理赔：结构化分析辅助

车险理赔展示了 AI 如何**辅助而非替代**人类决策。智能体帮助理赔员组织信息、呈现相关保单细节，但所有承保和赔付决定都留给人。这是敏感领域中 AI 的正确定位。

> **类比理解**  
> 这四个场景的共同点是：智能体不是要"取代"专业人员，而是帮他们从繁琐的信息整理中解放出来，让他们把时间花在真正需要专业判断的环节上。就像一个出色的助理——该整理的整理好，该标记的标记出来，但最终签字的还是你。

## 四、构建生产级方案

从 demo 到生产，你需要关注的不仅仅是"能不能跑起来"，还有：

| 生产要求 | 说明 |
|---------|------|
| 错误处理 | 解析失败、检索为空、模型不确定时的降级策略 |
| 输出验证 | 结构化输出是否符合 schema，数值是否在合理范围 |
| 可扩展性 | 从处理 10 份文档到 10000 份，架构是否撑得住 |
| 可定制性 | 业务规则能否灵活配置，不同场景能否复用核心流程 |

---

## 为什么重要

ADW 代表的是文档 AI 从"聊天机器人式问答"到"端到端工作流自动化"的升级。RAG 让 LLM 有了知识，ADW 让 LLM 有了执行力。对于法律、金融、医疗、保险这类文档密集型行业，这不是"要不要做"的问题，而是"什么时候开始"的问题。

---

## 延伸思考

1. **你现在的文档流程里，有多少步骤是"人在做 AI 应该能做的事"？** 画出你的文档处理流程图，标出每一步是"提取"、"验证"、"判断"还是"执行"——前三类大概率可以让智能体来做。
2. **你的 RAG 系统有没有碰到天花板？** 如果用户的反馈越来越多是"它找到了信息但没有帮我做判断"或"它不知道下一步该怎么办"，那就是 ADW 该登场的信号。
3. **哪个场景适合"辅助模式"，哪个适合"自动模式"？** 高风险决策（如医疗、法律）适合辅助，低风险重复任务（如发票提取）适合自动。先搞清楚边界，再选架构。
